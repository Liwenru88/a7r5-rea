# Tab焦点、分组投影与应用状态隔离

Feature ID: 013-creative-look-tabs
Status: IMPLEMENTED_OFFLINE

## 当前接线与边界

012拥有源为`native24-combined/runtime/unified-look.c`，原43行注册及MID／selector保持。已读取原`n12_dispatch`、`n12_labels`、`n12_refresh`、`n12_current`及原D9标签更新体`0x2208e34`。主页和调参页的vtable分别为`0x58ca670`和`0x58ca720`。现有中键事件由原分发处理并保留在途保护，右键进入DA调参页。

只在当前创意外观主页面启用分组，不将原厂条目从全局注册树或Fn入口删除，不重新编号或移动持久化数据。复用原厂顶部标题控件和真实中文字体渲染两组名称，方括号表示当前组，`>`表示Tab获得焦点；不在模拟器绘制Tab，不修改PNG，不改未经确认的原控件颜色字段。

原调用点均由严格构建器核对BL前像：`0x2208e68`的标题调用接入`n12_group_title`；`0x2208f7c`、`0x220847c`的原`0x1bc36f8`调用接入`n12_list_projection`；`0x22074b4`的原`0x1bd7234`调用接入`n12_tabs_nextrow`。投影和导航作用域内同时限定`visible`及`available`两条资格路径；作用域外保持全局原43行，避免影响Fn等入口。

实际vtable的`+0x1a8`先进入上游`r5_filter_row_available`，它按旧附加编号直接返回mask，部分新MID不会经过`0x1bcfffc`。因此派生构建还将该包装器严格接入`n12_visible`；原`r5_filter_row_available_direct`继续接入`n12_available`。原枚举和原行索引随后使用同一资格规则，避免原厂末尾越组或稀疏槽编号错位。原包装器的真实机器码入口单独参与回归，不能用仅调用新增函数的夹具替代。

分组scope覆盖D9原事件分发、原刷新和完整标签体，不只包住No9投影：原生刷新还会用组内索引反查MID，若刷新时恢复全表资格，组内第二行会错误变为PT。每个包装体保存并恢复旧scope，调参页及其他页面不进入该作用域；窗口结束后全局资格保持。

## 状态与事件

将`group`、`tab_focus`、两组浏览MID与`browse_only`保存在UI线程状态。已应用值仍来自原后台；Tab切换时不调用`apply`、原预览或原选择，不设置原厂成像属性。不取消已被工作线程接收的事务，不清除原E4在途位。

列表的首个有效项按上进入Tab，Tab左右只切两组，下或中键仅进入列表。进入另一组和离开Tab仅恢复浏览位置，仍不应用；列表实际移动／中键确认／主动进入调参才沿原选择意图执行。上下移动不先应用旧浏览项。菜单离页先恢复已应用组及其MID，再沿原取消路径退出。原参数页全部保持既有接线，不消费Tab按键；若未应用的浏览项需要进入参数页，八项工作模型和保护仍依其自身MID，不能误写另一配方或原厂数组。

跨组定位通过原导航体`0x2207480`，在限定调用中返回目标稳定MID与原`0x1bd6384`取得的行种类，再由原属性绑定及通知发布UI选择。不直接写全局MID或成像属性。页面离开后清除活动焦点和浏览状态，各组最近浏览MID仅存RAM。空组只显示“未导入自定义滤镜”，下和中键不进入列表，不能选不存在的槽位。

每组有效条目用原稳定MID投影，继承原厂资格与本地可用mask；空组显示空状态且不进入不存在的列表。UI状态刷新只更新已验证当前对象，不能保留释放后的原呈现器指针。
