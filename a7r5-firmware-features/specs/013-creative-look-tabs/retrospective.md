# 分组菜单实施复盘

本轮只修改创意外观分组与导航，未连接相机。以下失败现场保留，不计入最终通过证据。

| 发现 | 原因 | 修正与回归 |
|---|---|---|
| 从Tab进入列表后按下，先请求旧浏览项再请求新行 | 浏览解除时过早预览 | 上下键交原导航只请求新行；在旧候选机器码上复现两次请求，新增断言只请求最后目标 |
| 浏览另一组后MENU退出，组状态未恢复 | 原取消路径只处理原MID | 离开前按已应用值恢复组和UI导航；新增无请求、正确组／MID回归 |
| 中键已返回上级，但验证报告仍在D9 | 旧apply追踪未覆盖页面pop／restore | 保留旧追踪用于前21步对比，新增经vtable核对的原manager当前页只读观察；现场`xv1kuydd` |
| 原厂末尾仍能走到附加F01，补available仍复现 | 实际vtable先进入上游`r5_filter_row_available`，按旧编号直接返回mask，绕过新visible入口 | 严格接入该上游入口；两条资格路径在投影／导航scope内共同过滤，新增上游实际机器码回归。失败现场`w9y338no`、`w1vfdeoy`；后者的遗留VM已通过其专属QMP退出 |
| 自定义组开始应用后标题跳为PT，随后导航停滞 | 原生刷新使用组内索引反查MID，却在scope结束后按全表资格计算 | D9事件、原刷新及完整标签体使用同一分组scope，结束后恢复；两项失败回归复现第二行变PT，现场`iv27yas5` |
| 空库VM启动被拒绝 | 与另一AP VM并发触发原独占锁 | 不绕过锁，改为顺序验证；现场`fb5syvau` |
| 空库已正确载入，脚本却拒绝文件长度 | 继承的验证器写死满库58976字节 | 对已固定摘要输入的实际长度做核对，空库为128字节；现场`f1ocv1zu` |
| 原重置框已显示，验证脚本却报告未弹出 | manager当前主页仍为DA，模态框44c只出现在原入页追踪中 | 同时要求主页DA与原弹窗追踪44c，再实际选择确认、核对八项恢复；只修验证器，现场`8am1id4v` |

投影、导航、原厂UI属性发布和页面生命周期属于不同边界，纯状态机夹具不能替代真实AP验证。最终门禁要求满库和空库独立Qt回执、原帧一致、源码新鲜度及三侧正常退出。QEMU原E4初始化缺口继续如实保留，不以菜单或工作值成功替代成像／保存验收。
