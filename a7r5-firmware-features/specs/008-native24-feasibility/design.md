# 二十四槽容量与文件兼容原型设计

Feature ID: 008-native24-feasibility
Status: PROTOTYPE_ONLY

链路边界是“编译结构布局＋执行配方／选择文件编解码”，不启动拍摄、原E4、CP原接收任务或菜单。原型独立放在`native24-prototype/`，通过完整上游快照校验后，将需要的头文件和C编解码器派生到新的输出目录。每次替换检查精确前像及次数，记录原文件和派生文件摘要，不编辑冻结源。

## 文件安排

- `native24-prototype/prepare.py`：校验来源、受限派生12／24版本、编译宿主库及目标布局对象，保留编译命令／输出／摘要。
- `native24-prototype/layout.c`：使用实际bank、Gamma、view、诊断、transfer结构，明确保留旧布局中的不透明间隙；编译期断言旧偏移，报告各区大小；仅用于布局和边界原型。
- `native24-prototype/tests/test_prototype.py`：独立文件构造、交叉兼容、拒绝保持、选择文件及编译布局检查。
- `native24-prototype/verification/2026-11-03-01/`：新证据，不覆盖旧结果。

## 布局模型

保留现有每款2392字节CP配方、20028字节完整Gamma上下文、八档405点打包网格和24字节活动视图；原厂十二种外观的Gamma路径仍是十二种，不能把这些原厂循环误改成24。原厂75行Gamma表和32条原厂恢复缓存保持原规模。

十二槽模型必须复现bank=28768、off_table=48796、views=50896、diag=52252、transfer=52324、grid=52352、extra_gamma=301840、allocation=522152。二十四槽重新排列这些区块，不复用旧数值偏移。目标编译用ARM32与AArch64验证无指针的布局结果一致。边界写入仅证明布局隔离，不证明原固件消费者已接入新指针。

先保留现有预计算方案评估，不在本阶段引入Gamma共享、按需缓存或渲染期改写。1048576字节只作为显式测试预算；不推断真实共享堆剩余量，也不把“单库容得下”推断为多代可用。

## 候选文件契约

研究候选采用配对的`R5CUST5\0`／版本5表示最多24槽，保留128字节头、2452字节记录及现有参数／UTF-8／身份／CRC校验；读取旧`R5CUST4\0`／版本4时仍严格限于12槽。仅用前十二槽的集合输出原v4字节，含13～24号的集合输出v5。它是独立候选格式，尚未成为正式固件接口。

选择文件保持24字节：0～12完全沿用`R5SEL4\0\0`及原版本字段；13～24候选使用`R5SEL5\0\0`和单独版本字段。两种格式不得交叉伪装。旧固件拒绝新格式是明确拒绝，**不表示可以把24槽数据无损降级到旧固件**；本阶段不对用户文件执行自动转换。

独立Python构造器制作测试BIN并算CRC，避免让同一C编解码器互相证明。新增十二槽仅复制已有合法参数并改成测试名称，数据不交付为滤镜成品。

## 下一阶段门禁（本阶段不实施）

1. 原生列表从31到43行的真实容量、渲染及导航；现有No9结构只验证过31行，不能仅放宽断言。
2. 标题资源的16项分组、短名／状态资源范围、48个新增图标和MID冲突审计。
3. AP／CP容量握手、mask、槽上限、BEGIN／PUT／SEAL序列和固定14次发送预算，必须版本／能力匹配，拒绝混搭。
4. CP所有旧偏移、原消费者指针、布局保护、零额外切换分配、单库复用和失败保留；真实共享堆余量未知。
5. AP线程局部缓冲、扫描读取预算、启动／恢复和选择持久化。不得将所有原厂“12”常量整体替换。
6. 二十四槽跨层CPU及有限QEMU验证；原E4模型限制与最终机身验收分开。

需求追踪：布局对应REQ-001／AC-001；配方对应REQ-002／AC-002；边车对应REQ-003／AC-003；来源、隔离与后续门禁对应REQ-004／AC-004。回退方式为不接入此独立目录；原十二槽组件无需还原。
