# 二十四槽离线可行性原型

Feature ID: 008-native24-feasibility
Mode: research
Status: PROTOTYPE_VERIFIED
Created: 2026-11-03

用户在确认二十四槽可行性分析后要求“继续下一步”。本阶段仅验证内存布局和旧文件兼容性，形成下一阶段依据；不接入现有固件，不代表授权改动现有运行时、迁移用户数据或发布升级包。

沿用目标：未来二十四款仍放在原创意外观，保留原十九项、ST原厂语义、FL2／FL3、本地四项、冷启动导入、机内保存和最后目标合并。当前十二槽AP、CP、BIN、上游及两个历史DAT保持不变；007热导入继续搁置。

| Requirement | Acceptance | Verification |
|---|---|---|
| REQ-001 测量布局 | AC-001 基于实际结构定义编译十二／二十四槽布局，十二槽精确匹配现有偏移及522152字节；二十四槽各区不重叠、边界与对齐可观察 | 宿主执行与ARM32／AArch64目标编译常量交叉核对，带边界哨兵的槽写入 |
| REQ-002 文件兼容 | AC-002 原十二槽v4配方完整解码且原样重编码；二十四槽候选可读写13～24号和稀疏槽；损坏、越界及伪装版本拒绝并保持输出；旧解码器拒绝新文件 | 固定BIN、独立Python构造器与派生C编解码器交叉验证 |
| REQ-003 选择兼容 | AC-003 保留旧0～12号边车字节；候选13～24号采用可区分格式，旧读取器明确拒绝；CRC／范围错误不更改输出 | 原／派生C选择编解码及独立CRC校验 |
| REQ-004 如实界定 | AC-004 明确模拟内存预算不等于实机可用堆；记录43行菜单、标题编码、传输、线程栈和CP指针迁移的待实现门禁；冻结源码与旧交付未变 | 摘要、收据、测试XML、规格和结论检查 |

不包含：新滤镜配方制作、实际24槽AP／CP接线、QEMU模拟器放宽、安装、机身I/O、实体卡或分区、生产数据迁移、提交或推送。新增槽使用明确标识的合成测试数据，不能称为新增十二款可用滤镜。
