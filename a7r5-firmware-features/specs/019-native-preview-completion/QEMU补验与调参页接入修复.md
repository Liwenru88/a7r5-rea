# QEMU补验与调参页事件入口修复

用户授权结束旧QEMU实例并补验后，已核对PID89176及其专属QMP路径，通过QMP退出并确认结束，没有操作相机。补验使用固定正式十二款BIN，继续保留原E4与成像边界。

## 补验发现与修复

019首轮候选AP `3cc55b…`在真实列表页可收到自然心跳，但进入调参页后，列表包装器的心跳计数不再增加。原DA控制器与D9使用不同的分派入口：新AP的ELF表项`0x58da6d8`指向原DA分派器`0x1a6df54`，原D9分派器为`0x1a6d8cc`。首轮只挂钩D9，虽然包装器内有DA判断，实际DA事件不会到达它。

原调参页CPU测试直接调用D9包装器，遗漏了真实接入。现改从原DA表项取得入口，先校验跳板，再实际执行该入口；首轮AP有2项预期失败。修复新增DA独立包装器，保留其原分派与按键返回，仅在DA、创意外观呈现器及原生心跳／值通知均匹配时运行现有刷新协调器。D9与DA共用稳态检查，避免重复实现；没有把DA交给D9原分派器。

生产代码相对019首轮只改`build.py`和`runtime/unified-look.c`，测试只改`test_preview_idle.py`。新AP为`401c16fe99a047f1440c2a9d1b7c5a48a9e5c380db5e57eed150d1604074f21f`；CP、两份图标、BIN、持久化格式及E4门禁保持。两次独立构建`.local/native24-preview-fix-20261104-13`与`-14`一致，8项定向回归通过，完整95项相关回归重新执行。

## 自然事件如何验证

新独立实验位于`a7r5-qemu/experiments/native24-preview-idle/`。观察库在客体RAM中透明包装列表／调参分派与各自绘制入口，严格核对四个可搬移序言，保留原调用和返回，只累计观察计数。它不调用刷新协调器、不写完成状态、不伪造按键；磁盘AP摘要保持。客体的其他条目与父输入逐项核对，原始帧必须与PNG一致。

真实Qt路线覆盖原厂外观与FL2／FL3、正式十二款、八项调节、重置、重入和四轮MENU。四处停手观察分别为Tab只浏览、首次预览、列表末次目标和调参页；空闲期间继续虚拟时钟并服务原有CP传输，没有导航输入。

第一次完整路线在DA计数为零处失败，没有计为通过；其退出清理中断后遗留的本轮AP也通过专属QMP清理，另补控制端EOF发送STOP。首轮观察器源码、日志和失败图像单独保留，不覆盖历史归档。

另一次集中观察确认列表停手后后台从状态1进入5，并出现1次重绘请求和1次标签绘制；像素仍相同。原E4仍在途、后台仍处于恢复保护，标题逻辑继续显示“切换中”，所以“像素必须变化”的原测试判断过强。该次没有计为通过，也没有通过改写状态来制造终态画面。最终分别记录事件到达、重绘调用、像素是否变化及E4是否完成，不能相互替代。

## 交付边界

补接DA后的第二场在进入DA之前，较长空闲触发了原生`[Master][Shutdown] factor:00000011 type:00000002 next_reboot:00000002`，进入`0x316`关机页面，随后在AP原函数`0x34e620c`发生对`0x3cc`的空指针读取。监控立即停止后续输入，AP经QMP退出、CP正常退出。该处原代码没有修改，但这不能证明异常与补丁无关；当前尚未归因，也没有修复或通过长空闲验收。

后续菜单观察将停手窗口限定为1／5秒，验证短窗口内的自然事件与菜单操作。较短测试通过不能抹去长空闲失败，也不能替代原生关机链路诊断。未关闭关机、E4或成像保护以绕过异常，长空闲失败现场继续保留。

短窗口截图还保留一个数值显示疑点：调参页停手后的AP工作值为`1/1/1/1/1/5/4/2`，但同次原帧底部清晰度仍显示1。其余按键后曾出现上一项才更新的现象，可能涉及模型／绘制时序或客体画面采集，尚未定位。107帧的检查证明原始BIN与PNG一致，不证明画面数值与AP工作值实时一致；此项像素与工作值的等价性未验收，不能仅凭工作模型测试通过就宣称界面完全闭环。

最终数量、四处自然事件计数、退出与截图身份见后续QEMU证明及[验证记录](verification.md)。旧188项CPU归档与4.15包保持封存；新的AP与补验材料另归档。原95项结果只适用于旧AP，新AP必须使用本轮重新执行的证据。

QEMU仍不能证明滤镜成功应用、机内保存与实际成像；自然事件和绘制链路通过也不能证明可见终态变化已经完成。没有生成新DAT，没有连接、上传或修改相机。
