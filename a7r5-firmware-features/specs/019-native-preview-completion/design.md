# 原E4参数完成与UI值通知

## 已复现的缺口

1. 原E4执行体`appFw+0x348292c`调用九个原生分派器`0x350927c…0x350947c`，第一条为`0x402f`外观选择，后八项走12字节属性发送。012的`r5_tune_verify()`只在见到`0x960`完整包时才接受微调已发送。旧回归在E4夹具内主动构造完整包，掩盖了生产分支差异。对比度分派的回退分支`0x35614ac`仍进入发送链，初期“漏发”的静态推断已由原函数执行回归排除。
2. `n12_refresh()`负责队列推进及状态差异检查，但原D9／DA的`0x20f0000`空闲心跳和`0x20f0001`值通知均未调用它；没有新输入或额外查询时，最后目标与标题变化可能滞留。旧异步回归通过宿主显式`poll()`推进，掩盖了通知契约缺口。原QEMU观察器明确将`0x20f0000`作为周期噪声跳过，不能将它误认为值通知`0x20f0001`。

## 最小修复

保留原E4执行体、九次分派和原消息数量。叠加器仍只改冻结八项的值，不把改写缓冲区当作完成。新增观察器在真正OSAL发送前核对消息格式、各项值与当前冻结代次；发送返回0后，按代次累积八位属性掩码。只有八项全部成功才接受；重复同项、缺项、迟到代次和发送失败均不能冒充完成。完整0x960包可一次覆盖八位，原生逐项消息逐位累积。

并发注入另复现了“先检查代次、后写独立掩码”的窗口：旧回执检查通过后，新prepare清零，新事务会被旧回执误标完成。将32位代次、八位掩码及错误位合在同一64位原子回执中；prepare在快照发布前更新代次标签，回执用比较交换同时核对标签并累积结果。若prepare穿插其中，比较交换失败后读到新标签，旧回执退出。错误位同样按代次更新，不污染后续事务；不改变线协议、持久化格式或微调值。

高层发送器`0x355882c`在返回前执行清理函数，不存在可用的发送状态返回契约；不能拿残留寄存器判断0成功。严格挂钩其`0x35589d8`对原`SND_MSG`的调用，原代码紧接着`cbz w0`确认0成功。观察器在发送前读取消息，发送后只用代次／掩码／结果，不再解引用已移交的消息。非目标队列、外观选择0x402f和其他不相关消息保持原发送。原高层返回值原样透传，原错误处理保持。`r5_filter_runtime423.c`、E4完成包装器、CP、BIN、协议和两份图标均保持4.15原样，不增加额外参数重发。

在已验证D9／DA控制器、创意外观呈现器及菜单身份匹配时，原生心跳和值通知先保留原委派，再调用现有刷新协调器；有变化则按原dispatcher返回契约通知UI重绘，无变化保持原返回。稳态心跳在确认无在途／排队目标、工作值和后台状态差异后直接返回，避免持续重建列表。UI对象指针只在本次所有者调用栈内使用，不新增后台UI线程、不伪造按键、不写全局属性脏位。

用户授权后的QEMU补验发现DA另用原分派器`0x1a6df54`，只挂钩D9的`0x1a6d8cc`不能覆盖DA。现为DA单独保留原委派并接入同一空闲刷新助手；测试必须从原DA表项`0x58da6d8`读取入口后实际执行，禁止以直接调用D9包装器代替DA集成验证。首轮2项先失败与实际QEMU缺口、修复记录见[补验分析](QEMU补验与调参页接入修复.md)。

## 验证

先在4.15 AP上复现两项失败，再修复。新增E4回归撤去原E4执行体和高层发送器替身，执行真实原体、九分派、原逐项打包、原发送器的消息复制和真正发送调用点，以及原CP属性任务窗口。原E4对象构造、消息堆／OSAL、未来对象清理、时钟和存储仍为明确夹具；0x402f的CP原生消费及整机成像未执行。清理函数故意返回非零值，防止再次依赖错误ABI。

成功回归核对九条原消息没有额外重发、八项CP字段、AP／CP私有选择和保存编号，并确认退出自定义后原厂八项恢复。失败回归让原厂错误处理返回，以验证私有回退和空闲通知不重试；不能把它描述成实机OSAL失败时不会终止。另测八种属性缺一／重复、代次过期和错误结果不能完成事务。保留完整包回归，同时修正旧夹具对高层返回0的错误断言。

UI回归以真实AP调度器分别处理原生心跳和值通知，无新按键或宿主poll，核对最后目标、重绘返回、稳态无重复提交及调参页保持。它证明收到通知后的行为；是否在QEMU／机身空闲时自然收到通知，需单独观察，不扩大CPU证据范围。并发回归在编译后回执函数的第一条独占加载指令前插入下一次prepare，确认新事务仍不能通过验证。中间候选及被中止的测试不计为最终全套成功，最终数量以完整集合核对证据为准。
