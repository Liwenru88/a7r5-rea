# 二十四槽实施设计

Feature ID: 009-native24-runtime
Status: IMPLEMENTED_OFFLINE

## 边界和文件

`native24-combined/derive.py`从已校验的冻结上游、008编解码原型和当前统一入口派生新源，逐项记录前像／变化。`build.py`只接受新的输出目录：重编上游模块与镜像，叠加来源明确的本地四项和统一入口，导出独立AP、CP及两份图形资源。旧构建器、旧运行时、冻结上游和DAT不改。

`tests/`在实际新AP／CP上验证传输、颜色消费、恢复、原厂切换和快速切换。需要的QEMU适配独立固定新身份，保持原清单／沙箱和不返回成像完成的边界；实际画面无法通过时如实保留失败，不放宽生产门禁。

## 数据／代码布局

沿用008测量：bank57472，第一款Gamma57472，退出表77500，views79600，diag81244，transfer81316，grid81344，恢复缓存392392，额外Gamma486352，总分配947000。原厂75行表、十二基底和32条恢复缓存不扩容。SELECT只切换不可变视图，不额外分配。

AP工作模块保持RX=0x8e90000、RW=0x8ea0000；扩展BSS明确核对终点在统一入口RX=0x8f00000前，报告实际栈使用。字体函数直接参与模块重编，不依赖旧指令位置。统一入口仍用独立RX／RW，所有符号来自本次审计；固定OEM地址继续校验原指令／RELA。

CP保持原getter和接收器地址。新代码直接扩容时7572字节，超过原窗口4字节；0x1195000含原数据不能前移getter。最终仅`native_gamma.c`使用`-fno-inline`，总代码7540字节，其他选项、栈／页表／映射保持；24槽Gamma与尾字段、八档网格和11处原入口寄存器已在最终组件回归，未使用帧链选项或新增映射。

## 协议和持久化

探测独立版本／magic／CP build标识，回复容量57472；传输独立版本／magic、24位mask和终止序列25，完整BEGIN＋PUT＋SEAL至少26次，边界预算显式绑定槽数量。SELECT使用独立版本／magic，能力不匹配时不发布名称或提交应用。旧文件v4与新文件v5保持008兼容规则，0～12边车原字节保留，13～24采用R5SEL5。

冷启动仍先选择并持久化整套数据，再建立CP库；无卡读取机内，休眠只读机内并复用同库。保持原E4执行和持久化成功门禁，不写成功位。共享堆不足时明确拒绝，不覆盖读者持有的库。实际1 MiB预算为测试模型，真实堆余量不作假设。

## 菜单

原十九记录逐字节保留；新增MID 0x1610～0x1627、selector19～42。标题按32项一组，共五种状态，避免F17与F01状态重叠。简称、全名和状态资源同步扩大；两份图形资源各追加48个普通／选中图标。

No9状态快照只在当前原生Creative Look呈现器、同MID／布局／可用位条件下使用；43行必须执行真实注册树、导航并做实际Qt遍历，不能只把31改成43即称验证通过。原厂路径、参数隔离、Enter等待保护、离页取消未提交目标和最后目标合并沿用006。

## 验证与回退

先建旧能力拒绝24号／新协议的回归，再构建新组件。V2真实双CPU、传输故障／资源拒绝、24款选择与ST／FL2／FL3、冷启动／恢复和本地四项；V3有限QEMU仅验实际菜单。E4外部返回夹具与完整QEMU／实机成功分开。没有新DAT或机身准入结论。回退是继续使用保留的十二槽组件；本阶段不迁移用户文件。
