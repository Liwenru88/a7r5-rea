# 三项操作闭环修复：实施与离线验证

日期：2026-11-11。对应[修复前审计](../4.19-operation-audit/审计报告.md)中的 F1、F2、F3。用户授权保留现有成像逻辑和必要保护，修复三个问题并补齐横竖屏、按键及异常恢复的离线回归。

本次交付为源码、实施记录和**非安装组件**。没有连接相机，没有修改历史升级包，没有生成新的 `BODYDATA.DAT`。原 4.19 封存包仍包含审计发现的问题，不能将本次源码修复视为已更新该包。

## F1：同组中键重试先恢复旧状态，再处理最后目标

修改 [r5_filter_runtime423.c](../../native24-combined/runtime/r5_filter_runtime423.c)、[接口](../../native24-combined/runtime/r5_filter_runtime423.h)、[unified-look.c](../../native24-combined/runtime/unified-look.c) 和[构建绑定](../../native24-combined/build.py)。

新增 `r5_filter_recovery_retry()`，只接收状态 5 的显式恢复请求。必须仍处于有效会话，且没有恢复执行或原生对象在途；状态 7 的库不确定性不开放直接重试。以比较交换取得请求权后，发布新代次，交由原唯一工作线程重建恢复预算。

中键在失败保护状态下先请求恢复已提交的旧滤镜及微调；成功后再处理 UI 保留的最后目标。保留原 E4 所有权、两次 CP 确认、配对日志、保存校验及最多 30 次／60 秒的原恢复预算。没有清空完成位、没有用菜单高亮代替 CP 成功。

新方向输入仍能替换目标并取消旧确认。退出菜单仅取消尚未接受的 UI 意图；已经接受的后台恢复继续按原规则完成。DA 调参页中键使用 DA 的原生确认分派，不转交 D9。

测试：[test_recovery_retry.py](../../native24-combined/tests/test_recovery_retry.py)、[test_tabs.py](../../native24-combined/tests/test_tabs.py)。

## F2：画幅启动恢复有预算地补读

修改 [ap_persist.c](../../photo-aspect-ratios/src/ap_persist.c) 与[状态定义](../../photo-aspect-ratios/src/ap_state.h)。

首条原生配置保留立即读取路径，正常冷启动不依赖打开菜单。临时 I/O 或接口错误进入后台补读，包含首次读取在内最多三次，间隔一秒。`ENOENT` 视为没有记录；格式错误、过长文件或无效编号终止补读，保留原文件及原厂回退。不会每帧无限读取。

后台读取继续用选择代次比较交换发布，用户显式操作优先。补读成功后，借用原厂模型锁和属性 `0x52b` 的依赖更新／通知链，推动原生配置更新；不直接构造私有 CP 成功消息，也不在文件线程保存 UI 对象指针。回归实际执行下一条 `0x402d` 的封装，确认恢复 2.35:1 后携带 `0xe5`。

线程使用相机已有的 `libpthread.so.0`，沿用已有运行时的动态解析、64 字节属性缓冲与分离线程方式，独立栈 128 KiB，空闲轮询 100 ms。后台只访问原独立设置文件，不持有声音／CP 的资源句柄。创建失败有可见状态并允许限次重新启动；中断睡眠可继续，其他睡眠错误结束工作线程。

## F3：确认只排队，保存失败显示状态

保留 `/setting/r5_aspect10_v1.dat` 的 16 字节格式、版本、编号及反码校验。确认后由后台保存，采用原独占临时文件、完整写入、文件同步、同目录原子改名和目录同步，不改动原始 BIN 或其他设置文件。

新的确认用代次绑定保存目标与回执。旧写入失败不能污染新确认；忙时保留最后目标。每次确认最多三次写入尝试，间隔一秒；耗尽后停止刷盘，新确认可重新发起。目录同步失败即使文件已经完整改名，也不会宣称持久化成功。

原生画幅菜单标题按状态显示“正在保存”“画幅已生效，保存失败”“正在恢复”或“读取失败”；成功后恢复原厂标题。提示仅对菜单 33 生效，其他菜单沿用原厂标题体。状态变化通过原厂属性通知重绘，不需要再次按方向键。

资源从 C1–C6 后的 `0x0200abde..0x0200abe1` 扩展索引，避免覆盖已占用的 `0xab66`。68 份横竖语言文件一起生成，简繁中文使用对应文字，其他语言暂用英文提示。旧资源表相对指针、原厂载荷、C1–C6 名称和六档比例标签保持。

相关源码：[ap_menu.c](../../photo-aspect-ratios/src/ap_menu.c)、[原生标题续接](../../photo-aspect-ratios/src/ap_menu.S)、[构建前像检查](../../photo-aspect-ratios/src/build_ap.py)、[资源生成](../../photo-aspect-ratios/src/build_resources.py)。测试：[test_persistence_recovery.py](../../photo-aspect-ratios/src/test_persistence_recovery.py)、[test_ap_state.py](../../photo-aspect-ratios/src/test_ap_state.py)、[test_resources.py](../../photo-aspect-ratios/src/test_resources.py)。

## 从原厂 4.00 重建与复验

在仓库根目录执行，`stock` 是已校验的原厂 4.00 解包目录，包含 `manifest.json`、原厂 AP／CP、USR 和 AVCAM 分区。`work` 必须是 `.local` 下不存在的新目录。

```sh
stock=/path/to/verified-stock400
work="$PWD/.local/operation-fixes-reproduce"
bash a7r5-firmware-features/specs/4.19-operation-fixes/build-components.sh "$stock" "$work"
bash a7r5-firmware-features/specs/4.19-operation-fixes/run-verification.sh "$stock" "$work"
```

构建入口实际调用现有模块构建器，不修改原厂输入；再通过正式 `apply_rows()` 合入 NTSC／构图标记。组件夹具逆还原 AP 与 CP 每一层补丁并核对来源摘要，明确标记 `installable=false`，没有伪造 DAT 回读清单。

原生注册树依赖的 `libstdc++.so.6.0.22` 从同一原厂 USR 提取并核对固定摘要，不依赖旧临时目录。Python 使用仓库 `.venv`；仅调用含加密依赖的现有打包辅助函数时使用 DAT 工具自身的 `.venv`。不安装依赖，不访问相机，不签名、不封升级包。
