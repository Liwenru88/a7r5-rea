# 自定义Tab切换导致实机重启

Feature ID: 015-tabs-device-reboot
Status: INVESTIGATING
Mode: bugfix
Created: 2026-11-03

用户报告4.13在顶部从原厂左右切到自定义滤镜Tab的瞬间死机重启，尚未按下、确认或调参。现已明确授权通过指定相机SSH读取和修改文件以分析修复。本轮先保留现场、确认身份并离线定位；不主动复现崩溃、重启、附加调试器、关闭异常保护或改写固件分区。

| Requirement | Acceptance | Verification |
|---|---|---|
| REQ-001 实机证据 | AC-001 固定机型／版本、启动标识、实际四组件和配方，采集已有日志及必要的精确只读状态；区分工具失败与机身异常 | SSH原回执、摘要与离线解码 |
| REQ-002 根因与最小修复 | AC-002 为实际触发路径建立失败回归，保持切Tab不应用、原厂路径、调参、空槽和最后目标保护；不凭旧故障或QEMU通过认定根因 | 真实原生体／最小失败回归及代码对照 |
| REQ-003 兼容复验 | AC-003 修复组件与测试对应，实际十二款BIN、稀疏槽及空库按风险验证；不伪造E4或成像成功 | 定向回归及必要QEMU／相关回归 |
| REQ-004 安全交付 | AC-004 旧4.13与原始证据保持，新修复可审查且回退边界明确；机身写入前明确文件、备份、可逆性及风险 | 差异、摘要及验证记录 |

用户提供的凭据只存于采集进程内存，不写入源码或交付。设备已有状态与新复现／新修改分别记录。高风险持久化替换或主动重启不从一般排查授权中推断，必须先形成具体可审查方案。

2026-11-03进度：已定位图标LDEC失败并完成离线修复，实际机身仍未修改，验收状态继续为NOT_VERIFIED。参见verification.md，不以源码修复或QEMU通过代替机身闭环。
