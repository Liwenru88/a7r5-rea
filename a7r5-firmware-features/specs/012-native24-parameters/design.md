# 独立微调、原生打包与身份保存

Feature ID: 012-native24-parameters
Status: IMPLEMENTED_OFFLINE

## 已核对的接线

011的附加项编号19～42不能进入原18项参数数组。复用原调参页面，虚拟读取／步进／赋值／重置和显示独立分流；保留原初始化的索引与基底隔离。基底不开放修改，避免把色彩配方换成另一基底。

原完整参数发送器在`0x355a4a4`调用`0x355882c`，长度`0x960`，包含八项已知12字节属性记录。仅在该已验证调用点叠加事务参数，不改原厂数组。属性依次为`4030/40f3/40f4/40f5/4031/4032/40f6/40f7`。CP原生字段为`a44/a46/a45/a47/a48/d2e/d2f/d30`。单属性发送处同样按当前事务隔离，原厂目标委派不叠加。完整参数头、八项位置、长度和原分支须严格校验；未知格式拒绝修改并记录故障。

CP组件保持011，使用原生参数处理和现有自定义色彩／Gamma／网格路径，不扩大CP代码或BSS。CPU执行原CP分派和原上下文消费；到达字段不能等同实际像素成像。

首次构建发现AP代码加原PLT副本超过原64KiB映射，构建门禁按预期拒绝。只在新候选将AP私有RX容量改为128KiB，私有RW从`0x8ea0000`移到`0x8eb0000`，文件预留与真实PT_LOAD同步；所有引用由严格链接重新生成，必须校验RW+BSS低于`0x8f00000`的统一入口。原厂六个加载段不改、无W+X；冻结011不变。此调整不触碰CP已满的代码段。

## 配方身份与独立文件

对规范色彩内容（CC1、矩阵、Gamma、网格，含结构域分隔）计算SHA256；不包含名称和槽号。新增独立`R5TUNE.BIN/.NEW`，固定版本／长度／CRC和逐记录范围校验；原始配方保持。记录携带身份、初始八项和保存八项；同一身份共享同一状态，换槽／改名不丢失，不同内容禁止按槽或名称匹配。

新配方八项基准由原厂ST模型的默认字段`0xa8 + 0x1f8*i`建立；`0x50 + 0x1f8*i`是用户工作值，禁止作为初始值。原调参页默认 getter 的`0x2978`与工作 getter 的`0x2920`确认了这一区别。已保存的身份保留原初始值。无卡、冷启动和休眠恢复读取机内记录。最多128个身份，满时拒绝新身份，不自动淘汰；损坏／写失败不能被当成清空或保存成功。

文件采用64字节头与48字节记录，最多6208字节。独立`R5TREC.BIN`日志先记录旧微调和旧选择，再建立`R5RECOV.BIN`；提交先发布微调文件，再完成原选择发布与恢复日志删除。选择日志的删除是提交点，孤立微调日志不能触发回滚。缺少旧选择时先保存合法的0号选择，使两日志逐字节绑定。坏文件原样保留并禁用微调，不静默覆盖。

## 应用与并发

UI修改工作值，不做文件I/O。后台捕获目标配方及八项快照，原E4打包只使用此快照，后续输入留在工作值。成功完成原刷新、选择确认和文件发布后提交；失败使用最后已提交的配方和参数进行后台回退。原厂选择解除叠加后，完整包恢复原值，原厂设置不改。

调参工作值可在等待时编辑和显示；不跳过当前E4、不伪造完成。新数据按最后版本合并。事务参数与已提交参数各有序列号及原子字节发布，跨线程读者遇到变化只重试有限次数，不能混读两次事务。QEMU初始化缺口未消除时，允许真实调参页验证工作模型，明确记录未应用／未保存状态，不把图中数值当成成像证明。

原厂焦点映射`0x16`是对比度，`0x15`是高光；首次进入附加项调参页定位对比度，沿原左右导航走完八项。重置保留原确认框及默认“取消”，确认后只重置当前身份的独立工作值，不写原厂数组。

## 验证与冻结边界

保留011组件、包、上游及全部证据；只编辑拥有源，严格派生构建。先增加身份／故障状态回归，再实现；按行为批次做定向测试，最终运行相关集合一次。新QEMU实验固定新AP及旧CP摘要，不修改默认模拟器，不伪造原菜单像素或状态成功。
