# 实现复盘

Feature ID: 012-native24-parameters
Created: 2026-11-03

现有BIN没有八项标量，不能凭空宣称支持文件内每款不同默认值。本轮只读原ST参数模型的默认字段建立配方的初始微调，之后按色彩SHA256保存初始／工作／已提交值，不从上一附加滤镜或ST工作值读取，不修改BIN。

首次构建`native24-parameters-20261103-01`按预期停在AP菜单／PLT副本64KiB容量门禁，未生成最终候选。通过明确移动私有RW并扩大RX预留解决，不能直接删除大小断言；新增容量及段重叠检查。CP和原厂段保持。

实际QEMU运行`z2ugg54v`发现初始焦点`0x15`对应高光，第一次UP修改第二项。读取两处原焦点表后改成对比度`0x16`，后续真实按键已能逐项编辑八项。`gwadnkp7`完成八项与重入，但脚本直接确认了默认“取消”的重置弹窗，按预期未重置；脚本改为UP选“确认”再ENTER，未修改客体默认交互。

默认字段复核发现`0x50`是ST工作值，`0xa8`是默认值。独立回归在04构建复现错误，最终候选使用默认字段并保持原模型不变。同时为首次选择文件缺失建立合法0号基线，避免两恢复日志一份全零、一份合法选择而在下次启动不匹配。最后补齐事务／已提交快照的原子发布，避免UI和原生发送线程混读不同版本。

原CP参数接收任务、刷新快照、C4上下文构造和锐度／颜色消费窗口实际执行，不改CP组件或由Python写目标参数。帧元数据仍为显式夹具，不能由此推定八项像素效果已验收。QEMU的E4初始化缺口保留，不解除在途保护或写成功位。
