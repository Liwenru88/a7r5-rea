# 本轮整合要点

1. 不能仅因固件同源便套用旧布局。远端活动PHDR已经搬到新增RX段，原RX有效终点也与本地4.06不同；照片标记必须定位活动段表并重新检查同页空白。
2. CP代码区前方并非全部空闲，零前像检查阻止了不安全落点。最终复用本地已有“两条Gamma原样搬迁后使用旧RX”的机制，保留远端映射器和两个完整RX页，不新增可执行映射。
3. 三条实际AP调用窗口暴露了远端保存基底为0时FL2／FL3仍发送ST。整合必须保留本地主选择固定身份，而不能把菜单出现或参数模板存在当作选择链完成。
4. LLVM汇编中的数值ADRP与既有工具的绝对地址约定不同；新函数最终使用远端实际的十二项内联映射和符号相对ADR，独立CPU回归核对普通基底与FL2／FL3。
5. 正常签名与完整解包只证明本地产物内容。新引导组合、声音和照片叠加仍需要独立实机验收，不能用17项测试或736841帧校验替代。
6. 将固定上游归档成无Git快照后，`git rev-parse`可能误读父仓库HEAD，不能直接沿用。新增固定摘要的331文件清单及原188源码锁验证，拒绝篡改和额外源；原Git检出路径仍保持兼容。
7. 成果和中间件放入模块后，递归扫描整个模块作为实施源会把归档DAT和本次输出纳入来源，造成无关依赖和潜在自引用。来源清单现仅枚举本模块代码及直接测试，上游身份由独立快照固定；归档证据与原封包回执分别保存。
