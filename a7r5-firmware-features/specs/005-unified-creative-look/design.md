# 实现设计

原生创意外观描述符位于 AP+0x5858b08，MID=0x1f2，十九行包含 FL2／FL3、六个原生槽及原特殊项。保留全部原行内容和原生 D9 控制器／呈现器；新增十二行使用独立身份及 19..30 的界面选择值，不将其写入原厂模型。保留特殊项原有语义，不猜测其用途。

新增独立 AP 覆盖层，来源严格固定为 E4 修复 AP。新增 RX／RW 段，完整程序头表另存于新增 RX 开头；旧段地址、权限及内容除收据列出的补丁外不动。更新既有 RELATIVE 条目的描述符行指针及 getter，保留位置无关运行。撤回旧主菜单插入并恢复原 PLT 布局；Fn 恢复六候选。旧 0x635 仅允许归一化至 0x1f2 兼容既存引用，不再注册独立描述符。

原行注册完成后追加十二行。原生别名、父项、名称、可见性与图标查询对新增身份分流。原生预览外层、提交和内部写模型入口均对扩展值隔离。初始化、显示、基底和八项调参入口必须保护有限数组；原有十九项继续执行原体，禁止伪造新增项目的原生微调支持。

QEMU 证明原生页面左列走图形路径，接入完整列表 String 更新回调未命中，已撤回该无效接法。独立扩展两个 `image_00_*_IPSX.uxc`，追加 F01～F12 各一对普通／选中图形（不固定绑死 BIN 名称），原 3511 个有效记录及全部像素载荷保持。选中图以黑白反相提供独立焦点反馈，不依赖猜测像素通道色序。图标资源由现有研究过的 UXD 布局独立编解码，不引入32槽后端。原生 D9 左列继续使用原图形路径，右侧显示 BIN 完整名称与应用状态。标题资源编号包含应用阶段，防止同编号字符串缓存导致旧状态滞留；仅在当前 D9 呈现器上通过原 UI 查询请求刷新，不广播成像属性。

UI 等待返回“仍在进行”后，worker 也可能晚到失败。防重入必须同时核对后台状态、命令序列和当前行，不能只检查同步等待函数的返回码；失败不允许值刷新事件自行重试。新增实际 AArch64 回放覆盖该迟到失败路径。

UI 请求沿用现有 r5_filter_request 与后台 worker，等待精确命令序列的有界回执；成功由后端产生，不写成功字段。原厂选择在退出覆盖事务成功后委派原生 setter；失败不委派。显示当前项由已应用编号推导，原生模式继续用原 getter。持久化仍使用原 R5FILTER.BIN 和原厂 Backup，无新增格式或批量迁移。

验证分批进行：先做独立构建及真实 AP 指令边界验证，再接入严格摘要的独立 QEMU 客体。实际 Qt 按键核对列表、跨界选择、失败回退和页面重入；原帧及 AP/CP/文件分别取证。完整启动缺口保持为未验证，不放松沙箱、完成位或原有门禁。

原版对照也在进入 D9 后请求 ON 通知并失败。允许独立候选显式启用单请求待处理模型：校验 ON 请求长度、源队列、上下文和载荷后保留消息所有权，返回“已接收入队”；不回传命令完成，不生成 0x2040，不唤醒原厂等待 future。重复请求／未知请求拒绝。该模型只用于观察尚未完成成像初始化时的 UI 行为，不能据此授予完整启动通过。

最后候选包含一个未奏效的列表保存实验：仅在事务状态变化、原厂刷新未请求、同MID／可用位／布局且确认D9及No9参数类型时，跨原生labels调用保存行数据，不保存几何；切行／布局／可用位变化仍执行原生重建。CPU夹具证明该条件分流按设计运行，但真实QEMU失败终态仍丢失左列，因此它只是待调查代码，不是已验证的修复，不进入升级包。
