# 4.19 全功能整合：实施与复验

以 ILCE-7RM5 原厂 4.00 DAT 为唯一基底，启用十个模块、十档画幅修订 3 和机械／电子双组自定义声音。包头为 4.19。旧的 4.19 单独 24 槽版、4.17 及 4.18 历史目录保持；版本号相同的产物必须按完整 SHA-256 区分。

## 固定输入与配置

- 原厂 DAT：754525608 字节，SHA-256 `51e1176a255a9a4b4782dfbcfa6c5f332b71173bdfe9ed2bcf4fca6bcbc6c2e2`。
- 配置：[full-4.19.json](../../presets/full-4.19.json)。十个模块一次生成共享组件，不能把旧包增量直接叠加。
- 声音：`variants.photo-electronic-shutter-sound = custom-dual-full`。缺少变体仍保留历史原厂声音；未知变体及不完整组合拒绝构建。
- 配方：随包为现有正式十二款 `R5NATIVE.BIN`，容量仍是 24。24 槽合成库用于全部槽位协议回归，与随包配方分开。
- 沿用现有研究签名身份。公钥摘要为 `7f65b296987df665da217de514e785f75238e686ddd18952fa425fc47e8c858a`；私钥不进入交付目录。

## 关键布局与修复

| 区域 | 全功能布局与约束 |
| --- | --- |
| AP 声音和滤镜主运行时 | RX `0x8e90000`，RW `0x8eb0000`，实际 BSS 331248 字节；保留容量及栈检查 |
| AP 创意外观 | RX `0x8f10000`，RW `0x8f20000`；声音四个父菜单重定位与原 PLT 保留 |
| AP 画幅扩展 | 代码 `0x8f14400`，选择状态 `0x8f22b60`，会话 `0x8f22d00`。依据已核验的 ELF 布局移位，不依赖测试环境变量 |
| CP 常驻代码 | `0x1195260..0x1197000`，7584 字节。CRC 仅取消一层尾调用包装，共享 CRC 算法保持 |
| CP FL2／FL3 | 矩阵和原生曲线 `0x1a3a000..0x1a3ad80`，原系数和运算保持 |
| CP 画幅状态 | `0x1a3ad80..0x1a3af80`，保留逐张锁存、复制及复用清理 |
| CP 声音代码 | `0x1a3b000..0x1a3b8c0`，完整页处于 BSS 末端到 L1 页表之间的对齐余量，独立映射并检查 PTE 和完整代码 CRC |
| CP 页表 | 保持原生 `0x1a3c000`。不得把 BSS 扩大到该位置，否则原生页表会后移 16 KiB；真实启动指令回归强制检查 |
| CP 启动助手 | 画幅助手 → 六款 `0x109000` → 声音 `0x109100` → 原厂映射；矩阵早期复制继续使用 `0x108f8c`，保留原助手 |

USR 写入使用独立的 `usr-components` 暂存目录。NTSC／标记补丁不得改写已生成的画幅 AP 中间文件，否则会破坏收据摘要和独立逆还原。最终文件由各层收据及最终 DAT 回读共同绑定。

AVCAM 仅在原 FAT 簇链余量内增长，MPR 保持原加载区再增加只读执行段；其他文件和分区保持。WBI 仅清零包内首 512 字节并保持尾部，重算 `part_image.sum`。不修改更新器和内核。

## 构建与独立解包

从仓库根目录操作，准备现有两个虚拟环境和 LLVM。输出目录必须全新，封包器继续使用原有 `.local` 路径保护。

```sh
mkdir -p .local
a7r5-dat-tool/.venv/bin/python -B a7r5-firmware-features/compose.py plan \
  --config a7r5-firmware-features/presets/full-4.19.json
a7r5-dat-tool/.venv/bin/python -B a7r5-firmware-features/compose.py build \
  --config a7r5-firmware-features/presets/full-4.19.json \
  --base a7r5-firmware-images/官方升级包/BODYDATA.DAT \
  --version 4.19 --output .local/full419-new
a7r5-dat-tool/.venv/bin/python -B a7r5-firmware-features/compose.py verify \
  --base a7r5-firmware-images/官方升级包/BODYDATA.DAT --bundle .local/full419-new
a7r5-dat-tool/.venv/bin/python -B a7r5-firmware-features/materials/dattool/dattool.py unpack \
  .local/full419-new/BODYDATA.DAT --public-key a7r5-dat-tool/keys/research-public.pem \
  --output .local/full419-new-readback
```

新声音变体还保存 `build-evidence/native24` 和 `build-evidence/capture`，包含实际组件、对象、符号和构建收据。封包回读核对所有 147 个归档成员、736841 帧、完整包头、分区与研究签名，并以 OpenSSL 独立验签。USR 执行 `e2fsck -fn`。

## 回归入口

正式原厂输入解包位置由 `A7R5_PHASE3_STOCK` 指定。滤镜历史对照 `A7R5_PHASE3_417` 必须含已锁定的 4.17 CP；注册树所需 `libstdc++.so.6.0.22` 的 SHA-256 为 `28f2d082aea5206c42ba15664f39e2eaf7febed8f6264305e7e16aa44c878389`，可从已核验客体只读提取。

```sh
export A7R5_FINAL_BUNDLE="$PWD/.local/full419-new"
export A7R5_FINAL_READBACK="$PWD/.local/full419-new-readback"
export A7R5_NATIVE24_BUILD="$A7R5_FINAL_BUNDLE/build-evidence/native24"
export R5_SOUND_WORKSPACE="$A7R5_NATIVE24_BUILD/work"
export A7R5_ASPECT_CAPTURE="$A7R5_FINAL_BUNDLE/build-evidence/capture"
export A7R5_ASPECT_AP_INPUT="$A7R5_NATIVE24_BUILD/appFw.so"
export A7R5_ASPECT_CP_INPUT="$A7R5_NATIVE24_BUILD/cpapp-b.bin"
export A7R5_ASPECT_NATIVE24_IMAGES="$A7R5_NATIVE24_BUILD"
export A7R5_OPTIONAL_AP_READBACK="$A7R5_FINAL_READBACK"
.venv/bin/python -B -m pytest -q -p no:cacheprovider \
  a7r5-firmware-features/photo-aspect-ratios/src \
  a7r5-firmware-features/tests/test_full419_integration.py
.venv/bin/python -B -m pytest -q -p no:cacheprovider \
  a7r5-firmware-features/photo-electronic-shutter-sound/tests \
  a7r5-firmware-features/tests/test_compose_419.py
```

原生画幅回放包含 RAW 头 144 个场景、横竖遮罩、JPEG／HEIF 局部区域、MPR 元数据、回放图标及放大资格。共享回归包含两组记忆、24 个槽、失败恢复、八项偏移、声音原生菜单、页保护、NTSC、标记和十二模板字段。各实际命令及结果随交付回执归档。

## QEMU

[full419 实验目录](../../../a7r5-qemu/experiments/full419/)使用最终 DAT 独立解包后的 AP／CP、68 份文字资源、两份图标、MPR 与随包 BIN。固定模拟器、内核和 GPE 摘要保持，未知组件与构建锁不符即拒绝启动。

```sh
cd a7r5-qemu
PYTHONPATH=tools .venv/bin/python -B experiments/full419/build_guest.py \
  --bundle ../.local/full419-new --readback ../.local/full419-new-readback \
  --output build/full419-new
PYTHONPATH=tools .venv/bin/python -B experiments/full419/run_validation.py \
  --manifest build/full419-new/manifest.json --log runs/full419-new.log
```

以保存会话的 `exported-files.json` 传给 `build_guest.py --restore` 和 `run_validation.py --restore`，在全新虚拟 VFAT 中检查无卡恢复。串口只剔除已识别的异步 UIPC 日志，所有导出文件仍需通过 CRC、身份、长度与十档载荷摘要；未知数据拒绝。

QEMU 界面使用真实 Qt 按钮。初始智能自动模式下原厂限制创意外观是正常保护；通过 `MODE_M` 模拟原生模式转盘事件后再验证创意外观，不解除生产模式保护。CP 侧车不代表完整 RTOS 启动，音频、SD 和图像硬件边界明确使用替身。

当前 QEMU 的 `0x4073` 订阅夹具只保留等待，不产生原生 `0x2040`，因此自定义滤镜的实际 E4 成功完成和参数提交不能由菜单截图验收。菜单如实显示“等待切换”；成功事务、九条参数消息及 CP 色彩消费由最终包内 AP／CP 指令回放验证。本轮没有扩大硬件模拟或通过补写成功状态掩盖限制。

## 验收边界

离线通过不等于机身升级、启动或拍摄验收。真实扬声器、曝光到声音延迟、实卡／eMMC 断电、物理 LCD／EVF、JPEG／HEIF／ARW 成片、动态 MF 放大和实镜 AF 仍需另行实机验证。本轮不连接相机。
