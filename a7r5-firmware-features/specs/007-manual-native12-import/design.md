# 手动热导入设计与实施门禁

Status: DEFERRED

用户已选择维持现有冷启动导入，当前不实施本设计。下文是保留的热导入候选方案，其G1内存／读者门禁不作为本次冷启动版的交付前置条件；未来重启本方案时再重新核对代码与证据。

## 用户操作与菜单

预期入口为同一“颜色／色调”分组下的“创意外观”和“自定义滤镜导入”。导入页选择卡槽1或卡槽2，读取该卡根目录`R5NATIVE.BIN`，展示读取／校验／导入状态；成功提示“已导入N款，创意外观已设为ST”。导入后按用户最新要求实际选择ST，ST的微调及保存行为走原厂正常选择路径。

统一列表没有独立的“关闭自定义滤镜”项。用户选择ST、PT或FL2／FL3等原厂项时，解除新增配方覆盖后应用所选原厂外观；选择新增项时才启用对应配方。手动导入的默认结果明确为ST，不是任意一个先前原厂外观。

后台自定义编号0与原厂ST选择值0属于不同状态空间。前者只说明没有新增配方覆盖，不能据此显示“ST已生效”。需要分别确认CP覆盖解除和原厂ST选择／刷新，并由原厂机制保存；不能只改标题、菜单MID或直接改写Backup文件来模拟原厂选择。

不存在有效机内配方时，仍显示导入入口。卡槽由原厂介质状态映射到当前盘符，不把卡槽号硬编码为A／B；所选卡失败不能悄悄改用另一张卡。零字节和合法空包在此入口明确拒绝，保留旧配方。

新MID及资源编号先进行注册表冲突检查，不复用旧私有菜单`0x635`，避免破坏其归一化到`0x1f2`的兼容行为；原有Fn六候选保持。

## 已核实的约束

| 约束 | 所有者与证据 | 设计影响 |
|---|---|---|

| 冷启动先找SD，成功后替换机内文件 | 同文件`r5_stage411_child()`／`r5_stage411_persist()` | 新派生版本须拆开“内部启动读取”和“显式卡导入” |
| CP每库522152字节，旧代际保留 | `r5_custom_filter423.h`、`cp_stage413_probe.c` | 不能使用每次导入分配并永久保留的方式；双库也不能直接假设可容纳 |
| 现有SEAL会立即公布新bank | `cp_stage413_probe.c`接收器 | 需要区分候选准备与事务提交，不能直接复用旧SEAL即切换逻辑 |

| 006已有单笔在途与最后目标合并 | `unified-look.c`的`flow`／`pump()` | 导入须与选择共享协调入口，不能并发替换其bank或重放旧目标 |

本轮运行了现有两项真实CP机器码回归：同内容复用、不同时代际的资源失败保护，2项通过。在1048576字节的显式测试预算下，两库占1044304字节，第三库分配拒绝并保留旧库。这证明当前累计分配限制，**不是实机可用堆大小或导入次数测量**。

## G1：实现前必须解决的安全门禁

先建立可源绑定的读者生命周期和完整内存预算。必须覆盖CC1／矩阵、Gamma、网格、原生关闭view及可能跨函数保留的指针；CP接收器串行锁、SELECT0回复和E4返回都不能单独作为所有成像读者已经释放的证明。

候选方向是有界参数池配合可证明的读者退出栅栏；须先核对两个现有大库、消息、原厂其他开销是否能同时容纳。不能容纳时，应先证明可保持参数语义的布局改造或其他有界方案，而不是假设分配成功。AP名称及原生UI持有的字符串同样需要生命周期证明，不能简单对16份目录循环覆盖。

G1交付包含：读者／持有者清单、进入与退出点、候选内存布局及峰值预算、保留旧读者时拒绝复用的回放、旧读者退出后多次复用的回放、迟到消息拒绝，以及从导入页面进入原厂ST选择／保存路径的源绑定证据。当前ST原行MID为`0x84c`、选择值0；不能把仅解除覆盖与原厂ST选择混为一次操作。未证明时停止在离线研究阶段，不能写入／释放活跃库，不能声称热加载已完成。G1若不能在本轮环境证明，后续实现任务保持未完成并写明缺口。

## 导入所有权和状态机

一个AP后台所有者负责导入，UI只提交“卡槽＋会话／介质代际＋请求序号”，定期读取状态。实际目录／Fsys句柄不跨任务转交。槽位准备状态和拍摄／录像空闲条件来自原厂已验证接口；未知状态按不可导入处理。

状态划分为：`IDLE → READING → VALIDATED → PREPARING → PREPARED → COMMITTING → VERIFYING → SUCCESS`；另有`CANCEL_REQUESTED`、`FAILED`、`RECOVERY_REQUIRED`。它们是待实现接口，不代表已有代码。

- READING：固定路径只读，限制长度／读次数，完整校验当前v4格式、机型／基线、CRC及槽参数。读完并关闭SD句柄后再进行跨处理器等待。
- PREPARING：保留旧数据，准备候选文件、名称目录和CP参数库；预检容量及当前模式下ST原厂路径是否可用，不可用时不进入提交。选择事务先按原门禁结束，取消尚未提交的006旧目标。导入过程中新的选择请求被明确拒绝为忙，不积累待导入结束后自动执行的旧意图。
- PREPARED：所有候选可验证但还未公布，取消应可清理本事务候选。固定暂存文件必须核对归属，不能批量清理目录。
- COMMITTING：解除新增配方覆盖、执行G1规定的读者切换／退出流程，协调机内文件、新bank、自定义编号0和名称目录发布；通过已验证的原厂选择路径切到ST并完成对应刷新／保存。此阶段不以“取消”中断一半；退出页面也不能将所有者销毁。
- VERIFYING：核对精确代际／CRC、CP状态、AP目录、原E4门禁、机内配方与选择文件，并分别回读原厂ST状态、实际焦点及其保存／恢复结果。全部匹配后显示成功，并允许用户重新进入创意外观选择。

重复点击同一导入操作不产生第二个所有者。相同配方可以走已验证的复用路径，但仍须实际回到ST；不能因CRC相同或内部编号为0而跳过原厂ST选择及结果确认。

## AP／CP协议与持久化

具体操作码和地址在G1之后源绑定，不在设计中猜测空闲编号。需要协商的语义为“准备、查询、提交、放弃候选”，精确关联会话、导入序号、代际、掩码和内容CRC。错代际、重复／迟到消息不得改动当前bank；缺少新能力时明确拒绝热导入，不偷偷走旧冷启动接口。

配方文件及选择文件保持现有格式，但它们的替换与CP内存提交不是天然的单个原子操作。设计需要同目录、版本化并带CRC的恢复记录；候选路径暂定`R5NATIVE.NEW`、受控旧版本引用和`R5IMPORT.TXN`，最终名单及归属规则在T003固化。不能直接依次覆盖两个正式BIN并宣称事务原子性。

提交前完整旧数据仍可用。进入退出覆盖／持久化步骤后，记录旧配方身份、旧自定义编号、旧原厂外观状态、候选身份及ST确认阶段；启动先处理未完成记录，再读取已确定的机内配置，绝不扫描SD决定恢复。恢复结果只能是“经校验旧状态”或“经校验新配置、自定义编号0且原厂ST已确认”，不能是新配方加旧非零编号。若ST尚未设置或保存未确认，保持恢复未完成，不能把它报告为导入成功。

涉及原生rename／fsync失败后发布状态不确定时，应保留诊断与恢复材料，展示`RECOVERY_REQUIRED`。如果退出覆盖后无法恢复旧选择，提示旧配方保留及实际可确认的外观；只有ST已确认才能显示“当前为ST”，无法确认时显示“外观恢复未完成”。不能承诺任何阶段失败都必然恢复原画面，也不将内部覆盖状态包装成可见的“关闭”外观。UI成功门禁不接受仅有消息入队或自定义编号0的结果。

## 启动与目录刷新

冷启动和恢复都只读取机内配置与选择记录；启动不打开卡上的BIN、不写SD诊断文件、不因等待SD而延迟机内加载。无配置或配置无效时保持原厂路径，导入入口可用。

本次导入成功后的保存状态必须能恢复为ST。正常启动不得将所有历史`R5FILTER.BIN=0`一概改成ST：该文件只记录无新增配方覆盖，原厂PT／FL2等仍按各自原厂保存机制恢复。用户后续明确选择其他外观时，同样按原有逻辑保存。

导入提交后在UI所有者上发布一个新的目录代际，刷新创意外观原生页面与父菜单。资源缓存键应包含目录代际或通过已验证的原生失效／重建流程更新，不能只在掩码变化时刷新。F01～F12编号图标保持，名称来自新包。旧006目标、旧字符串、旧回执不能作用于新目录。

## 验证、风险与回退

主要验证层是V2真实AP／CP协议及有界内存、文件事务回放，覆盖成功和独立失败结果；文件发布中断、会话／迟到消息以及生命周期需要相关V3回归。UI验证使用原厂真实Qt输入和原始帧。CPU夹具或简化QEMU不能替代原厂指针生命周期证明及实机准入。

| 影响对象 | 风险与可逆性 | 回退与限制 |
|---|---|---|
| 原开机行为 | 卡上新文件不会自动导入，是用户已确认的行为变化 | 独立候选保留旧e833…组件和旧包；旧版本仍按旧自动导入规则运行 |
| CP消费者与活跃内存 | 错误复用可能造成参数混用或崩溃，不能依赖事后回退弥补释放错误 | G1未通过不得安装热替换路径；不覆盖／释放读者仍持有的数据 |
| 机内文件与当前选择 | 多文件／内存跨阶段中断可能不一致 | 候选＋恢复记录＋明确失败状态；记录可验证恢复边界 |
| 协议与菜单 | AP／CP不匹配、旧UI或旧回执可能指向旧目录 | 能力协商及代际校验，旧组件组合不支持时拒绝导入 |

本次实施确认只应覆盖离线代码、模拟验证及研究组件；相机操作、刷写或正式DAT交付另行处理。不得以旧版本实机测试替代本功能验收。
