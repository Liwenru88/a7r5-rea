# 自定义滤镜手动热导入

Feature ID: 007-manual-native12-import
Status: DEFERRED
Created: 2026-11-03

## 当前决定

2026-11-03用户选择保持现有冷启动导入。本手动热导入方案暂不纳入当前版本，T002～T006不启动，不增加同级导入菜单，不改变AP／CP或开机逻辑。当前继续冷启动优先导入卡上有效BIN并保存机内、卡上无文件时读取机内、休眠恢复只读机内。

下文保留此前已讨论的候选需求作为历史设计，特别是“冷启动仅机内读取”不再是本次版本目标。统一创意外观无独立关闭项、选择ST走原厂ST逻辑的要求继续有效，与本方案搁置无关。

## 已确认的需求

在006统一创意外观候选基础上，与“创意外观”同级新增“自定义滤镜导入”。用户选择卡槽后，从该卡根目录读取`R5NATIVE.BIN`，导入成功后无需重启即可在统一创意外观中选择新配方。成功时按原厂创意外观逻辑切换到ST，等待用户重新选择其他外观或新配方。界面没有独立的“关闭自定义滤镜”选项。

用户已经确认：

1. 配方继续叫`R5NATIVE.BIN`；机内`R5FILTER.BIN`继续只保存所选编号。
2. 首版只选择卡槽、读取根目录固定文件，不做目录浏览。
3. 冷启动只读机内保存的数据，不再自动扫描SD导入；休眠恢复同样不自动导入。
4. 导入成功后回到ST，不沿用旧编号自动应用另一款配方；这替代前版“保留当时原厂外观”的设计。

ST及其他原厂外观与新增配方是同一列表中的互斥选择。用户选择ST就执行原厂ST路径；选择PT、FL2／FL3等也按其原厂路径生效，不叠加新增配方。内部解除旧覆盖的编号0属于实现状态，不能单独作为“已切到ST”的证明，也不新增一个可见的关闭项。

以上产品行为已确认。实现前必须通过CP参数读者生命周期、内存预算和存储恢复的离线设计门禁；当前热导入尚未实现。继续保持不连接相机、USB、SSH、实体卡或主机原始分区的边界。

## 范围与兼容

- 保留原厂外观、FL2／FL3、十二款统一入口、006快速切换修复及本地其他补丁。
- 接受现有v4配方格式中的1～12个有效槽；导入时拒绝零字节文件及空配方包，不增加隐式清空操作。
- 继续使用`/usr/data/lut/R5NATIVE.BIN`及24字节`R5FILTER.BIN`，保留已有有效机内配置的读取能力。
- AP／CP热替换使用独立派生源码和协商接口；冻结上游、32槽工程、旧AP／CP及4.10／4.11 DAT不覆盖。
- 本阶段不发布DAT、不操作设备，也不将“保存后重启生效”冒充热导入成功。

## 验收标准

|---|---|---|
| REQ-001 同级导入入口 | AC-001 原“创意外观”旁有“自定义滤镜导入”；进入后可选卡槽1／2，固定读取所选卡根目录文件；不自动回退到另一张卡，不新增Fn候选或独立关闭项 | 注册树／原生路由回放、真实Qt与原帧 |
| REQ-002 仅从机内启动 | AC-002 冷启动／恢复从机内读取；即使卡上有不同配方也不隐式导入或覆盖；机内无有效配方时仍可使用原厂外观并进入手动导入 | 启动worker定向回归，记录SD打开次数为0 |
| REQ-003 不重启更新配方并回到ST | AC-003 合法文件校验、准备、持久化及CP切换全部确认后，新名称和槽位可用；解除新增配方覆盖，实际执行原厂ST选择／刷新并按原厂机制保存；后台及机内自定义编号均为0，原厂当前外观、菜单焦点及保存／恢复结果为ST，才能提示成功 | AP／CP协议、原厂ST回调与状态回读、文件及目录回读、原帧和重入／恢复核对 |
| REQ-004 有界内存与读者安全 | AC-004 不覆盖／释放仍被参数消费者引用的库；跨过旧实现2库测试预算及16名称目录边界后仍可继续导入，内存有上界；无资源或未能排空读者时拒绝导入并保持可恢复状态 | 真实CP指令、保留旧读者／迟到消息、重复导入及内存预算回放；原厂生命周期源绑定证据 |
| REQ-005 事务与恢复 | AC-005 提交前错误保留旧配方；提交边界中断时恢复经校验旧状态，或恢复新配置并完成ST原生选择；不能把新配方配上旧非零编号，不能把内部编号0冒称ST；回滚失败／持久化不确定必须明确显示 | 文件故障／断点恢复、原厂外观与内部编号不一致、AP／CP失配及回滚失败回放 |

| REQ-007 追溯与离线交付 | AC-007 严格前像、协议身份、逆还原及独立构建／清单，真实帧与PNG一致、MENU生命周期及正常退出；新功能各阶段与实机未验证项分别记录 | V0文档与摘要，V2行为回归，必要V3故障与QEMU观察 |

现有QEMU完整成像模型缺口单独记录。用户报告旧版本实机没有E4初始化阻塞，不等于新热导入的实机验收或设备I/O授权。
