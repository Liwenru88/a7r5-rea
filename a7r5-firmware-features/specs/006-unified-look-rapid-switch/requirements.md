# 统一创意外观的快速切换修复

Feature ID: 006-unified-look-rapid-switch
Mode: bugfix
Status: IMPLEMENTED
Created: 2026-11-03

用户确认采用“只应用最后停留项”：已有事务继续完成，连续输入覆盖单个待处理目标，中间项跳过。范围是005统一入口候选，保持离线；不修改冻结4.11包、上游、CP、BIN或32槽工程，不解决完整成像初始化和既有列表消失问题，不生成DAT。

原问题：上一笔尚未结束时，同项刷新或快速切到下一项会被后台忙态拒绝，UI却记成失败；上一笔随后成功，错误标题仍残留。原UI同步等待最多20秒，也妨碍合并连续输入。前次真实AP回放已复现，现补正式回归。

| Requirement | Acceptance | Verification |
|---|---|---|
| REQ-001 串行合并 | AC-001 只有一笔在途事务和一个最新目标；忙态不重复提交、不显示失败，输入不再同步等待；A进行中依次选B、C，完成后只提交C | 真实AArch64入口及真实后台提交器的交错回放 |
| REQ-002 精确结果 | AC-002 成功／失败只归属于匹配命令序列与目标；迟到或外部命令不完成新目标，实际失败保留旧应用结果，同项值刷新不自动重试 | 成功、失败、序列替换和拒绝边界回放 |
| REQ-003 原厂切换及生命周期 | AC-003 原厂目标也合并；退出覆盖成功后才能按当前原厂目标执行原路径。离开页面取消未提交目标，已接收事务继续按后台门禁结束；等待时Enter不关闭页面 | 原厂委派、取消／重入及D9 dispatch回放 |
| REQ-004 状态显示 | AC-004 新增十二项标题区分已应用、应用中、等待应用、未应用和当前目标失败；原厂应用值与界面焦点分开，忙态拒绝不污染后续标题；原厂项保留原标题 | 实际标题资源／字符串与状态查询回放，有限QEMU画面 |
