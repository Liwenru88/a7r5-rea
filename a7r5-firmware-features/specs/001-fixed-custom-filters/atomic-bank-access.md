# 整预设、银行集合与帧引用：第十五批接入契约

- Feature ID: `001-fixed-custom-filters`
- Updated: `2026-10-26`
- Status: `OFFLINE_CONTRACTS_VERIFIED_NOT_INSTALLED`

## 结论与实际范围

新增了可执行的整预设事务核心、4.06输入状态写入器，并与原CP有锁快照联合验证。银行集合、会话和帧租约是实际C实现，成功/失败事件由测试提供。原CP的资源守卫、回复封装和EVF对象初始化也已执行原指令。**没有安装新的AP/CP消息入口，没有将实际银行或最后帧释放接入这些核心。**

三层证据必须分开：`INPUT_PREPARED`表示九个输入字段已准备；所有必要消费者成功后才允许发布完整银行集合；每帧的全部输出和拥有者最后引用结束后才允许回收该集合。原消息发送返回0、完成掩码清零、JPEG守卫返回或缓冲句柄登记清除，都不足以替代后两层。

## 原子输入落点

新代码：[af_cp406_state.c](../../custom-filters/native/af_cp406_state.c)、[af_cp406_state.S](../../custom-filters/native/af_cp406_state.S)。输入根`0x157aa10`，源快照长度`0xdbc`，原互斥`0x24`。

| 输入 | 根内偏移 | 编码 |
|---|---|---|
| 基底 | `0xa40` | 小端32位；AP基底0～9对应`0,3,2,1,16,15,17,18,5,13`，FL2/FL3的17/18对应19/20 |
| 对比度 | `0xa44` | 有符号8位 |
| 高光 | `0xa46` | 有符号8位 |
| 阴影 | `0xa45` | 有符号8位 |
| 褪色 | `0xa47` | 有符号8位 |
| 饱和度 | `0xa48` | 有符号8位 |
| 锐度 | `0xd2e` | 有符号8位 |
| 锐度范围/精细度 | `0xd2f` | 原字段范围1～5 |
| 清晰度 | `0xd30` | 有符号8位 |

叶函数先验证完整纯参数预设及三个独立内存范围，再写九字段，其他字节保持；最后设置`0x19c999d=1`，保留原高光/阴影/褪色分派的额外副作用。LUT及非法值在写入前拒绝。汇编入口调用原ARM服务`0x5b8d6c(0x24)`获取互斥，写入后执行`dmb sy`，再调用`0x5b8910(0x24)`释放。

原CP消息任务本来已持有`0x24`，未来从该任务接入时必须调用叶函数，不能再次调用带锁入口。释放失败返回`AF_IO`时输入可能已改变，不能报告回滚成功。`dmb`也不证明DMA缓存一致性或其他未持锁读取者安全。

联验在新写入器的首个、中间和最后写点暂停，以独立寄存器上下文及独立栈执行原`0x898548`快照。持锁时目标保持，恢复写入并解锁后，原`0x4b8d88…0x4b8dc4`读到完整新值。无锁叶函数的中间快照实际出现混合值，证明测试没有只检查一个锁标志。原快照被拒绝时`r0`可保留目标首字内容，本次为`0x5a5a5a5a`；不能把它当规范错误码。

## 统一银行集合

代码：[af_apply.h](../../custom-filters/native/af_apply.h)、[af_apply.c](../../custom-filters/native/af_apply.c)。三个集合，每组保存完整预设、版本、槽号、最多13个输出范围和帧引用数。13是原完成身份的研究上限，具体模式所需掩码仍必须从真实路由确认，不能假设每帧恒用13项。

调用顺序：

1. `af_apply_init`：对象首次清零；由上层提供非零且不复用的启动会话。有待处理事务或帧引用时拒绝重建。
2. `af_apply_negotiate`：只接受已经解码、相同会话/必要消费者集合的规范HELLO；实际安装必须来自真实对端收包。
3. `af_apply_stage`：一次校验和复制完整预设；只选非活动且无帧引用的集合。接受版本严格递增，失败/取消的版本也不能重放。
4. `af_apply_reserve`：生成之前逐个预留全部输出地址/长度，拒绝重叠、未对齐、32位溢出、单项超128KiB及与活动/帧引用集合重叠。内存本身仍由实际分配器拥有。
5. `af_apply_start`：全部预留后才允许声明启动；本函数不派发实际任务。未启动时可以取消，取消后旧完成事件失效。
6. `af_apply_bank`：每个必要消费者只接受一次同会话/版本/集合回执；成功必须与预留范围完全一致。失败也必须表示该消费者已经退役。
7. `af_apply_publish`：全部必要输出成功后，单次切换活动集合；逐个修改原全局颜色/锐度指针不属于本契约。任一失败保持旧活动集合。
8. `af_apply_abort`：已启动事务必须等待全部声明消费者成功或失败退役；超时不能直接清空和复用。

所有入口由一个事件拥有者串行调用。这里没有跨线程锁，也没有把普通C字段赋值变成真实多核发布协议。实际接入须让消费者从同一个帧租约取得完整集合，验证发布/缓存屏障和输出内存寿命；现有原颜色与锐度窗口仍分别更新，尚未被重接。

## 最后引用与失败退役

`af_apply_frame`在帧起始声明所有输出位，最多64个同时存在的帧租约；自动附加独立的拥有者屏障。`af_apply_view`只在租约有效期间借用不可变集合。`af_apply_retire`结束已声明输出，`af_apply_owner_end`结束真正帧拥有者最后引用，两者都结束才减少集合帧引用。重复释放、过期版本/会话/租约均拒绝；先结束拥有者也不会提前回收尚有输出的集合。

输出位尚未绑定EVF/JPG实际身份，不能从“JPEG完成”直接调用`owner_end`。也不能在租约结束后保留`view`裸指针继续读取。实际CP仍有C4浅复制及共享根别名，必须把真实全部借用者迁到租约，或补齐最后借用者证据。

本批执行原链：`0xae4170 → 0x462734 → 0xae2afa/0xae2bda → 0x462c5c → 0x462cdc → 0xb2b42c → 0xb2a5a4`。两组使用同一照片`CapRsrc_JPG`虚表及成对守卫，驱动成功/首驱动失败分别注入：

| 原守卫返回后 | 成功 | 首JPEG驱动失败 |
|---|---:|---:|
| 请求计数`+0x28` | 0 | 1 |
| 节点使用标志`+0xc` | 0 | 1 |
| 持有计数`+0x6c`/节点持有`+0xd` | 0/0 | 0/0 |
| 节点登记/回收池 | 已摘链/已归还 | 已摘链/已归还 |
| 原缓冲归还函数 | 执行 | 执行 |

实际执行缓冲函数后，两个夹具缓冲头从`0x20`变为`0x80000020`，`0x1934564`写入1，原句柄登记清除。这里只证明归还请求/标志写入；未执行后续缓冲管理器，不知道像素、DMA或其他借用是否已结束。尤其失败后节点使用仍为1，但节点已经摘链和归还，不能把析构返回当作最后引用。

## 版本包与原回复

[af_apply_wire.c](../../custom-filters/native/af_apply_wire.c)实现固定128字节小端研究包：

| 偏移 | 字段 |
|---|---|
| 0～15 | `A7P1`、协议1、HELLO/PRESET、长度128、必要消费者掩码 |
| 16～35 | 64位会话、64位版本、用户槽1～20 |
| 36～47 | 基底、纯参数种类0、八项值、零保留字段 |
| 48～111 | 父修改4.06 AP/CP的两个SHA-256 |
| 112～123 | 载荷版本1及零保留字段 |
| 124～127 | 前124字节的CRC32 |

这些SHA识别父构建，不测量正在运行的对端映像，也不提供认证。真实传输命令ID、负载容器、会话来源、双向协商及AP超时/future对象仍未接入。旧12字节消息不能直接装下本包，也不能把本包的操作码当作原CP消息种类或命令ID。

原回复链`0x898210 → 0xaf051e → 0xaf06c4`发诊断，再到`0x496180`，后者分配、执行原ARM memcpy、由`0xbaaaa0`写来源`0x90030001`，调用队列发送至`0x80020002`。本批执行发送成功、分配失败、发送失败后释放、两种目的字段过滤共5例。**过滤路径完全不发送也返回0**。分配/发送/释放和诊断为显式隔离后端，未执行物理IPC；夹具采用原“不支持命令”回复格式，不是预设已应用回执。

原参数分派成功路径`0x345c86…0x345cae`只执行表回调/接收器及更新标记，不会自动提供新协议的版本确认。不能在AP看见旧封装返回0就标记APPLIED。

## EVF/JPG路由定位结果

照片资源已由`Camera::Capture::CapRsrc_JPG`的原RTTI/虚表绑定。EVF本批新增明确的显示层身份：

- `VDF::VfxmixExecutorDevEvf`：RTTI`0xc93a80`，虚表`0xce2718`；原构造入口`0x6ab7ee`初始化对象`0x16a8268`及回调`0x1f62b1`。
- `VDF::DevEvfCmdOutv`：RTTI`0xce2768`，虚表`0xce272c`；原`0x6ab816`将输出命令身份设为`0xb`。
- 原回调`0x1f62b0`进入通知入口`0x6a3070`前，实际提供端点`0x9059081a`及传入的16位值。本批在通用通知服务前停止，不伪造“已显示”事件。

上述原构造和回调已执行，不只搜索字符串。但显示执行器仍未关联到原照片操作上下文`0x165d758/0x165d820`，也未证明颜色银行`0x1efb7d0`、锐度银行`0x1f52cf8`到EVF/JPG的同版本使用。ScalarInfra LiveView的JPEG类型仍不能代替这一关联。

## 实际接入与LUT/菜单剩余清单

后续补证：第十六批已加入原消息私有HELLO入口，第十七批又接通原任务启动与原OSAL轮询；这些不改变本文的银行/图像帧安装门槛。第十七批还实际执行原句柄占用`0xb2b37e`与归还`0xb2b42c`，证明同句柄再次占用无代号变化，夹具重放旧归还可以清除当前占用；全局`0x1934564`又可被另一句柄的占用清0。不能把这两处直接绑定到`af_apply_owner_end`。具体原指令、回执边界及后续代号要求见[运行时与缓冲接入](runtime-access.md)。
