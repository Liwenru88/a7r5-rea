## 验收顺序

依次验收，每一项保存候选SHA、现场状态、日志和结果，前项失败不扩大测试：

1. 先验证一次受控更新是否由机身明确报告完成，再观察正常启动／MENU／拍摄页及真实AP／CP版本握手；软件函数返回0不足以认定握手或升级已完成。
2. 验证原厂12外观含FL2／FL3和原六自定义槽内容保持，再检查固定C01～C20、列表导航、中文名称与八项参数显示／调整。原厂外观不得被导入或保存覆盖。
3. 先创建一个纯参数用户滤镜，临时编辑、取消、保存、另存，确认其他用户槽不联动；保存后返回拍摄页并重开菜单核对。导入异常须保留旧槽，不能仅看提示成功。
4. 用专用测试卡分别导入一个受支持的sRGB三维`.cube`和同源电脑拟合`.a7filter`到不同测试槽，记录输入SHA、报告误差和最终配方身份；损坏文件／不兼容模型须拒绝。参考模型预测误差不能标成照片实测色差。
5. 正常退出文件操作并确认访问已结束后，验证换卡以及正常关机重启后机内副本、名称和参数保持。掉电耐久性属于单独高风险测试，本清单不授权拔电测试。
6. 在固定曝光、白平衡和场景下，对原厂ST／FL2／FL3与同基底非零用户配方分别记录取景与JPG，确认选择身份、参数变化、实际像素变化和切回原厂结果；排除曝光／白平衡差异后再评估。保持普通照片模式为首轮范围，未知特殊模式不得默认已支持。
7. 最后独立测试照片标记显示及预期输出，记录有无实际叠加；仅有菜单选项不算通过。

## 异常停止与恢复边界

出现循环重启、MENU卡死、访问异常、握手不符、原厂外观异常或保存后丢失时，停止后续测试，保留当前屏幕、指示灯模式、时间、已执行步骤、完整包SHA和可获得的只读日志。升级尚未明确完成时，不根据本清单直接拔电、换卡或反复重刷；先确认是否仍在写入及现有恢复通道。固件或文件写入恢复必须另列精确目标、备份和风险并取得授权。
