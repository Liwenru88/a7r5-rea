## T01：父项缓存分支可以排除一项疑点

初始化器`AP 0x16f6550`遍历`0x502a980…0x5030590`，每项16字节，共1473项。key `0x1f2`指向创意外观描述符`0x5858b08`；所有描述符声明行数之和6073，最大单表82行。这些是当前AP元数据统计，不是界面最大容量测量。

创意外观描述符`+0x28/+0x29/+0x2a`均为1。`0x1bd9eb0`根据类别转到`0x1bd9d9c`，在`0x1bd9dec…0x1bd9e08`只追加父项。真实原指令对19、33、82行均输出同一个父项记录，前后保护区保持；父身份映射和资格谓词是夹具边界。

因此，仅扩展现有描述符行且保持类别/父项时，这个缓存分支不因增加14行而多占14个记录。上一批“必须先统计该缓存所有模式总占用”的疑点可缩小为：先保持此类别和父项不变，其他缓存及呈现器分别取证。若改变类别、新增父页面或身份注册方式，此结论不能直接沿用。

实际修改仍需要：33条表记录、真实身份注册/查找、行到20个用户槽的独立路由、所有18项参数数组保护、名称显示、调参页及全入口导航容量。原厂表最大82行不构成创意外观实际页面支持82项的证明。

## T02/T08：有原厂LUT实现，但必须先识别适用范围

当前AP中找到：

- SD库路径字符串`/PRIVATE/M4ROOT/GENERAL/LUT`和`/Private/Sony/PRO/LUT`；机内路径`/usr/data/lut`，文件格式`LUT%03d.cube`及`LUT%03d.LUT`。字符串不能替代实际SD读取入口验证。
- 文件名构造器`0x30a16b0`和`0x30a16d4`；头解析`0x30a15ac`，完整解析入口`0x30a1a80`。完整解析中的维度检查允许17或33，声明用户LUT身份可见USER1～USER16。尚未证明这些身份在本机启用，更不将其等同于32个创意外观槽。
- 完整解析入口栈预留`0x5c32b0`，即6042288字节；输入读取调用点`0x312c180`预留`0x800000`字节。这里是静态预留量，未实际运行完整解析、测量峰值或确认可直接借用该线程栈。

挂载调用为`0x30db520 → 0x30a284c → 0x3691334 → mount PLT 0x16da690`。模拟器拦截处的实际参数：

```text
source  = /dev/nflasha30
target  = /usr/data/lut
type    = vfat
flags   = 0xc0ed0480
options = posix_attr
```

启动入口通过`0x2e7b9e4(0x9c)`或`(0xa0)`的返回值决定是否尝试挂载；后续另查询`0x2e7b9d8(0x26b)`。四组门控/挂载失败场景通过，实际功能查询值尚未知。本包usr镜像没有`/data/lut`；历史挂载清单也不能证明该路径当前启用。**不据此选择、创建、格式化或挂载该设备分区。**

原厂文件写入器`0x3691384`执行open（flags `0x41`、mode `0x1e4`）、单次write、fsync、close，然后返回write结果。六组成功/短写/写入失败/同步失败/关闭失败/打开失败场景证明：同步或关闭失败不会改变返回字节数；打开失败返回0；短写不重试。

具体接入决定：不能把该函数直接接到`af_finish_save(...,1)`。未来存储适配器需独立保留各阶段状态、完成回读并证明目录/副本发布顺序。是否能借用原厂LUT解析/转换，仍需确认输入域、输出载荷格式及照片消费者；不能由视频路径字符串推定照片取景和JPG支持。

## T03：从通知结构追到真实上下文首指针

本批执行以下源指令窗口，未用Python替代复制函数：

```text
八项消息接收器 → 通知状态0x157aa10
  → getter 0x89853e
  → 0xafcb6c…0xafcb80：真实ARM memcpy 0x5f51bc，复制0xdbc字节
  → master 0x164eef0
  → 0x4baa9e…0x4baab6：同一memcpy，复制0xe70字节
  → 参数快照0x1653c68
  → 0xafd2da/0xafd5b8：构造上下文0x192b070，首指针指向上述快照
  → 0x9071cc…0x9071f6：复制0xc4字节上下文到0x157c278
  → 0x9053f8…0x905442：解引用首指针，生成派生参数
  → 0x92e688…0x92e6bc：锐度/锐度范围进入下游+0x35c/+0x35d
```

五组锐度范围1～5场景中，八项字节均完整经过快照，真实复制前后保护区保持；重新写通知状态不会直接改变已经复制的master/快照。上下文构造本身执行原代码；窗口入口寄存器、关闭日志标志、串行调度是边界条件。

关键限制：`0xafcb5c`的已定位调用者在`0x49926a`，日志上下文是`Init_DDS/Init_Command/Init_FuncParam/Init_Pmon`。本批证明的是初始化来源链，不能认作每次调参的实时更新入口。尚需定位后续master更新、外围调度锁和条件、取景/JPG各自消费、最终锐度运算、帧引用及释放；T03继续未完成。
