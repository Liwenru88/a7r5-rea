# 原厂网格控制器：选择、缓存失效与输出发布

- Feature ID: `001-fixed-custom-filters`
- Updated: `2026-10-26`
- Status: `OFFLINE_NATIVE_CONTROLLER_VERIFIED_NOT_INSTALLED`

## 确认的接入链

第十八批只执行完整打包函数。本批新增[cp_grid_route.py](../../custom-filters/a7filters/cp_grid_route.py)，从当前修改4.06的原控制器`0x230da8`入口执行到返回，保留当前六款滤镜助手、校验、缓存判断、原查询和打包指令，不拦截函数返回值、不伪造成像成功。

```text
原颜色执行入口0x719ef6
  → 0x719f16调用原网格控制器0x230da8
  → 当前4.06已有助手0xbef4c0选择六款表并核验头/FNV
  → grid_state+0x184 = 源表；+0x188/+0x189 = 格式/类型
  → 原更新判定0x231234
  → 原打包0x231654（405个u32，1620字节）
  → grid_state+0x20 = 原输出缓冲指针；+0x24 = 就绪标记
```

原查询`0x415160`在句柄为空时执行原指令返回4。现有助手对参数模式0有特例桥接，能进入打包；模式1、原索引1/2的12种六款组合仍被阻断。不能将这些索引命名为EVF/JPG，也没有证明该输入对应实际照片模式。输出区的三个1620字节段是原控制器的局部布局，不等同于本项目自建的三银行集合。

六款249～254分别通过完整控制器取得原固定表`0x11952e0 + slot×1215`，原校验通过后生成405个字，发布索引0的原缓冲指针；未选中段和前后保护区保持。相同参数再调用不重打包。另验证原profile字段6的值为1时输出位于`output_context+0x5c`，该地址紧接原缓存后；仍只称字段值，不据此判定照片/取景身份。

## 同槽替换必须显式触发更新

本批在匿名CP副本中，将第一张旧表及其FNV替换为第十八批AArch64实际拟合产物，参数、标记及缓存保持。结果：原助手能重新验证新表，但原控制器写出0个网格字，原打包结果仍旧。原更新比较包含参数和分类，没有新表摘要/版本比较；因此“校验通过＋换指针/内容”不能当作应用完成。

在同一匿名上下文，将`output_context+0x54+native_index`的原缓存标记置为与当前标记不同的值后，原判定重新打包405个字，发布的新结果与拟合产物的独立期待完全一致；再次调用又回到零重打包。这里只验证索引0的失效操作，没有向实际AP/CP安装写入器，也没有证明可从其他线程直接改此字节。

强度更新还有来源分类条件：

| 显式夹具 | 实际原指令结果 | 接入要求 |
|---|---|---|
| `grid_state+4=0xff`，无原来源 | 修改强度更新缓存值，但不自动重打包；显式使当前段失效后，按新强度生成正确字节 | 新解析器必须同步处理分类和内容代号，不能只设源地址 |
| `grid_state+4=0`，原来源分类0，仍由现有助手选择自定义表 | 强度8→7自动生成405个正确网格字 | 保留原分类、参数和原控制器更新逻辑，不能把0xff夹具行为推广为机身缺陷 |

0xff/0均为本批输入夹具，未观测机身当前分类。没有因此修改原厂强度算法或全局强制更新标志。

## 新槽具体改动清单

1. AP在用户槽被选择/调参时形成完整、稳定的“槽号＋基底＋八项参数＋表摘要/代号”快照。当前UI目录及HELLO仍未发送真实PRESET，不把握手当作应用成功。
2. CP接收完整候选并校验后，把新增表绑定到实际参数/颜色上下文，保留所选原厂基底。新增表解析优先在现有`0xbef4c0`附近的选择落点扩展，未命中新绑定时委派现有六款/原厂逻辑。不得随意借用249～254及未知编号表示全部20槽。
3. 在原控制器持有上下文的串行边界比较“表代号＋摘要”，发生改变才使对应原段失效，并保证原分类与输入一致。失效与源表发布必须是一组可回退操作；当前还未证明该串行拥有者，不安装跨线程裸写。
4. 打包、原输出指针/缓存发布及后续消费继续交给原厂函数。只追查新增源表和原输出缓冲的必要寿命；不默认替换原厂整套银行/帧管理。`grid_state+0x184`在返回后仍保留源地址，不能仅凭一次打包返回就释放或覆盖它。
5. 继续将参数/颜色上下文绑定到照片取景与JPG，查原上传`0x414f44`、缓冲复用和失败回退。当前查询为原空句柄路径，没有执行硬件上传，原就绪字节不能当作像素效果确认。

上述是有证据支撑的下一步落点，不代表新增解析器、PRESET接收、动态20槽和应用回执已经安装。ST研究模型也未取得FL2/FL3等其他基底的效果许可；仅参数基底仍沿既有原生映射。
