# 第45批：Capture 生命周期、第二 Gamma 域与完整曲线对照

本批基于现有修改版4.06，在源码、宿主行为、静态指令和交叉链接范围实施。没有操作相机、执行ARM、进行硬件模拟或改写CP／USR／DAT镜像。整体功能仍为`NOT_VERIFIED`，本页不把软件接通写成EVF／JPG照片已验收。

## 已接入的生命周期

`af_cp_capture406`为每个原生Capture保存A地址、非回绕出生代号、B覆盖代号、正常逆展开的47字节写集，以及按值tone／输入版本。原对象、图像、完整asset都不由本模块持有；A+4仍是原厂引用计数，不写成版本字段。

| 原调用点 | 包装职责 | 保留的原行为 |
|---|---|---|
| `45BC80`、`45BE6C` | 原A分配成功后登记出生 | 原`AE0316`返回和NULL行为 |
| `48D700`、`48D8B4` | 普通B重建前撤销旧资格，返回后复核发布 | 原`AEBDC2`完整调用一次 |
| `46E65A` | 序列化恢复撤销旧版本，不伪造新来源 | 原`833CB4`五个参数，包括栈上第五参数 |
| `335E56` | 正常逆格式化前后核同代shadow和47字节写集，先形成待完成记录 | 原`845CF4`完整调用一次 |
| `872682` | 每次第二Gamma调用登记同步写者，包括无资格的原厂调用 | 原`845DB8`完整外层及返回 |

相同数值不是版本来源。序列化、debug跳过真实构表、旧epoch、重入、并发、池拆除、错线程和错F／O均不能沿用私有资格。原厂无资格作用域仅回退原厂，不应永久关闭后续正常自定义调用；独立审查发现并修复了这一误关闭，新增“未知／未stamp原厂调用→两通道构表→随后有效Capture仍可用”回归。

## 第二 Gamma 的实际落点

主Gamma构造通过现有84字节source→shadow复制传递按值身份。新增snapshot同时复核实际shadow字节、构造代号及复制状态；Capture普通重建中的真实逆展开才可把该身份绑定至本次B。

第二域只在当前原`872682`同步作用域内接收同一个A／birth／Bepoch／任务／G／channel，并要求`AA7F08`构表事件完成。通道0为`F=1F6DFDC,O=1F6FF74`，通道1为`F=1F6E390,O=1F709F4`；原`G+1`为零或非零都可能进入共同核心，不能误当enable。栈上临时F／O不授资格。

组件读取本次实际`F+30`route、`F+38`column及其原576字节记录，再施加同版本三tone。原轴、metadata及附属控制保留，进入真实core后仍返回原`413DF0`外层，允许其后处理覆盖曲线；失败沿原厂分组更新／回退，不提供整配方原子回滚。原CPU同步消费结束后不保留私有记录指针，因此没有新增图像帧lease或等待JPG回调的私有释放机制。

以上证明了已识别原Capture／Gamma链的源码及CPU调用关系。原EVF端点配置、JPG提交／回调、ISP／DMA／最终像素和最后图像帧是不同证据层，仍不能由core返回或消息ACK推导完成。

## 容量与保持区

490条ARM记录每条112字节，首次bind申请54880字节普通堆工作区；最终回池复用条目，拍摄热路径不分配或free。分配失败在HELLO前关闭私有绑定。工作区只支持同次CP启动的普通堆生命期，记录heap头变化时粘性关闭；**未支持同头热重建、未知region撤映射或保留私有状态后软重启**。已知普通堆初始化、无释放的destroy链及后续热重建候选见`.local/implementation45-heap-lifecycle/README.md`。

保持既定8页RX／12页RW、原408字节启动尾部和288字节factor；新增八个常驻门复用四段共460字节的已有明确保留区。30个真实挂点与460字节入口、288字节factor组成988字节同次链接合同，启动逐字节复核。匿名内存计划共44窗口，必须精确逆转回原CP摘要。

第一次普通`-Oz`链接超限，ThinLTO既未解决容量又丢失后端内存helper。最终采用C完整LTO、内存ABI／只读合同非LTO，并保留初始化诊断字以满足原guard布局；只对重复guard helper做最小`noinline`体积优化。容量以最终同源回执为准，未扩页。所有失败目录保留。

原六款资产、FL2／FL3及原声音区保持。特别是`BEF9C8..BEF9E6`实际属于`joint_sound`，不能当作空闲区放新门；原BL、LR、616字节活动栈和公开入口由实际汇编及内存计划核对。计划构建中另修复了“合同核对后再次读可变bin”的时间差，改用已校验ELF的不可变字节。

## 完整 Gamma 的本批结果

新增`tools/compare_gamma.py`，复用真实宿主C参考模型。共享原257候选基准，冻结矩阵／CC1／网格，两臂按相同追加预算分别搜索三tone和17个可调结点展开的129点曲线；训练、选优和最终留出测试分开。最终选择冻结后各计算一次test，不根据test回头选参数。

| 样例 | 每臂追加预算 | 三tone平均／最大ΔE76 | 完整曲线平均／最大ΔE76 |
|---|---:|---:|---:|
| 恒等 | 96 | 0／0 | 0／0 |
| 暖调 | 96 | 2.421／3.804 | 2.162／3.640 |
| 明暗 | 384 | 1.789／2.132 | 2.032／2.380 |
| 局部颜色 | 384 | 1.710／4.453 | 1.710／4.453 |

这是固定ST/context4与PT经验残差模型中的18个留出样本，**不是机身照片色差**。暖调平均改善约10.7%，明暗样例相对三tone反而退步约13.5%；局部颜色虽选优改善，最终留出误差不变。收益不稳定，当前不据此扩大产品格式。

129点并非129个已验证独立自由度：原点固定、独有61440点按既有CP↔Edit表示政策重建，当前桥最多127个独立纵值且CP值受Edit可表示上限131071限制；本工具只搜索17个平滑结点。坏源、非单调、越界和独立改动61440明确拒绝。

CP的mode1与Edit模型的`secondary_gamma`不是同一对象。两CP域虽共用576字节格式，但选中的route／column、E覆盖、debug控制和外层后处理不同，不能将ST绝对曲线直接套到第二域。当前AJR2／AJR3继续保存相对三tone；本工具只输出研究JSON及曲线，不导出新`.a7filter`格式、不改变机身准入。

后续完整曲线至少需要明确“匹配原记录的绝对曲线”或“重采样至本次原曲线的单调残差”语义、逐域适用性及量化误差，再验证文件／传输／保存兼容和Capture寿命预算。若将当前40字节tone身份直接扩成含516字节曲线的552字节身份，记录约624字节，490条即305760字节，明显超出当前54880字节合同；不能只增数组。详细域分析见`.local/implementation45-second-domain/GAMMA-DOMAINS.md`。
