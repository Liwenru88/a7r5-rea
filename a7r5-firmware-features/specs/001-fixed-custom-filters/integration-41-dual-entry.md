## 文件与操作

原SD卡选择和文件浏览同时显示`.cube`与`.a7filter`，忽略扩展名大小写。`.a7filter`是现有“导出已保存滤镜”的AFD1文件，不另建同义容器或任意BIN入口。

| 输入 | 处理 | 保存 |
|---|---|---|
| sRGB照片三维CUBE | 必须有完整模型，沿现有可让出联合拟合、量化及独立预测误差报告 | 原完整用户槽事务 |
| 电脑配方或已导出预设 | 独立双读及选中摘要核对；AFD1完整解码，AJR2再核固定CP身份、内部摘要、范围、基底、模型对应与seed/tone | 跳过拟合，沿同一完整用户槽事务 |

C01～C20固定容量不变；原厂12项不提供覆盖身份。C01～C06即使没有私有overlay也要求明确二次覆盖确认。文件中的名称、initial/saved八项值、LUT与模型摘要、载荷及预测报告保持；装入后working从saved恢复。更改工作值继续沿用原八项调参和显式保存逻辑。

完整成像配方首版仅接收converter2/AJR2，因为当前真实CP消费者要求`native_mode=1`。AJR1仍能用于旧存档解码，但从新增SD入口明确拒绝。合法纯参数AFD1可回导，不要求CP载荷或模型。AJR2须由seed及三项tone重建匹配Gamma；不能把任意最终曲线改名导入，也不能把上游16扇区矩阵截断为当前18增量。

## 接线和所有权

- `af_media_kind`统一后缀；POSIX、实际Fsys提供者和原D4浏览验证共同使用，保留超长名称拒绝、64项/4096遍历、编码和双遍读取边界。
- `af_repository_service`在没有转换模型时仍提供配方导入；CUBE选择继续明确返回NOT_READY。新增驻留配方源缓冲，不借用CUBE求解器工作区。
- 管理请求仍使用纯参数选择模板和同代媒体索引；电脑文件不能把内部路径、指针或目标槽写进请求。实际名称和完整预设由已重读文件校验后产生。
- 分批任务复制选择身份和提供者，配方解码工作区及对象驻留；源文件SHA在选择、实际重读和COMMIT前核对。配方校验完成后另一次poll才进入提交，允许取消和目标快照变化拒绝。
- 两入口都使用`commit_begin → af_persist_replace → labels回读 → finish`。写前失败保持原有效版本；发布后不确定沿既有冻结／显式恢复契约，不自动重试或误报成功。
- 旧同步`af_repository_execute`明确拒绝配方，防止将其误送CUBE解析；实际原菜单的分批服务支持双入口，不新建第二套保存实现。

## 电脑端交付

[封装工具](../../custom-filters/tools/recipe_file.py)与[使用说明](../../custom-filters/tools/README.md)提供`pack/inspect`：已拟合AJR2加严格元数据JSON可生成现有`.a7filter`，原C codec执行宿主校验。输出独占创建，不覆盖输入或既有结果。它是本项目配方的封装器，没有新增电脑训练器，也不直接转换Hearts-Ace BIN。

报告`scope=1`表示文件提供者声明的模型预测，不是机内重新计算、可信作者认证或相机实测。名称／八值等外层字段沿用AFD1既有格式，没有全文件签名或校验和；AJR2载荷有摘要，媒体稳定读取另有完整SHA。调参后原报告仍只对initial适用，不能作为saved画面的精度保证。
