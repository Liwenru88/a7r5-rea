# 停止硬件模拟后的软件实施

- 基线：现有修改版4.06；不替换为原厂包或参考仓库版本。
- 边界：不操作相机、USB、SSH或实际SD，不修改输入DAT，不生成可安装固件。
- 当前总体：仍未完成全部功能。本文区分已接通的软件事务、显式后端条件和实际成像缺口。

## 资源与失败处理

服务和浏览器由同一UI拥有者串行调用。目录fd由明确的文件服务提供；转换所借用的模型context、源缓冲和工作区必须保持到完成，不探测相机路径。

本次审查修复了一个跨批生命周期问题：READ_READY不等于任务已经不再借用输入。转换活跃时，媒体的cancel、prepare、rebind均必须返回BUSY，保持旧目录、缓冲、选择代号和状态；不能在忽略服务取消的情况下允许调用者释放旧缓冲。用户取消转换通过管理任务处理，等轮询实际结束后才允许重绑。

转换完成和提交之间还会核对候选摘要，防止合法名称或其他候选字段被替换后错误保存。取消、源变化、候选变化、陈旧槽和模型错误不提交；发布后不确定沿用显式恢复契约。

首次文件双读与CUBE解析仍是有界同步操作；分批预算不是机身耗时测量。误差报告是所绑定模型内的8位sRGB／D65 ΔE76，不是本机实拍误差。

## 验证方式

统一入口：

```sh
.venv/bin/python -B a7r5-firmware-features/custom-filters/experiments/software31/verify.py \
  --output .local/fixed-custom-filters/continuation31-software
```

只构建动态／固定AP研究模块、AArch64同版glibc后端并运行相关宿主测试。不启动虚拟机、外设模型或相机。回执记录完整命令、退出码、当前源码摘要和产物摘要；已有CPU局部检查独立列为历史／定向软件证据，不转成设备验收。

本次该命令退出0，**144 passed in 18.07s**，验证期间源码未变。动态AP研究模块112024字节，固定AP研究模块152088字节，文件后端110680字节；三个产物均有SHA-256。完整回执：`.local/fixed-custom-filters/continuation31-software/verification.json`。IMPORT界面另有16项定向软件检查，明确媒体／原manager服务边界；不启动完整客体。

## 保留的关键缺口

1. **实际4.06完整颜色模型未绑定。** 参考仓库的部分算子、固定PT平色数据和三组件表不能证明本包sRGB域桥与非零网格的完整组合。联合搜索与完整文件保存已经有软件实现，默认转换仍不能用合成模型替代。
2. **UI发送尚未启用。** 已有AP→CP输入准备接口，但从用户槽切回同一原厂外观时，原通知是否完整恢复基底和八项参数尚未证明。只恢复FL3基底可能残留用户调参，因此不把接口直接绑定到拍摄选择事件。
3. **完整LUT到原消费者、取景／JPG和最后帧引用尚未接通。** 输入prepare、消息接受和保存成功都不是成像成功，不能将其归结为只差拍照片验收。
4. **真实机内持久化位置和旧六槽迁移仍未完成。** 显式普通目录副本／重开恢复不是相机掉电、换卡和存储容量证明；旧六槽继续原委派，避免丢失现有设置和既有联合增量。

硬件模拟已经停止，不再把WDT／整机引导模型作为继续实现的前提。上述缺口保留在原M1～M4任务中，不用新增测试数量代替总目标完成。
