68组收尾均由原缓存取出/强制释放、数据库卸载及字符串析构完成：1564块所属分配均有释放记录，文件描述符、映射和存活分配为0，保护区保持。这里是命名资源的受控引用/回收，不是字体/图像共享、并发线程、缓存压力或实际Qt页面生命周期验收。

### MAP_FAILED问题与五指令保护

[原失败复现](../../../.local/fixed-custom-filters/resource-mmap-11-red.json)注入POSIX `mmap=-1`，未修改原返回值，原库在0x122a84读取无效地址。该结果来自隔离VM，不是相机事件。原0x118468只判断是否非空，未拒绝−1；没有把主机后端−1改成0冒充恢复成功。

新增`resource_guard.py`和`native/af_resource_guard.S`，只在匿名库副本把0x118468的4字节分支改到0x300000的20字节跳板：0或−1跳回0x11846c原关闭/释放/失败路径，其他值继续0x118484。原库摘要、分支前像及跳板与原段不重叠先核验；正常场景272次真实进入跳板，结束精确恢复原4字节并撤销跳板页。汇编器产物与运行字节一致，目标架构的0、−1和正常指针路由通过。

7类故障分别记录：open失败、stat失败、UXA错误魔数、UXC错误魔数由原路径拒绝并回收；未保护的MAP_FAILED保留无效读取证据；匿名保护后的数据库/UXC MAP_FAILED均返回失败并清空文件、映射和所属分配。原库本身未修复，研究保护也未装入真实AP加载器；0x300000仅为隔离地址，不能推断机身空闲位置、重定位/页权限或线程安全。
