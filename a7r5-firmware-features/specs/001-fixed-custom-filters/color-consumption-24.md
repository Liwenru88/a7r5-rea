# 原矩阵完整消费、动态校准和身份约束

- Feature ID: `001-fixed-custom-filters`
- Updated: `2026-10-26`
- Status: `OFFLINE_NATIVE_COLOR_CONSUMPTION_VERIFIED_FULL_PIPELINE_PENDING`

本批落实T08b2d3的限定范围。代码位于`custom-filters/native/af_color406.*`和`a7filters/cp_color_consumption406.py`，通过既有`--joint-adapter`接入同包审计。全部原指令只运行于已核验4.06 CP的匿名内存，未接相机或真实存储。

## 动态CC1校准

原修正器`0x71e74e(output, root)`的门控与来源如下：

| 条件 | 原行为 | 本批证据 |
|---|---|---|
| 全局`0x16afd14+0xc`的bit3置位 | 完整返回，但不写16字节输出 | 保护区和原输出保持；完整主/第二域由调用者清零修正缓冲，不能把修正器不写说成写零 |
| 未禁用且`[root]+0x1e0 == 1` | 经`0x73e654`读取`[root+8]`；从动态对象`+0x1a..21`取8字节 | 前4项有符号、后4项无符号；覆盖−128、−1、0、127、128、255 |
| 未禁用且状态不是1 | 全局`0x195effc+0x34..37`为前4项，`+0x30..33`为后4项 | 状态0和2均回退；未选动态指针设为不可读哨兵并完整运行 |

新增`af_color406_adjust`只解释**已经按原门控选定**的规范8字节，不猜测实际校准对象或替代门控。非法/重叠指针不发布输出。

同包联验包含6组原修正器门控、24组完整主域构造及24次完整第二域构造。FL2/FL3的主域包含在内；其原不支持的第二域没有被开放。动态字节和回退字节仍为显式夹具，未取得相机实际校准值。

## 16扇区完整矩阵消费

从原`0x71d37c(root, pipeline)`入口执行到返回，不替换其原构造、插值或输出助手。实际调用包含原`0x234344`属性准备、`0x12c5e0`数值处理、`0x71e41e`三端点构造、逐扇区输出`0x71ecf2`，最终回写首扇区到原状态`+0xc2..d3`。这是完整**参数消费者**，不是ISP像素处理。

本批显式关闭时间平滑和附加矩阵变换，使用合成单调色相轴/普通运行属性。内嵌profile54～57的系数来自当前CP，其余系数来自合成运行属性。未使用未知全局值伪装真实标定。

原五个Q8字段位于`[root+4]+0x76..7e`，顺序为主路径端点1、次路径端点0、次路径端点2、次路径端点1、最终混合。新`af_color406_matrix_blend`接口收紧为4项：主路径端点1、次路径端点1、次路径端点2、最终混合；次路径端点0由256减去另两项。每项0～256，次路径两项和不超过256。

对三端点的同一个系数`a,b,c`：

```text
R(v) = sign(v) × floor((abs(v)+128)/256)
S(v) = min(32767, max(-32768, v))
main = S(a + R((b-a) × main_weight))
secondary = S(a + R((b-a) × secondary1 + (c-a) × secondary2))
output = S(R(main × (256-mix) + secondary × mix))
```

**先舍入差分、再加基值**不能改成直接舍入加权和。以−1→0、权重128为例，前者为0，后者为−1。它也不同于上一批CC1的第一层向下截位/低半字存储，两者必须使用各自算子。

72组原完整消费覆盖9个常规数值profile、端点/内部/边界权重、六个旧标记249～254的允许/抑制门控，以及大幅半字系数。每组核对16×9项，共1152个扇区；独立整数期待、新AArch64和原ARM结果一致。逐次检查源属性/校准保持、首扇区状态副本、双侧保护区及原函数允许写区。

本批没有覆盖特殊profile16/17/36/37、单色53、时间平滑、附加矩阵变换或硬件上传；不能按72组的通过范围开放这些路径。

## 原包装器与双身份约束

原包装器`0x719ef6`的顺序为：

```text
0x232fe0 选择外观
0x231eb8 CC1消费
0x71d37c 矩阵消费
0x230da8 网格控制器
0x71a05e 后续处理
0x71f674 后续标志处理
```

选择器为`[pipeline+8]+1`写颜色profile，而矩阵消费者从`[root+4]+0x25`读profile。选择器还更新`[pipeline+0xc]+0x24/+0x25`缓存和状态`+0x3d1/+0x3d2`；**缓存的+0x25不是矩阵校准对象的+0x25**。

ST、FL2、FL3三组执行原包装器的“选择→CC1→矩阵”前缀，在网格入口`0x230da8`前停止，保留`STOPPED_BEFORE_BOUNDARY`状态。显式将上游矩阵身份置ST时：

| 选择值 | 颜色profile | 矩阵校准profile | 与独立一致身份上下文的矩阵 |
|---|---|---|---|
| ST 0 | 0 | 0 | 相同 |
| FL2 19 | 54 | 0 | 不同 |
| FL3 20 | 55 | 0 | 不同 |

这证明**只接选择器不足以完成新增槽的整组应用**，不证明相机原厂FL2/FL3有缺陷：这里故意省略了原厂上游状态生产器。独立一致身份上下文仅作对照，不当作已找到原厂同步入口。

一次整包装器探测在网格`0x230de6`停止：`[pipeline+0x10]`为未提供的空对象，原代码尝试写其`+0xb`。保留[失败边界](../../../.local/fixed-custom-filters/wrapper-24-boundary.json)，没有为此映射零页或伪造返回。最终联验明确停在网格前，不把前缀通过当作整包装器成功。

下一段实际接入必须先补齐：上游`[root+4]+0x25`生产器与其余基底/权重字段、`pipeline+0x10`的原对象来源、原网格查询/缓存和寿命。然后在同一个原上下文内验证四组件及八项参数一致更新，并绑定EVF/JPG身份；不能只将两个profile字段裸写成相同值后宣称闭环。
