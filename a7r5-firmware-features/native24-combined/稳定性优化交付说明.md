## 已实现的闭环

| 范围 | 本轮行为 |
|---|---|
| 发送与回退 | SELECT可能已生效而ACK丢失时也尝试回退；区分目标失败已恢复和需要恢复。未知状态锁定调参及新自定义目标，允许通过原厂目标受控同步 |
| 保存与重启 | 新R5SEL6仍为24字节，绑定配方库身份；读取旧R5SEL4／5。改变选择前同步恢复日志，提交后清理；发布不确定和回退保存失败可见，重启优先处理有效恢复记录 |
| 启动恢复 | 30次与60秒总体窗口共同限制自动恢复，耗尽后明确终态；启动事务持有提交权，UI只保留最后意图，不覆盖已接收输入；新epoch不服务旧alias |
| 原E4对象 | 超时不再等同于原生队列取消。原对象返回前不排入新的私有E4；只有精确对象完成才释放在途记录，错误／迟到对象不能完成新事务 |
| 导入 | 合法短读可完整读取24槽；0字节无效且不清空；相同有效库跳过重写；旧坏库仍允许有效SD修复；槽1优先等待最多2秒，再有限回退槽2 |
| 库变更 | 库未改变保留原选择，库身份改变不把旧编号解释为新配方；解除覆盖后由UI所有者委派原厂ST。用户随后明确选择的原厂外观优先 |
| 资源失败 | 发布新库前保存旧有效库；新CP库不足时尝试恢复旧库及其选择。原厂网格诊断资源错误阻止报告成功；首次堆分配返回NULL可由有限探测重试恢复 |
| 栈与旧页面 | 共用工作线程暂存，去掉两个约64KiB局部缓冲。已取消的旧私有页面只保留原厂构造委派，回收对象池及同步等待代码 |
| 诊断和构建 | 诊断使用有界RAM环，正常链路不写SD日志。容量／协议合同集中生成，替换次数与连续来源账本检查，构建期间源码变化拒绝出最终收据 |
| 交付门禁 | 完整相关回归与源码／组件摘要绑定；QEMU实际驱动与清单绑定；原帧重新生成PNG比较；研究归档按SHA清单重新读取核对 |

保持统一创意外观入口、缺槽隐藏、不重排编号、原厂ST／FL2／FL3及本地四项、单笔在途与最后目标合并。没有增加热导入菜单或独立关闭项。0字节不再清空，明确有效的空配置头仍可表达清空。

“需要恢复”表示当前整体状态未被确认，菜单中的旧编号只代表最后已提交结果。原E4仍在途时，新的同步也必须等待它释放，不能通过写成功位、反复排队或只把AP编号改成0解除错误。

## 构建与复验

在仓库根目录使用已有`.venv`。输出目录必须不存在；可用`--inputs`直接提供两个已锁定基底，避免依赖某次完整旧构建目录：

```sh
.venv/bin/python a7r5-firmware-features/native24-combined/build.py \
  --output .local/native24-stable-new \
  --inputs .local/native12-combined-baseline-01/work/inputs

A7R5_NATIVE24_BUILD="$PWD/.local/native24-stable-new" \
A7R5_NATIVE24_EVIDENCE="$PWD/.local/native24-stable-new/cpu" \
.venv/bin/python -m pytest -q a7r5-firmware-features/native24-combined/tests \
  --junitxml=.local/native24-stable-new/regression.xml
```

测试应明确设置`A7R5_NATIVE24_BUILD`；默认旧路径保留给历史基线研究。新候选QEMU必须重新核对固定组件身份，不能改清单来接受未知输入。归档核对PNG需要Pillow，应在`a7r5-qemu`目录使用其已有`.venv`执行`../a7r5-firmware-features/native24-combined/archive.py`；本轮没有安装依赖。

研究组件包SHA256：`cf8dc76ab9d2c3e247efb3f3b7492f61460afcc052b982bbe4800c77dac38b12`。包内988个文件有摘要清单，另含`SHA256SUMS`；压缩包已重新读取校验。包不含私钥或DAT，组件目录没有把合成测试BIN作为成品配方提供。
