# 自定义滤镜八项相对偏移

当前源码将自定义滤镜的八项显示值改为相对原生基准的偏移。新配方初始全为 0，确认重置后八项也全为 0。偏移仍按配方色彩身份独立保存，原厂外观继续显示和调整其原厂绝对参数。

调参实现阶段只构建离线组件并执行 CPU 回放，其冻结证据仍保留。本次已进一步[封装为 4.17 更新包](releases/4.17/README.md)，[当前候选](current-candidate.json)标识相对偏移 AP；44 项封装测试、736841 帧、独立解包和 OpenSSL 验签通过。31 项 CPU 证据按相同源码与组件身份复用，全程未连接相机。

## 显示、应用和重置

每次原生 E4 生成属性消息时，先读取消息中的原生值，再加上本次事务冻结的配方偏移，最后限制在对应原厂范围。这里的原生值来自上游原本读取的原厂工作状态，不是一组写死的 ST 默认数值。来源核对见[上游参数核对](上游八项参数核对.md)。

例如原生锐度为 4，自定义页显示 0 时实际发送 4；显示 -1 时发送 3；重置为 0 时恢复发送 4。如果下次原生锐度变成 6，保留的 -1 偏移会发送 5。没有修改配方 BIN，也没有把八个显示零当作八个原生零发送。

| 参数 | 自定义偏移范围 | 原生实际值范围 |
|---|---|---|
| 对比度、高光、阴影、饱和度 | -18～18 | -9～9 |
| 褪色、锐度、清晰度 | -9～9 | 0～9 |
| 精细度／锐度范围 | -4～4 | 1～5 |

偏移范围取原生范围的最大跨度，以支持旧绝对值记录转换，并能从任意合法基准到达整个原生范围。超出实际值边界时限幅，界面和保存记录保留用户设定的偏移。例如原生精细度为 4、偏移为 +4 时实际发送 5，偏移仍显示 +4。原生基准变化后仍使用这份偏移。

归零使八项原消息数值和其余字节保持上游输出。原生 E4 的构造器、参数 getter、九次发送以及 CP 配方与色彩代码沿用原实现。归零保留上游参数逻辑；本轮没有验证实机 EVF／JPG 像素。

## 身份保存和旧记录兼容

- 身份仍是 CC1、矩阵、Gamma、网格规范内容的 SHA-256。相同色彩配方改名、换槽或重新导入保留偏移；不同配方从全 0 开始；同配方多槽共享微调。
- `R5TUNE.BIN` 使用 `R5TUNE2`、版本 2。头部仍为 64 字节，每身份记录仍为 48 字节：身份 32 字节、最近一次原生基准 8 字节、已保存偏移 8 字节。最多 128 个身份。
- 兼容读取版本 1：旧保存绝对值减去旧初始值，得到偏移。例如旧初始锐度 4、已保存 6，转换为 +2。读取本身不改原文件，后续成功事务才原子发布版本 2。
- 版本、长度、CRC、各参数范围和重复身份校验保持。微调日志接受版本 1／2，与选择恢复日志逐字节绑定。损坏文件保留，不静默重置。
- 应用和保存成功后提交，失败时回退已确认状态；在途事务冻结偏移，事务中收到的新编辑保留到下一次应用。原生基准采集不覆盖新的偏移输入。

旧固件不能读取版本 2。需要降级时，应在升级前单独备份旧 `R5TUNE.BIN`，或在降级方案中处理新版微调文件；不能承诺新版偏移记录被旧固件直接识别。本轮没有读取或迁移实体机文件。

## 实现位置

- [r5_tune425.c](runtime/r5_tune425.c)：偏移校验、限幅、冻结、原生值采集、身份持久化、v1 兼容和恢复日志。
- [unified-look.c](runtime/unified-look.c)：八项偏移显示、直接赋值、步进和归零；自定义专用的带符号范围表，原厂继续使用原表。
- [build.py](build.py)：校验三个表指针读取点的原指令，再分别接入数值范围、活动数值格式和控件显示路径；中间调用保持易失寄存器和条件码。
- [相对偏移回归](tests/test_relative_parameters.py)：24 槽全零、原生数值更新体、正负边界、直接赋值和步进、基准变化、限幅、归零、旧文件转换、重启、失败发布和并发编辑。
- [既有调参回归](tests/test_parameters.py)、[真实 E4 回归](tests/test_native_e4_parameters.py)：身份重新导入、CP 字段消费、保存及中断恢复、九条消息和回执代次。

## 离线复现

本轮 31 项相关回归全部通过，测试期间源码摘要不变。零偏移的上游 48 次 E4／432 条消息逐字节一致。两次独立构建的四组件一致，CP、两份图标和正式十二款配方保持原字节。当前 AP SHA-256 为 `eaf0b742745696f651dbe5ee75a813bb168ac41db81706743712ab8f6d0491bf`。实际工作目录为 `.local/native24-relative-20261105-192203/`。

从仓库根目录按[实施手册](实施与复现手册.md)生成 `baseline`。输出目录必须是新目录。以下命令不访问相机。

```sh
feature="$PWD/a7r5-firmware-features/native24-combined"
out="$PWD/.local/native24-relative-new"

.venv/bin/python -B "$feature/build.py" \
  --baseline "$out/baseline" --output "$out/runtime"
.venv/bin/python -B "$feature/build.py" \
  --baseline "$out/baseline" --output "$out/rebuild"

for file in appFw.so cpapp-b.bin image_00_23_IPSX.uxc image_00_32_IPSX.uxc; do
  cmp "$out/runtime/$file" "$out/rebuild/$file"
done

tests="$feature/tests"
A7R5_NATIVE24_BUILD="$out/runtime" A7R5_NATIVE24_EVIDENCE="$out/runtime/regression" \
  .venv/bin/python -B -m pytest -q -p no:cacheprovider \
  --junitxml="$out/runtime/regression.xml" \
  "$tests/test_relative_parameters.py" "$tests/test_native_e4_parameters.py" \
  "$tests/test_parameters.py" \
  "$tests/test_tabs.py::test_left_restores_each_groups_last_applied_row" \
  "$tests/test_tabs.py::test_parameter_center_is_forwarded_through_native_parameter_entry" \
  "$tests/test_preview_idle.py" "$tests/test_ui_sync.py"

.venv/bin/python -B "$feature/audits/upstream-parameters/probe.py" \
  --baseline "$out/baseline" --candidate "$out/runtime" \
  --output "$out/parity-proof.json"
```

探针保留上轮冻结源码，重新执行上游原生构造、getter、执行器和打包，再把真实对象送入本轮候选。四种工作状态分别遍历十二款，比较 48 次 E4 的 432 条消息和 CP 参数字段。它也核对正式十二款配方与容量夹具前十二条记录相同。

结果、组件身份和回执见[本轮验证摘要](audits/relative-parameters/verification.json)及[证据清单](audits/relative-parameters/SHA256SUMS)。本轮执行真实 AP／CP 机器码；文件、时钟、调度、对象和 UI 服务由明确夹具提供。原生数值更新测试检查控件字段，不代表重新运行了 QEMU／Qt 像素渲染。实体机启动、介质耐久性、LCD／EVF 和 JPG 效果尚未在本轮验收。
