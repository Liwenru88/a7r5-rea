# 自定义滤镜八项调参

当前实现属于012离线研究候选，整体状态仍为`NOT_VERIFIED`。功能已接入，70项相关CPU回归、2项QEMU固定身份检查、106次真实Qt操作及106原帧／PNG核对均通过。未连接相机，不生成新DAT。

## 使用行为

在原创意外观中选择附加滤镜，按右键进入原调参页。八项依次为对比度、高光、阴影、褪色、饱和度、锐度、精细度、清晰度；沿用原左右切项、上下调节、确认和重置弹窗。基底外观不开放修改，避免破坏所选配方。原有外观仍沿原厂读写路径。

| 项目 | 保存和恢复规则 |
|---|---|
| 微调身份 | 对CC1、矩阵、Gamma和网格的规范色彩内容计算SHA256；名称、槽号、填充不参与 |
| 相同配方重新导入 | 保留保存过的微调；改名、换槽也保留 |
| 不同配方占用旧槽 | 不继承旧槽的值，建立自己的初始状态 |
| 同一配方出现在多槽 | 色彩身份相同，共享同一组微调 |
| 重置 | 原确认框确认后恢复当前身份的初始八项，其他身份和原厂外观不改 |
| 冷启动／无卡 | 读取机内的微调记录；配方仍沿既有冷启动导入规则 |
| 连续编辑 | 当前事务捕获固定快照，后续输入合并为最后工作值 |
| 应用或保存失败 | 不提交未确认结果，后台回退旧选择和旧已提交参数 |

现有`R5NATIVE.BIN`只有色彩配方，没有八项默认标量。因此新身份使用原厂ST模型的**默认字段**建立独立初始值，不继承ST工作值；当前照片模式实际基准为`0 / 0 / 0 / 0 / 0 / 4 / 3 / 1`。这里没有声称BIN携带每款不同的八项默认值，BIN不改格式、不重新编码。

微调独立存于机内`R5TUNE.BIN`，带版本、长度、CRC、范围和重复身份校验，最多128个身份。满时拒绝新身份，不自动淘汰。损坏文件原样保留，禁用微调而不静默清空。`R5TREC.BIN`与原选择恢复日志绑定，覆盖微调发布与选择发布之间的中断窗口。文件操作只在原工作线程与已验证目录中进行。

## 实现位置

- `runtime/r5_tune425.c/.h`：身份、初始／工作／保存值、文件校验、日志与固定快照。
- `runtime/unified-look.c`：原八项界面、赋值／步进／重置、焦点及原厂隔离、原消息发送叠加。
- `runtime/r5_filter_runtime423.c`：保存提交点、应用确认、最后目标及失败回退。
- `runtime/r5_stage413_thread.c`、`runtime/r5_stable_io425.c/.h`：启动及独立文件接线。
- `build.py`、`stability.py`、`layout.json`：严格派生和AP私有段容量；CP和两图形资源保持011。
- `tests/test_parameters.py`：身份重导入、原CP消费、重启、并发快照、损坏、发布失败、中断恢复、默认隔离与重置回归。
- 独立QEMU实验：`../../a7r5-qemu/experiments/native24-parameters-menu/`。

AP新增代码及原PLT副本超过旧64KiB限额，构建门禁先拒绝了首次候选。本轮明确扩为128KiB，私有RW从`0x8ea0000`移至`0x8eb0000`，检查段重叠、权限、代码和BSS预算。原六个加载段保持布局，未删除大小断言。最终AP BSS为290520字节，CP代码7544字节、共享堆请求947000字节；真实堆余量和线程高水位未测量。

## 复现入口

在仓库根目录使用已有环境：

```sh
A7R5_NATIVE24_BUILD="$PWD/.local/native24-parameters-20261103-07" \
A7R5_NATIVE24_EVIDENCE="$PWD/.local/native24-parameters-check" \
.venv/bin/python -m pytest -q a7r5-firmware-features/native24-combined/tests \
  --junitxml=.local/native24-parameters-check.xml
```

QEMU需在`a7r5-qemu`目录使用其已有`.venv`，参见[实验说明](../../a7r5-qemu/experiments/native24-parameters-menu/README.md)。上游、旧十二槽工程、010／011封存及旧4.10／4.11 DAT保持。新候选不能仅将AP拆出替换或视为可安装固件。
