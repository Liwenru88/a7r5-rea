# 后续升级包的接入说明

当前交付是“明确前像的运行时解锁方案＋完整 QEMU 证据”。它为后续升级候选提供输入和增量范围，尚未实现文件级 AP 补丁器或升级包构建器。

## 固定输入与继承关系

当前 DAT 为研究 4.06，754525608 字节，SHA-256 为 `3cb87fd41de7bf6693375bac66d780556d87e1f73270cadb1a8f02eb8c0f24c2`；其中 AP 为 97368304 字节，SHA-256 为 `d15933ceb5ff9ad0b4f789cbabd6ff0a51526472dd35c90db97196dd227820e9`。版本信息来自已验签研究包头，不把它等同于官方未修改发布包。

现有 `materials/reproduce.py --feature all` 是从原厂 4.00 重建既有四项功能的配方，目标 AP 恰为这里的 d159… 前像。照片标记是该前像之后的独立增量，不应重放旧补丁，也不应覆盖其他会话正在研究的自定义滤镜实现。若输入已经包含其他新增功能，应另做地址、重定位和增量冲突审计，当前检查器会拒绝它。

## 固件候选应包含的功能改动

1. 在原厂参数注册/菜单能力初始化之前完成三个属性登记和 28 个支持位的修改。
2. APID 0x645、0x646、0x647 使用原厂范围校验器 `+0x29051dc`；常量范围分别为 `[0,1,1]`、`[0,5,1]`、`[0,15,1]`。常量存储必须贯穿 AP 生命周期，不能指向临时栈或 QEMU 观察库地址。
3. 只开启机型列 16 的三个描述符、24 个选项和 MID 0x194。MID 0x195/0x196 原本已开启，不扩大修改。
4. 保留原厂菜单 setter、有效值计算、动态互斥、默认初始化、刷新和备份逻辑。不得用清零互斥计数或强写可见字段来替代接入。

具体地址、文件偏移、前像、原厂引用指纹与重定位记录均在 `patch-plan.json`。其中支持位是 u16，小端 `0000→0100`；地址不是十进制字符串，也不能将 VA 当成通用文件偏移。

## 运行时指针不能直接写入 ELF

当前 QEMU 方案在装载后的 RAM 写入 `base+0x29051dc` 和观察模块内的常量地址。未来构建器不能把这些绝对地址直接抄入 `appFw.so`。

本包重新读取实际 ELF，记录三处登记函数指针对应的 `R_AARCH64_RELATIVE` 重定位及 addend；参数指针原为 NULL。修改文件中的指针值却不处理重定位，可能被动态装载器覆盖。为范围常量新增文件存储后，其指针也需要正确的装载时重定位，或者在一个经过验证的原生初始化入口中赋值。

因此，仍需完成：常量/模块的文件布局、既有初始化入口的接入、重定位处理和 AP 文件增量白名单。当前清单明确标记 `file_patch_ready=false`，这些未定布局不能用猜测地址补齐。

## 以下内容只属于 QEMU，不能打入机身功能补丁

- 蓝牙初始化包装、USB/Hotplug 的 IMDB QEMU 目标位排除。
- 软件 GPE、AP 画面导出、CP 服务子集、无硬件的 MENU 重入适配。
- 时区种子工具、型号/版本 FAT 夹具、首次设置请求文件、Qt 注入按键和模拟器启动脚本。
- `A7R5_ASPECT406_GUIDE_DRAW` 的透明观察包装及其他调试日志挂钩。

`aspect-guide406.inc` 同时含功能数据改动和 QEMU 观察部分。后续提取功能模块时只继承经过核对的数据改动和输入检查，不能将整个观察 `.so` 改名后当作相机模块。

## 后续构建与验证顺序

| 阶段 | 具体产出与检查 |
| --- | --- |
| 输入审计 | 固定 DAT/AP 摘要、检查既有四项功能及更新包身份；原始输入保持只读 |
| AP 增量实现 | 选定持久的常量/模块布局与启动入口；处理重定位；输出普通工作副本和逐段 diff |
| 离线复核 | 每个支持位及登记前像匹配；增量白名单外字节不变；加载后指针和常量有效；已有功能不被覆盖 |
| 候选界面复核 | 原厂菜单选择与刷新；照片标记绘制结果单独记录；保留当前未通过证据作为对照 |
| 升级包构建 | 使用当前工程 DAT 工具更新内部文件清单、长度/校验并执行重打包和验签；输出新文件，不覆盖源 DAT |
| 设备测试准备 | 明确候选与原始包摘要、安装路径、恢复材料及停止条件，再执行具体实机测试 |

本轮未选择或执行任何相机写入命令。后续具体候选应与真实机身型号/版本核对，并单独记录安装、显示、拍照和恢复结果。

## 建议的实机观察项目

这是一份待执行清单，不是通过记录：

1. 菜单出现且六种比例能选择；原照片比例、文件尺寸及其他功能保持。
2. 在照片 M 模式、3:2 画幅下开启 2.35:1；分别观察 LCD/EVF、MENU 往返和透明度调整。
3. 比例 1:1 与 2.35:1 往返；开启/关闭往返；确认标记只用于构图，是否影响保存文件应以实际照片核对。
4. 验证 16:9、模式切换、像素位移和间隔拍摄等动态限制；不绕过原厂禁止状态。
5. 核对正常关机后的设置保留、复位默认值以及返回原包后的行为。

QEMU 中照片页未显示标记的原因仍未定位。若实机显示成功，可将模拟器缺口与真机结果分开记录；若同样未显示，应继续追照片控制器的组件创建、快照绑定、`+0x240dae0` 转换和 `+0x182e138` 绘制，不把“菜单已开启”写成显示功能完成。
