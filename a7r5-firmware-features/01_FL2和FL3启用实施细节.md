# 01 A7R5启用FL2／FL3与内嵌参数：实施细节

日期：2026-10-23。适用：原厂A7R5／ILCE-7RM5 4.00精确前像，复现当前研究4.06。**离线选择链和参数窗口已验证；本候选实机成片、完整启动及恢复仍未验收。**

## 要解决的问题

“菜单显示FL2／FL3”“发送FL2／FL3”“使用对应CC1／矩阵／Gamma”是三个环节。旧4.05虽然有菜单和内嵌参数，但本机对应保存基底仍为0，因此选择后发送ST；用户提供的JPEG和ARW均记录Standard。单独添加菜单，或单独内嵌矩阵，都不足以解决这个问题。

当前实现分三层：AP开放菜单并按固定身份发送编号；CP选择正确档位并读内嵌参数；包内同步校验、版本与加载辅助。**不再需要另外覆盖个人Backup或写矩阵设置。**

## 1. 固件位置、前像与地址规则

| 对象 | 位置／完整SHA-256 |
|---|---|
| 原厂AP | 解包`components/usr/lib/appFw.so`；`41bd8f4cda1f44c7038912837737e1ce6a650065f2108061ada30e5c7f9ce7c7` |
| 原厂CP | 解包`components/cpapp-b.bin`；`3269bf62426339791fcfbe8529698cd4accbe6c3d2ea61cd7c368a90ab7ee7c8` |
| 机身挂载路径 | `/usr/lib/appFw.so`和`/cp/cpapp-b.bin` |
| DAT分区成员 | AP为`0700_part_image/dev/nflasha15`；CP为`0700_part_image/dev/nflasha8` |

以下AP位置为当前RX范围中的文件偏移。CP同时给出文件偏移和该加载窗口的VA，使用`VA=文件偏移+0x108000`；BSS、暂存窗口和设备物理地址不可一律套用这个关系。AP是AArch64，CP相关窗口是ARMv7／Thumb；不可混用汇编模式、PC相对分支编码或字节序。

## 2. AP：开放支持与修复实际选择

### 2.1 原厂支持门槛

| 文件偏移 | 修改内容 |
|---|---|
| `0x3f4a5c4`、`0x3f4a644` | 两个原生菜单项的20个u16产品标记；保留原来前4项为1，将其后16项由0放开为1 |
| `0x4a249ba`、`0x4a249bb` | 基础外观允许表中的10／11由0改为1；同一表覆盖相关current／still／movie校验 |
| `0x4a25b99`、`0x4a25b9a` | 主选择允许表中的17／18由0改为1 |

这些位置来自本机4.00前像及其属性引用，不套用A7C2地址。原始移植实现见[source中的build_r5_m4strict_ap.py](materials/source/analysis/fl23-candidates-20261021/reference/tools/build_r5_m4strict_ap.py)。

### 2.2 最关键的选择修复

转换函数位于`0x3550354..0x35503d8`，输入`w0=主选择`、`w1=基础外观`、`x2=编号输出地址`。当前逻辑等价于：

```text
main16：保留原特殊值0xff
main17：发送19（FL2）
main18：发送20（FL3）
main10..15：发送249..254（六个固定自定义滤镜）
其他：按原基础外观表转换；非法基底仍进入原诊断路径
```

原生基础类型顺序的转换表为：`[0,3,2,1,16,15,17,18,5,13,19,20]`。编号19／20不是54／55：前者是AP→CP颜色编号，后者是CP内部参数profile。

此函数被两处原厂路径调用：全量参数打包器`0x35598e0`，局部通知函数`0x35614b4`中的调用点`0x35614fc`。回归需覆盖两处，不能只直接调用转换器。局部通知包含属性`0x402f`；隔离测试只记录原函数生成的消息，不代表真实IPC已发生。

最终实现见[ap_patch.py](materials/source/analysis/ap-look-selfcontained-20261022-01/ap_patch.py)。它严格接受旧4.05 AP摘要`b051590a61cf6fac9f0026601ca431405d9278d6ed3c814cf34f99164b0f3d3a`；**不得直接拿该函数处理原厂AP**。统一复现脚本已把完整原厂→最终修改合成受校验配方。

### 2.3 初始化／重置默认表

`0x4a422f8`起有54条`<u32属性ID,u32默认值>`，每条8字节，分三组，每组18条：current起API163A、still起164C、movie起165E。

- 每组索引10～15：六个自定义槽默认基础类型0。
- 每组索引16／17：FL2／FL3默认基础类型10／11。
- **默认表索引16／17对应主选择17／18**，中间特殊主选择16不作为普通默认槽，不能直接按主选择值索引。
- 其他默认值和属性ID不改；总共21个默认值真正变化。

本机旧设置中的对应字段为：

| 状态 | FL2保存属性 | FL3保存属性 | 本次旧值 | 新默认目标 |
|---|---|---|---|---|
| current | `02CF0B69` | `02CF0B6F` | 都是00 | 0A／0B |
| still | `02CF0B93` | `02CF0B95` | 都是00 | 0A／0B |
| movie | `02CF0B97` | `02CF0B99` | 都是00 | 0A／0B |

修改的是AP默认表和运行期解释，不是启动时替换这些保存字段。旧Backup仍可能保留00，但固定选择已经不受它影响。完整原厂初始化路径尚未执行验证，不能用静态表变化声称机身复位已通过。

## 3. CP：档位、CC1、矩阵、Gamma与名称

### 3.1 选择档位

| AP编号 | 场景 | CP profile（十进制／十六进制） | 供体bank |
|---:|---|---|---:|
| 19 | FL2照片 | 54／36 | 22 |
| 20 | FL3照片 | 55／37 | 24 |
| 19 | FL2视频 | 56／38 | 23 |
| 20 | FL3视频 | 57／39 | 25 |

原始选择分支文件偏移为`0x12b8ca`、`0x12b8fa`、`0x12be0e`、`0x12be3e`。它们保留本机FL的共有准备与尾部逻辑，修正新增档位和合法范围。不要仅改profile常量，忽略堆栈参数和现场寄存器。

### 3.2 CC1

主CC1函数VA`0x71e670`（文件`0x616670`）为54～57使用内嵌四行有效系数，不要求机身设置区另行提供bank22～25。每行有效48字节，即三组各8个int16；源供体绝对三组A／B／C转换为本机差分表达`A、B−A、C−A`，保留原运算与调节逻辑。

关键范围合法性在文件`0x61668c..0x616690`；系数派发在`0x6166bc`附近。旧53特殊路径保留。备用读取函数不是主函数的同义替换，部分54～57输入仍沿原拒绝边界；不能盲目放开所有上限就宣称完整链路已打通。

### 3.3 内嵌矩阵

主矩阵函数VA`0x71e41e`（文件`0x61641e`），新增档位分流钩子在VA`0x71e43e`。最终使用VA`0x1a3a000`的2304字节表，排列为四档×16子槽×3端点×6个16位系数。

历史设置增量为3076字节：4字节映射及4个768字节bank；其中保留区域并非有效系数。内嵌时只重排有效2304字节，按bank22、24、23、25对应profile54、55、56、57，不能把3076字节原样拷到2304字节目标。

六系数a～f由原厂函数结合本机校准C0／C1／C2展开：

```text
[ C0+a+b, -a,       -b       ]
[ -c,       C1+c+d, -d       ]
[ -e,       -f,       C2+e+f ]
```

保留16个子槽、原有端点选择及校准输入。矩阵所在的实际像素颜色空间尚未在硬件证明，不把参考渲染中的线性sRGB假设当成机身事实。

### 3.4 Gamma与元数据

移植曲线记录必须是本机576字节结构。参考FX2有580字节，需去除其`+0x238`额外u32，保留后续flag／enum，而不是把572字节随便补零。原始转换及指针清单见[build_r5_m4strict_gamma.py](materials/source/analysis/fl23-candidates-20261021/reference/tools/build_r5_m4strict_gamma.py)。

原厂CP有47行Gamma（0～46），FL2／FL3新增47～50后为51行；六款联合方案再扩为63行，并迁移两条原曲线、修正全部引用。最终地址应以[joint-layout.json](materials/joint-layout.json)为准，不直接沿用早期曲线地址。

原CP新增名称门槛文件偏移`0x13c460`、`0x13d43a`，B029枚举门槛`0x13c4fc`。不同函数的输入枚举域不同；不能把AP编号19直接当所有门槛的输入。验收目标是新拍FL2／FL3分别写出对应名称及B029=22／23，而不是只在桌面软件修改EXIF字符串。

## 4. 加载布局不能省略

最终矩阵与六款联合方案共享5872字节载荷：暂存VA`0x11d3000`，目标VA`0x1a39450`；矩阵仍为`0x1a3a000`。引导在文件`0x524`调用VA`0x108f40`的124字节复制器，校验、复制并擦除暂存区；BSS末端扩展至`0x1a3ab40`，页表／栈保留位置不变。

不要使用早期“扩大初始化data覆盖BSS”或改变文件长度的实验布局。最终等长复制方案的原理见[look_matrix_compact.py](materials/source/a7r5-qemu/tools/look_matrix_compact.py)，最终联合扩展见[look_joint.py](materials/source/a7r5-qemu/tools/look_joint.py)。静态加载范围和局部复制器通过，不等于完整NOR加载器、RTOS冷／热启动都已通过。

## 可直接执行的离线复现步骤

以下命令面向macOS／Linux的bash或zsh。材料中的Python组件工具没有硬编码本机路径，但本轮只在macOS arm64验证；Windows命令行没有验收。

**此入口复现当前整合4.06，包含四项功能，不是仅修改本文一项。** 四份文档按研究主题拆分，共享CP包装器、Gamma、加载和AP代码，不能把四份不同CP二进制相互覆盖。只有NTSC文档另提供经过校验的独立AP组合。

### 第一步：准备输入和运行环境

需要Python3.12及以上、`uv`，以及有合法使用权的原厂A7R5 4.00 DAT。把路径替换成自己的真实路径；保留引号。

```sh
KIT="/path/to/a7r5-firmware-features文档-20261023"
OFFICIAL="/path/to/official-4.00/BODYDATA.DAT"
RUN="$KIT/work-$(date +%Y%m%d-%H%M%S)"
mkdir "$RUN"
uv venv "$RUN/venv" --python 3.14
uv pip install --python "$RUN/venv/bin/python" -r "$KIT/materials/dattool/requirements.txt"
PY="$RUN/venv/bin/python"
```

依赖版本已固定：numpy2.5.4、pycryptodomex3.24.1、cryptography50.0.2。不要修改系统Python或拿其他机型固件尝试这些偏移。

原厂DAT必须满足：

```text
长度：754525608字节
SHA-256：51e1176a255a9a4b4782dfbcfa6c5f332b71173bdfe9ed2bcf4fca6bcbc6c2e2
机型：ILCE-7RM5，明文机型字段0x11030080
版本：原厂4.00
```

### 第二步：完整验证原厂包，解包到全新工作副本

```sh
"$PY" "$KIT/materials/dattool/dattool.py" verify "$OFFICIAL" > "$RUN/original-verify.json"
"$PY" "$KIT/materials/dattool/dattool.py" unpack "$OFFICIAL" --output "$RUN/work" > "$RUN/unpack.json"
```

`verify`验证全部帧；不能用只读首帧的`inspect`代替。新工作目录需要约1GiB，打包还需要至少3GiB空闲临时空间。解包器不在主机展开归档中的符号链接，只在清单保存链接信息。

### 第三步：修改工作副本中的组件

```sh
"$PY" "$KIT/materials/reproduce.py" \
  --workspace "$RUN/work" --feature all \
  --receipt "$RUN/components-applied.json" > "$RUN/components.log"
```

执行前会检查原厂DAT来源、所有AP／CP／UXC／WBI文件的完整SHA-256和补丁前像；先生成全部目标，再替换工作副本。原始DAT不会被打开写入。

本步骤修改：

- `components/usr/lib/appFw.so`：最终AP，97368304字节。
- `components/cpapp-b.bin`：最终CP，17617008字节。
- `components/usr/share/app/string_*_horizontal.uxc`及`_vertical.uxc`：68份资源，各增长132字节。
- `archive/0700_part_image/dev/nflasha5`：只改偏移3，WBI2→WBI3。此标记不证明实际冷启动、NOR或CP已重新加载。

回执必须为`WORKSPACE_COMPONENTS_VERIFIED`。新AP／CP必须分别为：

```text
AP d15933ceb5ff9ad0b4f789cbabd6ff0a51526472dd35c90db97196dd227820e9
CP 18b265c589eb4201d3b3680857d897b693d06c6dd491d795dbb3a616d6182e97
```

脚本拒绝已经修改过的前像，不能在同一个work目录重复执行。若替换工作文件中途失败，目录可能部分修改；不要继续打包，也不要修改摘要门槛“强行通过”，应从原厂DAT另建全新work重做。没有自动机身恢复或自动刷写动作。

### 第四步：用与机身信任相配对的研究身份打包

```sh
KEY="/private/path/research-signing-private.pem"
PUBLIC="$KIT/materials/dattool/keys/research-public.pem"
"$PY" "$KIT/materials/dattool/dattool.py" pack "$RUN/work" \
  --output "$RUN/BODYDATA.DAT" --version 4.06 \
  --private-key "$KEY" --public-key "$PUBLIC" > "$RUN/pack.json"
"$PY" "$KIT/materials/dattool/dattool.py" verify "$RUN/BODYDATA.DAT" \
  --public-key "$PUBLIC" > "$RUN/final-verify.json"
```

`KEY`必须是RSA-2048配对私钥，在macOS／Linux上权限为0600。**材料未附私钥；没有配对私钥则不能完成这条打包路径。** 原项目已有本机私钥或先前独立工具包中的私钥，需要所有者单独保管和交付。不要将私钥写进Markdown、命令参数字符串或公开仓库。

本材料配套研究公钥PEM SHA-256为：`7f65b296987df665da217de514e785f75238e686ddd18952fa425fc47e8c858a`。不是索尼官方公钥，也不是索尼私钥。若使用自己的身份，需要使用匹配公钥，并另行解决机身信任；这四份功能文档不提供信任环境写入方案。

打包器合并组件到分区，更新对应归档`.sum`中的CRC32，更新BCD版本头与头CRC，再加密、签名和完整回读。不手改`manifest.json`、`.sum`、文件系统分配或签名字段；不要同时修改同一分区的原始镜像与其内部组件。

`4.06`是本次研究版本示例，不是官方4.06。相同／更高版本机身是否接纳未由此证明；不要自行加入同版本绕过。打包器选择的空闲块分配次序可能不同于历史构建，因此**目标组件摘要应完全一致，整份DAT摘要不强求等于历史文件**；最终以本次完整回读回执绑定输出。

### 第五步：完成验收后才讨论上机

`final-verify.json`必须有签名通过、`full_frame_validation=true`、正确机型和研究版本。该校验不等于机身更新器接纳、完整启动或实拍成功。

本手册的自动步骤到此结束，不操作USB／SSH／SD卡。若后续决定实机试验，必须另行核对当前机型、固件、更新器信任、版本准入、供电及恢复条件，再由操作者通过原厂菜单完成。完整DAT可能重写分区，不能把“改了几个字节”理解为机身只写几个字节；旧DAT也不自动等同可用救援包。

## 本功能的验收与停止条件

离线要看到：旧保存值00仍产生AP编号19／20；两处调用路径一致；照片CP选择54／55、视频56／57；目标矩阵和CC1与ST不同，非目标不变；输出边界、栈和保存寄存器不损坏。不能从直接给CP输入54／55的测试跳过AP入口。

实机另外验收：菜单选择、实时取景、新拍JPEG和ARW、保存再开机。RAW当前参数应是FL2／FL3而非Standard；检查7842／7844／7845、7800、780F、7806及名称7770。应区分当前SR2根目录和十种可用外观目录，后者存在不证明当前应用。控制曝光、白平衡、光源与滑块，不能用自动白平衡场景的全图像素差直接评判滤镜精度。

若仍是Standard，先保留原片、核对实际AP／CP文件及运行路径，再查通知和消费者；不要继续修改供体系数碰运气。分区文件摘要相同不证明正在执行的CP RAM或NOR相同。没有证据时不追加机身写入或热补丁。
