# A7M4 镜头 AF 与自定义纵横比移植

镜头 AF 能力过滤已接入 A7R5 离线构建，使用 `--lens-af` 开启。自定义纵横比研究组件已接入原厂十档菜单和两套照片取景控件，包含 1.91:1 和 2.35:1。AP 消息、横竖取景坐标、CP 逐张锁存和 AVCAM 编码请求均完成离线回放。QEMU 已确认六档新增比例及横屏拍摄页构图边界，物理 LCD／EVF 与成片仍待验收。[十档纵横比研究组件](../photo-aspect-ratios/src/README.md)

## 镜头 AF 能力过滤

原厂分类器 `0xa6bca0` 继续写入兼容标志，原厂 getter `0xa6bce2` 仍可供其他调用点读取。只有兼容标志为 1 且兼容配置为自动（0）时，五个指定调用点读取 0，从而保留镜头原报数据并按原厂分支发布能力。

| CP 调用地址 | 原生用途 |
| --- | --- |
| `0x3f4db0` | info7 过滤 |
| `0x3f3fec` | info8 过滤 |
| `0x3f47b6` | info3D 能力和速度档案过滤 |
| `0xa64db4` | 发布缓存能力位 12、15、21 |
| `0xa64f48` | 发布缓存能力位 28、29 |

辅助代码占用 44 字节，起于 `0xbef780`。该空间来自已搬迁的曲线区，现有电子快门声与 FL2／FL3 矩阵指令位于前方。构建器核对整份 CP 输入摘要、五条原指令和辅助代码区前像，记录逐处逆还原结果。AF 逻辑见 [lens_af.S](../lens-af-compat/src/lens_af.S) 和 [lens_af.py](../lens-af-compat/src/lens_af.py)。 [A7M4 AF 补丁配方](https://github.com/Erlla/sony-a7m4-custom-firmware/blob/main/a7m4/profiles/lens-af.json)

从仓库根目录构建及回放，`--baseline` 指向已有原厂派生基底，`--output` 指向尚未创建的离线输出目录。

```sh
feature=a7r5-firmware-features/firmware-runtime
baseline=a7r5-qemu/runs/verify-17-NqJEIq/baseline
output="$PWD/a7r5-qemu/runs/native24-lens-af"
.venv/bin/python -B "$feature/build.py" --baseline "$baseline" --output "$output" --lens-af
A7R5_NATIVE24_BUILD="$output" .venv/bin/python -B -m pytest -q \
    "$feature/tests/test_lens_af.py" "$feature/tests/test_build_contract.py"
```

- 启用补丁的 CP SHA-256 为 `530b45341bd17649d561bb5f906a23c505724d78e408ec2edc7dbf465eade3d5`。默认构建的 CP 为 `35eb911d27be4a8aab8a0a5fe9a8f028c16453d5ab79605fe36dbd199b833300`。两次构建的 AP 和两个图标容器逐字节一致。
- 定向构建与 AF 测试 6 项通过，默认构建下的 AF 回放 1 项通过。回放覆盖原厂镜头分类、自动／强制／关闭兼容、未知标志、三个信息包字段、五个能力位的逐位发布、辅助代码寄存器和条件码。
- 现有运行时回归选取 7 项通过，覆盖 24 槽与 ST／FL2／FL3 往返、Gamma、NTSC、照片标记、电子快门声及组件布局。全目录测试在 17 项通过后停止。离线回放使用合成镜头包，实际镜头对焦及连拍表现待实机验证。

## 自定义纵横比初次定位

A7M4 增加 17:6、65:24、5:4 和 7:6，保留四种原厂比例。新增选项通过拍摄任务传到 JPEG／HEIF 的编码输入，RAW 主图保留全幅，取景遮罩单独绘制。A7R5 的 2.35:1 照片标记属于构图功能。 [A7M4 纵横比实施说明](https://github.com/Erlla/sony-a7m4-custom-firmware/blob/main/methods/07-custom-aspect-ratios/IMPLEMENTATION.md)

| 环节 | A7R5 已定位的证据 |
| --- | --- |
| AP 原厂选项 | ELF VA `0x3f46600`，四行各 `0x80` 字节，alias 126–129，行内枚举 0–3。描述符 VA `0x586b990`，`+0x54` 是数量，`+0x58` 通过 ELF 重定位指向选项表。 |
| AP 菜单状态 | 描述符原生回调 `0x1c448dc` 读参数，`0x1c61d14` 设置参数，`0x1c93d88` 走提交。参数 ID `0x52b` 出现在描述符和 setter 中。 |
| CP 主 JPEG | `0x473562` 从 `task+0x5f78` 向栈上请求复制 12 字节。 |
| CP 场景 JPEG（SCN） | `0x472a0e` 从 `task+0x5fdc` 向栈上请求复制 12 字节。 |
| CP 缩略 JPEG（THM） | `0x473282` 从 `task+0x5fe8` 向栈上请求复制 12 字节。 |
| AVCAM | 在 `nflasha3` 提取到原厂 `AV-CAM.BIN`，其中有 JPEG 转换的 canvas、有效区域和目标区域日志，以及静态照片比例枚举。尚需追到实际逐格式写入者。 |

CP 地址属于原厂 CP SHA-256 `3269bf62426339791fcfbe8529698cd4accbe6c3d2ea61cd7c368a90ab7ee7c8`。三条复制指令都调用原生 `0x5f51bc`。以不同的 12 字节任务数据回放每条路径，确认栈上请求逐字节复制、原任务数据保持。这些片段验证了输入副本边界，尚未运行编码器。

上表保留初次定位所依据的地址。后续已按 A7R5 原生布局核对 AP→CP 枚举、逐张任务编号和 JPEG／HEIF 请求副本边界。成片验收需读取实际解码尺寸并验证 RAW 有效幅面，复现命令和验证范围见[纵横比离线验证](../photo-aspect-ratios/src/README.md#离线验证与成片边界)。
