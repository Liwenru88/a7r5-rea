# 长期资源、最终包资源与机内 RAW 备选外观

本轮只离线修改和回放，未连接相机、未覆盖历史升级包、未生成新 DAT。机内 RAW 路线已按用户选择实施；Lightroom DCP 不在范围内。实体相机出声、真实 ARW／Imaging Edge 重选与导出仍未验收。

## 已确认的问题及修改

### CP 暂存区

`native24-combined/runtime/cp_stage413_probe.c` 原来在失败导入后重新 BEGIN 时另分配一个 947,000 字节库；开始导入后恢复相同已发布库的快捷路径，又把暂存指针直接丢弃。两条路径均能持续消耗 16 代预算。回放先观测到本应两次分配变成四次，再实现修复：

- 只清零并复用从未发布、不同于当前已发布指针且未封存的暂存库。
- 快捷恢复相同库时取消暂存会话的 phase，保留暂存区；迟到的 PUT／SEAL 不再恢复旧事务。
- 已发布库不回收、不改写，不按时间推断消费者退休；16 代上限保持。达到上限拒绝新的库，普通切槽不分配库。
- 去掉重复 CRC28 实现，改用已有 IEEE CRC32 的前 28 字节计算，原线协议保持。全功能 CP 常驻代码仍限制在 7,584 字节，未扩展执行区。

历史测试夹具固定每次推进 512 KiB，小于实际 947,000 字节库，第二个库会覆盖第一个。新增本地 `tests/cp_services.py` 按实际长度和 8 字节对齐分配；冻结的上游夹具没有修改。

单项 CP 的当前摘要为 `bf94dff634ce8369073c4f25728fd02fa1e6a02f5d3e46d69360b85e184b6a9b`，已更新 `look24/runtime-components.json` 修订 3。为核对来源，使用逐文件验证的固件源子集分别编译 HEAD 旧 C 文件和新 C 文件：旧 CP 精确恢复修订 2 的 `075e4395…`，新 CP 为上述摘要。此为组件诊断；完整快照门禁仍然拒绝发布，不能将子集诊断称为净源码全量构建。

### 声音长期回归

声音生产代码没有发现需要更改的问题。扩展宿主 C 回放并启用地址／未定义行为检测：10 万次曝光和重复通知、计数回绕、10 万次停止等待，以及实际派生双组服务 1000 次选声／关闭／机械电子切换。装卸后分配计数归零、峰值不增长；等待停止时不释放缓冲。这里是有限次数压力回放，未进行同等时长的硬件运行或扬声器测试。

### 最终包资源门禁

新增 `core/resource_audit.py`，在 `core/package.py::verify_readback` 中检查最终解包的 USR。不能只验证中间目录或组件摘要：

- 34 种语言必须各有横、竖银行，共 68 份，按记录检查索引、标识、终止符和 UTF-8；逐语言核对 C1–C6 与画幅新增文字内容。
- 对两份 IPSX 图标银行的所有载荷解码；每块独立字典，前序块必须是 4096 字节，尾块不得超限。拒绝短读、跨块反向引用、越界／错位描述符。
- 按所选模块核对 24 槽、画幅菜单／回放／尺寸图标的存在、形状和分块；核对已登记的菜单、静态文字、图标和动态文字范围没有跨模块编号冲突。
- 资源失败会中断验证，不能输出 OFFLINE_VERIFIED。动态文字只验证声明的编号范围；UTF-8 通过不代表所有字体字形都已屏幕渲染验收。

从历史 4.19 修正版 DAT 重新验签、解密全部 736,841 帧，核对 147 个归档条目后提取 USR；新增资源检查通过。原厂 USR 也通过，避免新门禁误拒绝未选择相关模块的包。该检查不改变 WBI、NOR 或更新器信任策略。

### R5 原生 RAW 十二项目录

新增 `look-fl2-fl3/raw/native.py` 和 `raw_alternatives.S`，由 `native24-combined/build_stock_color.py` 和 `build.py` 在 FL2／FL3 已接入后调用；相应源码及链接器进入构建来源摘要。FL2／FL3 模块修订升为 2。没有照搬 A7M4 地址或 169 根字段常量。

| R5 原厂 4.00 CP 地址 | 操作及保护 |
| --- | --- |
| `0x0198780c` | 配置 RAM；仅原数量 10 时补 `+0x7a=10`、`+0x7b=11`，最后发布数量 12，其余字节保留 |
| `0x00ad9ff6` | 数量接口；10／12 成功，其余保持失败 |
| `0x00ada00e` | 有界映射；未知值返回 -4，输出保持 |
| `0x00ada014..0x00ada08e` | 122 字节 helper，放在已替换映射函数的原执行区，未新增可选页 |
| `0x00ade854` | 构造调用经 helper 尾调原 `0x00add162`，原构造函数全段前像保护 |
| `0x00ca09b8` | 备选 Gamma 第 10／11 项改为 19／20，原十项不变 |
| `0x00bef220..0x00bef33c` | 既有 FL2／FL3 八组 RAW 参数／名称路由必须符合完整前像；拒绝在尚无该能力的原厂 CP 上只加目录 |

R5 根字段仍为 175，每个 child 114 字段、步长 3110 字节。十二个 child 从 `0x1162` 到 `0xa32a`，下一原生区域从 `0xaf50` 开始。原十款 child 与直接执行原生构造器的输出逐字节一致；新配置只改变上述三字节。原生未知配置保留。新增 RAW helper 本身不分配堆、不增加 BSS、不写持久备份，也不改 Bayer 数据或十二款 SD 配方的 Gamma／矩阵／网格算法。

独立 FL2／FL3 从原厂 4.00 成功编译组件；与 24 槽、双组声音、C1–C6 的组件诊断后，重新运行现有画幅及 AF 构建器成功。RAW 全部测试 32 项通过，包含两款在八组参数／名称路由中的指令执行。没有真实相机 ARW，不能据此声称 Imaging Edge 已识别或导出颜色已验收。

## 运行方式与证据边界

从仓库根目录执行；`stock` 是已按原厂 4.00 DAT 完整解包的工作区。完整组件回放使用根 `.venv`，封包测试使用 DAT 工具环境。两个既有环境各有所需依赖，测试时可用只读 `PYTHONPATH` 补入另一环境的包；不修改环境或安装依赖。

```sh
.venv/bin/python -B a7r5-firmware-features/native24-combined/build_stock_color.py \
  --stock "$stock" --fl23 --output "$out/fl23-components"

A7R5_RAW_CP="$out/fl23-components/cpapp-b.bin" \
  .venv/bin/python -B -m pytest -p no:cacheprovider -q \
  a7r5-firmware-features/tests/test_raw_alternatives.py

# 当前已构建 CP 的符号收据位于 build/work/cp/build.json。
A7R5_LONGRUN_BUILD="$build" A7R5_LONGRUN_CP="$cp" \
  .venv/bin/python -B -m pytest -p no:cacheprovider -q \
  a7r5-firmware-features/tests/test_longrun_resources.py

R5_SOUND_WORKSPACE="$build/work" .venv/bin/python -B -m pytest -p no:cacheprovider -q \
  a7r5-firmware-features/photo-electronic-shutter-sound/tests/test_sound.py
```

RAW 用例还需要 `A7R5_NATIVE24_BUILD` 指向有效 CP 符号收据；默认使用本机保留的 4.19 组件视图。逆还原测试的 `A7R5_RAW_SOURCE_CP` 必须是已含 FL2／FL3 路由、尚未叠加 RAW 扩展的 CP。缺少这些输入时不能把跳过当作通过。

本机组件诊断位于 `.local/longrun-raw-20261112/`，小型结果归档在本目录 `evidence/`。诊断中的 AP 从此前最终包补丁精确逆还原，再按实际补丁组合，重生成的 C 源摘要与历史编译收据相符；没有重新编译 AP。组合测试显式使用 `--noconftest`，复用原生测试体并核对组件与逆还原证明，不冒充当前净源码全套门禁。
