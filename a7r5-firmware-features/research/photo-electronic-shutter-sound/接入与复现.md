# 自定义快门声音双组候选：接入与复现

本文下方保留首次双组候选的固定布局和 41 项历史证据。当前新增[4.19 全功能预设](../presets/full-4.19.json)，使用 `custom-dual-full` 变体适配全部十个模块；声音页改为 `0x1a3b000`，独立声音映射助手为 `0x109100`，原生页表保持 `0x1a3c000`。完整构建及回归命令见[4.19 实施记录](../specs/4.19-full-integration/实施与复验.md)。下面“禁止与色彩组合”只适用于首次候选，不适用于新增全功能变体。

本阶段已完成原厂 4.00＋24 槽运行时上的 AP／CP 离线候选。机械快门、电子快门可分别选择声音、关闭及设置 10%～100% 音量，电子前帘共用机械组。候选复用原厂选择页；浏览不应用，按中键确认后由后台保存并安装。默认两组均关闭，音量 50%。

当前 `module.json`／`compose.py` 的正式配方仍使用原厂声音模式。本候选禁止与旧声音补丁、FL2／FL3、C1–C6 组合，避免把尚未核对的新布局当成发布版本。没有生成 `BODYDATA.DAT`，没有相机读写或真机验收。

## 源码与职责

| 文件 | 职责 |
|---|---|
| `upstream.json`、`bindings/upstream/` | 固定上游提交、源码摘要及原始实现；派生时不编辑原文件 |
| `bindings.py` | 核对原厂 AP 身份、快门类型描述符及选项；接入媒体、曝光、电源、后台线程、AP 重定位与 CP 保护页 |
| `profiles.py` | 将上游单配置服务派生成机械／电子双配置；串行保存、切组与退休事务；将导入索引缓冲移到堆中 |
| `bindings/r5_sound_profiles_menu.c` | 四项菜单：电子声音／音量、机械声音／音量；两套独立的原生描述符和确认回调 |
| `runtime/r5sound_profiles.c` | `R5SOUND.PRO` 的校验、身份恢复和两组原子保存 |
| `runtime/r5sound_catalog.c`、`r5sound_package.c` | 声音库、文件身份、十档音频载荷校验 |
| `runtime/r5_shutter_scheduler.c` | 曝光去重、只保留最新待播事件、Stop 后等待真实退休 |
| `unified.py` | 保留声音注册、四条父项重定位和 PLT 副本；隔离与创意外观的行号、文字资源和加载段 |
| `../native24-combined/build.py --custom-sound` | 完整离线组件构建，保存派生摘要、编译命令、布局与逆还原证据 |

上游来源固定为 Hearts-Ace `be3dc9a622a797ce72270ff39a5d44ccaa33edc8`；Erlla 行为对照固定为 `68878118af81466575654ac02edaedcc4b391f14`。转码器的旧来源提交另见清单。重新取源码时必须逐文件核对清单，不能把 M4 地址直接搬入 R5。

## 状态与保存

1. 完整冷启动扫描已完成挂载的 SD 根目录 `.R5S`，最多 60 个。全部校验通过后发布机内目录；未完成的卡、导入失败或没有有效新文件时保留原库。
2. `R5SOUND.IDX` 保存声音库；`R5SN_<头部SHA256>.R5S` 保存声音内容；`R5SOUND.PRO` 保存两组声音身份和音量。原始 SD 文件保持原样。
3. `R5SOUND.PRO` 为 96 字节：8 字节魔数 `R5SNDPF1`，4 字节版本 1，两个 40 字节记录，最后 4 字节 CRC32。每组记录为 32 字节声音身份、4 字节音量档位、4 字节启用位，均为小端。
4. 排序或文件名改变时按声音身份恢复。声音已不可用时该组关闭，保留音量。损坏记录拒绝加载，默认关闭／50%。首次没有双组文件时，只将旧单组 `SEL`／`VOL` 读取到电子组，机械组保持关闭；读取过程不写盘。
5. 两组设置使用同一个临时文件事务原子写入。写入失败不发布新的配置；重命名后目录同步失败记录为持久化不确定。选择先保存，再校验／安装音频；安装失败时状态报告失败，不能视作已经出声。
6. 切换模式期间停止接收待播事件，旧播放需要原生退休证据。当前事务期间再次切组，先完成资源事务并保持静音，随后装入最新目标组。另一组编辑只保存配置。静音和原厂音频信号仍由原生接口在播放前复查。

原厂 4.00 的快门类型属性是 `0x60a`。描述符 `0x5897cc0` 的读取入口为 `0x1bfadc0`，机械和电子选项分别为 0／1，证据由构建自动输出到 `work/import/r5sound_native400.json`。其它值关闭自定义播放。

## 布局约束

| 项目 | 候选布局 |
|---|---|
| 自定义滤镜行 | `0x1610..0x1627` |
| 电子声音／音量行 | `0x1680..0x16bc`／`0x16c0..0x16c9` |
| 机械声音／音量行 | `0x1700..0x173c`／`0x1740..0x1749` |
| 四项父菜单 | `0x636..0x639` |
| 电子／机械文字资源 | `0x02ff5600`／`0x02ff5700` 起；避开滤镜标题和 Tab |
| AP 主 RX／RW | `0x8e90000`／`0x8eb0000`，BSS 容量 393216 字节 |
| 统一外观 RX／RW | `0x8f10000`／`0x8f20000`；地址换算基准同时移动 |
| CP 主代码 | `0x1195260..0x1196fff`，容量 7584 字节 |
| CP 声音保护页 | `0x1a3a000`，实际内容、复制与校验由 CP 构建器核对 |

为容纳声音接入，CP 的 `native_gamma.c`／`cp_transfer.c` 使用禁止内联编译；传输 CRC 复用同算法的 `r5_diag_crc`，仍将偏移 28～31 视为零。实际 CP 指令已与标准 CRC32 对照。当前 CP 主窗口没有剩余空间，后续加入其它功能必须重新核对布局。

## 复现命令

从仓库根目录运行，使用已有虚拟环境与 LLVM 工具链。输出目录必须是新的目录。`-B` 防止在固定源码快照中产生 Python 缓存；原厂输入不会覆盖。

```sh
a7r5-dat-tool/.venv/bin/python -B \
  a7r5-firmware-features/materials/dattool/dattool.py unpack \
  a7r5-firmware-images/官方升级包/BODYDATA.DAT \
  --output /tmp/r5-sound-stock400

.venv/bin/python -B a7r5-firmware-features/native24-combined/build.py \
  --stock /tmp/r5-sound-stock400 --custom-sound \
  --output /tmp/r5-sound-dual-candidate

R5_SOUND_WORKSPACE=/tmp/r5-sound-dual-candidate/work \
  .venv/bin/python -B -m pytest -q \
  a7r5-firmware-features/photo-electronic-shutter-sound/tests \
  a7r5-firmware-features/tests/test_compose_all.py::test_full_preset_resolves_sound_once_and_combines_templates

A7R5_NATIVE24_BUILD=/tmp/r5-sound-dual-candidate \
  .venv/bin/python -B -m pytest -q \
  a7r5-firmware-features/native24-combined/tests/test_tabs.py \
  a7r5-firmware-features/native24-combined/tests/test_runtime.py::test_all24_transactions_names_colors_and_factory_roundtrips \
  a7r5-firmware-features/native24-combined/tests/test_runtime.py::test_all11_gamma_getters_preserve_registers_flags_and_native_fallback \
  a7r5-firmware-features/native24-combined/tests/test_relative_parameters.py::test_all_twenty_four_display_zero_and_signed_native_ranges_preserve_registers \
  a7r5-firmware-features/native24-combined/tests/test_relative_parameters.py::test_offsets_follow_native_changes_clamp_without_losing_intent_and_reset
```

构建器先核对原厂 DAT／AP／CP 的完整 SHA-256；每处变更必须匹配前像。产物为 `appFw.so`、`cpapp-b.bin`、资源及 `build.json`，`installable` 与 `DAT_generated` 均为 `false`。AP 两层分别有可逆补丁记录；最终 ELF 核对装载权限和区间，声音的四条重定位及 PLT 均保留。

## 验证边界与后续

本阶段的运行时回放执行实际派生 C 服务并启用 ASan／UBSan；菜单、重定位、切组及滤镜色彩检查执行实际 AP／CP 指令。文件系统、E4、原生音频接口及完成事件使用明确的测试替身。没有声称音频硬件播放、真实 eMMC 断电恢复或相机菜单显示已经验收，也没有继续扩展 QEMU 硬件模拟。

正式发布还需：原厂声音单项构建适配、自定义声音与 FL2／FL3／C1–C6 及拍摄模块的组合布局、`compose.py` 配方切换与独立解包验签，以及另行授权后的实机出声、连拍延迟和电源恢复验收。现有升级包和正式配方保留。

本轮最终候选共 41 项检查通过：声音及正式配方兼容 10 项，创意外观切组、24 槽色彩／Gamma 和相对调参 31 项。独立逆还原均精确回到原厂 4.00 AP／CP。声音启动函数栈帧为 4496 字节，BSS 为 331248 字节，均在候选布局限制内。

本轮回执见 [双组接入离线验证](verification/dual-profile-verification.json)，命令及源码摘要见 [构建收据](verification/dual-profile-build.json)，原始输出见 [声音测试](verification/dual-profile-sound-tests.log) 和 [创意外观回归](verification/dual-profile-native24-tests.log)。

后续已使用同一候选补齐 QEMU 真实菜单、中文、独立选择／音量、取消、虚拟存储保存及无卡新客体恢复。详见 [QEMU 验证及截图](QEMU验证.md)。实际出声与音频硬件时序仍不在模拟验收范围内。
