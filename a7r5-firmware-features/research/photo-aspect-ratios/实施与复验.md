# 十档照片画幅：实施与离线复验

当前修订 5 保留修订 4 的限次补读、后台保存及失败提示，并修正 AArch64 的目录打开标志。先前非安装组件的代码和复现脚本见[三项闭环修复](../specs/4.19-operation-fixes/实施与验证.md)；该目录的源码锁对应修订 4，不能当作修订 5 的回执。历史升级包不自动包含这些源码修改。

目录打开必须使用目标 ABI 的 `O_DIRECTORY=0x4000`；`0x10000` 在 AArch64 是 `O_DIRECT`，而不是目录标志。配置读取与保存共用此约束，文件保持 `O_NOFOLLOW=0x8000`。依据为 [Linux arm64 UAPI](https://raw.githubusercontent.com/torvalds/linux/v4.9/arch/arm64/include/uapi/asm/fcntl.h)。`test_ap_state.py` 的文件服务夹具检查目标标志，`test_target_directory_abi_preserves_config_across_save_and_restart` 在修复前稳定失败，修复后完成保存／重启恢复。它覆盖了旧夹具只检查 `0x20000`、误把大型文件位当作安全标志的验证缺口。

## 范围与稳定契约

基线为 ILCE-7RM5 原厂 4.00。仍为原厂 3:2、4:3、16:9、1:1，以及 17:6、65:24、5:4、7:6、1.91:1、2.35:1。菜单编号 0..9、私有行 0x1600..0x1605、AP／CP 私有消息 0xe0..0xe5 不变。原厂属性只接收 0..3，CP 原生消费者仍看到 3:2 的 wire 值 2。

`cp.c` 的选择代次、拍摄快照、逐张任务旁表、任务复制继承及归还清理继续保留。裁切发生在编码请求副本或 AVCAM 局部区域，不覆盖源任务的完整几何。

参考固定为 Hearts 4.58 的提交 `1f7d537638897d91b0e0a2feff6370733b39179a`。具体文件与 Git 对象摘要见 [upstream-reference.json](upstream-reference.json)，许可在 `licenses/`。OpenPano 只用于核对公开描述，没有引入其未公开补丁或原生枚举扩展。构建不访问网络。

## 菜单、取消和保存

`ap_menu.c` 保留原厂四行，新增六行仍映射原厂 3:2 提交。`ap_menu.S` 将新增行委派到原厂可用性判断；`ap_guide.c` 只允许静态型号列 16 补取景控件，其他原厂拒绝不绕过。

`ap_state.c` 在原生 `0x2adfd3c` 捕获、`0x2adfd5c` 恢复入口配对保存私有比例，并补 `0x1bd64c8/0x1bd64d4` 的取消提交。恢复发布新代次，旧回调通过比较交换检查，不能覆盖较新的操作。

`ap_persist.c` 使用 `/setting/r5_aspect10_v1.dat`，不改原厂设置文件。记录为四个小端 uint32：魔数 `0x41533552`、版本 1、私有编号、编号反码。编号只允许 0 或 4..9；0 表示沿用原厂选择。只在确认时保存，浏览和直接取消不写盘。

修订 4 的确认只排队，独立分离线程执行原独占临时文件、完整写入、文件同步、同目录原子改名及目录同步。每个确认最多三次尝试，间隔一秒；发布前失败保留旧文件，目录同步失败也如实提示。菜单显示“正在保存”或“画幅已生效，保存失败”，成功恢复原标题；旧代次的失败不污染较新的确认。忙时保留最后一次确认，不保存浏览中的临时比例。损坏、空、过长或未知版本记录回退原厂，不清空其他设置。

开机首条 `0x402d` 配置消息保留立即恢复，不依赖打开菜单。临时错误在后台按一秒间隔补读，包含首次在内最多三次；无文件和格式错误终止补读。补读成功走原厂 `0x52b` 属性依赖及通知链，使后续原生配置携带正确私有画幅。内联包装仍保存易失整数、SIMD、浮点状态及标志；显式操作提高代次后，迟到读取不能覆盖它。

## 编码、RAW 与元数据

`geometry.c` 是十档整数比例的唯一数据源。`aspect_sizes.py` 从它生成 L/M/S 的 18 组尺寸、SCN/THM 表和回放表；这些表与 AArch64/Thumb 几何回放交叉检查。

- JPEG：继续裁切 CP 请求副本。RAW-only 的内嵌 JPEG 也走此路径。
- HEIF：原 `0xae78ae` 复制保持原生，Notify 只更新 HEIF 槽尺寸；共享 YC 主图、场景图和缩图描述不预裁。`avcam_views.c` 在各格式局部 prepare/encode 中裁切，已经合法裁切过的输入保持原偏移，不重复裁切。
- RAW：原始 Bayer、DefaultCrop、SonyCrop 和 RAW 槽完整幅面保留。`0x48a00a` 在原生头生成之后，仅同步 EMB JPEG 的两个尺寸字。完整原生头生产者回放对比只允许 `0x14a2c..0x14a33` 八字节变化。
- JPEG 元数据：`mpr_jpeg_metadata.c` 从有界 SOF 获取真实尺寸，修改本张私有 Exif 源，再执行原生缓存和写头。即时缓存与完整原生 Exif getter 的尺寸、分类一致。
- RAW 元数据：只同步私有预览 TIFF 的 PixelX/YDimension、FullImageSize 和 PreviewImageSize。先验证所有标签类型、数量与缓冲区边界，再一次提交；不回写共享源或 RAW 裁切标签。
- HEIF：补六档精确 SCN 尺寸及特定 THM 的原生分类，未知尺寸保留原分支。

AP 回放按本张文件的实际尺寸补画幅和像素数图标。未知比例放大只对元数据有效、格式存在、专用 RAW/主图尺寸一致且精确匹配的记录放行；其他描述符及新增编号空洞仍拒绝。旧文件中已经写错的 Exif 不会被批量改写。

## MF／AF 坐标边界

本地实时取景使用完整原厂图像加遮罩，没有裁掉实时流。因此 AF／MF 保持原厂完整源坐标域，不照搬 OpenPano 裁流方案的坐标重映射，也不新增“只能在裁切框内移动 AF 点”的限制。

离线回放覆盖六档横竖遮罩的实际原生图元、控件重建与代次失效；检查编码前后整个拍摄任务不变，AF／MF 相关原生枚举维持 3:2。`0x182d974` 实际是竖向 viewport 构造，已更正本地命名，不能把它当成 AF 点旋转函数。镜头 AF 能力消费者另按已有测试回归。

这些是坐标域和几何边界证据。实际 AF 点移动、眼部追踪、MF 硬件放大和退出恢复仍需实机验证，不将几何回放描述为真实对焦验收。

## 加载和分区布局

AVCAM 辅助代码从 `0xc5b380` 开始，必须不越过 `0xc5c000`。原有 FAT 文件大小 12,956,536 字节，原簇链分配 12,959,744 字节；新增代码只使用这段余量。`fat_avcam.py` 更新文件内容和目录项大小，不分配新簇，FAT 表及其他文件逐字节保留。原生 RAM 快照移到新增代码之后，RAM 窗口不变，整个保留范围不超过原厂 16 MiB。

MPR 增加只读执行段与实际映射的 PT_PHDR，原 LOAD、BSS 和动态重定位保留。USR 使用已有 inode 增长工具，检查完整目录、非目标文件、inode 属性和只读 e2fsck。CP 定长写入；WBI 仍由既有组合构建策略处理，本修订不改变失效顺序。

## 从原厂输入复现

在仓库根目录执行。`stock` 必须是已有 DAT 工具验证原厂 4.00 后的解包目录，含 `manifest.json`、`components/` 和 `archive/`；所有前像均由构建器核对。输出目录必须新建，不覆盖已有包。

```sh
root="$PWD/a7r5-firmware-features"
py="$PWD/.venv/bin/python"
datpy="$PWD/a7r5-dat-tool/.venv/bin/python"
stock=/path/to/verified-stock400-unpack
out=/path/to/new-aspect-revision3-work
mkdir -p "$out"

"$py" -B "$root/firmware-runtime/build_capture.py" \
  --stock "$stock" --aspect --output "$out/standalone"

"$py" -B "$root/firmware-runtime/build.py" --stock "$stock" \
  --fl23 --factory-six --output "$out/native24"
"$py" -B "$root/firmware-runtime/build_capture.py" \
  --stock "$stock" --runtime "$out/native24" --aspect --lens-af --output "$out/combined"

export A7R5_ASPECT_STOCK_USR="$stock/archive/0700_part_image/dev/nflasha15"
export A7R5_ASPECT_STOCK_AVCAM_PARTITION="$stock/archive/0700_part_image/dev/nflasha3"
A7R5_ASPECT_CAPTURE="$out/standalone" \
  A7R5_ASPECT_AP_INPUT="$stock/components/usr/lib/appFw.so" \
  A7R5_ASPECT_CP_INPUT="$stock/components/cpapp-b.bin" \
  A7R5_ASPECT_NATIVE24_IMAGES="$out/standalone/stock-images" \
  "$py" -B -m pytest -q -p no:cacheprovider "$root/photo-aspect-ratios/src"
A7R5_ASPECT_CAPTURE="$out/combined" \
  A7R5_ASPECT_AP_INPUT="$out/native24/appFw.so" \
  A7R5_ASPECT_CP_INPUT="$out/native24/cpapp-b.bin" \
  A7R5_ASPECT_NATIVE24_IMAGES="$out/native24" \
  "$py" -B -m pytest -q -p no:cacheprovider "$root/photo-aspect-ratios/src"

for variant in standalone combined; do
  "$datpy" -B "$root/photo-aspect-ratios/src/verify_partitions.py" \
    --stock "$stock" --candidate "$out/$variant" --output "$out/$variant-partitions"
done
A7R5_NATIVE24_BUILD="$out/native24" A7R5_CAPTURE_AF_BUILD="$out/combined" \
  "$py" -B -m pytest -q -p no:cacheprovider "$root/firmware-runtime/tests/test_lens_af.py"
```

上述只构建不可安装组件和离线分区，不签名、不生成 DAT、不连接相机。后续封升级包仍使用根目录 `compose.py` 与模块 ID `photo-aspect-ratios`，并重新完成该包的签名、容器和独立解包校验；旧包不会自动包含源码的新修订。
