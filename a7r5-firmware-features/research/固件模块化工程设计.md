# A7R5 固件模块化工程设计

用户从一份已识别的原厂升级包出发，选择所需功能。工程先列出实际启用的模块、依赖、共享组件和验证状态，再按组合生成 AP、CP、AVCAM 与资源，最后封成一个升级候选。**独立目录管理功能，组件构建器管理合并。** 历史包继续使用各自锁定的前像和增量复现。

首个构建基线为 ILCE-7RM5 原厂 4.00，DAT SHA-256 为 `51e1176a255a9a4b4782dfbcfa6c5f332b71173bdfe9ed2bcf4fca6bcbc6c2e2`。其他原厂版本只有在单独录入组件摘要、布局和回归证据后，才能成为可选基线。 [现有独立构建说明](independent/README.md)

## 为什么不能按包叠加

现有增量以归档成员的完整前像和目标摘要校验。两个功能即便落在同一个分区的不同块，第一个写完后，第二个增量的完整前像也会失配。同一块有两份不同结果时，直接覆盖还会丢失其中一方的数据。 [增量格式与应用逻辑](../a7r5-desktop/engine/native24_preset.py#L63) · [当前固定配置构建入口](independent/build.py#L27)

本次直接读取现有增量的 4 KiB 索引和块内容，对相同基底的样本做比较。

| 配对 | 观察 | 设计结论 |
| --- | --- | --- |
| 24 槽＋FL2／FL3 | CP 分区 8 个共同块，块内容全部不同。两条实现还同时处理 Gamma 索引上限及查表路由。 | 由同一个构建流程生成原厂、FL2／FL3 和 SD 行的查表路由。原厂组切回和 FL2／FL3 数值路径已回放。 [模块实施](look-fl2-fl3/README.md) |
| 24 槽＋照片构图标记 | USR 1 个共同块，内容不同。标记模块依赖原厂活动 ELF 程序头，24 槽会改动 ELF 布局。 | 由同一 AP 写入器安排段、重定位和资源位置。 [标记实施](independent/profiles/photo-markers/README.md) |
| 24 槽＋NTSC 提示 | 同属 USR，现有增量共同块为 0。 | 适合首批共享分区集成，在当前 AP 上校验两处前像、分别回放菜单与提示，再一次性写 USR。 |
| 24 槽＋六款固定滤镜 | 原厂单项六款与 24 槽有 USR 11 块、CP 8 块共同改写。历史共存版借用十档比例组件的早期映射。 | 当前色彩构建器独立建立 CP 映射。SD 行 51–74 与六款私有行 75–86 分开，启动映射与 Gamma 已回放。 [共存构建器](look-factory-six/src/build_legacy_six.py) |
| R6 ST＋AWB 优先 | 12 份模板各有 1 个共同块，内容不同。本轮用现有字段写入器对原厂 12 份模板一次写入三个字段，范围与幂等检查均通过。 | 合并字段级请求，统一生成模板内部校验和及外层 `backup.sum`。 [字段合并实现](native24-combined/dependencies/native12-combined/upstream/firmware/r5/src/templates/prepare_templates.py#L112) |
| 镜头 AF＋十档裁切 | 两份历史增量有 1 个共同 CP 块。当前实现分别检查拍摄和镜头补丁的指令前像。 | 先接入拍摄 CP 布局，再改五处 AF 调用，一次写入 FAT。组合回放检查了原页表、取景及拍摄请求。 [共享构建器](native24-combined/build_capture.py) |

归档块相交只说明不能直接覆盖，实际写入冲突应定位到组件偏移或语义资源。共享同一组件也可以在单一写入器下安全组合，前提是有确定的合并规则和组合回归。

## 根目录布局

根目录提供十个现用模块。旧的 24 槽拆分清单由规划器从 `look24/legacy/` 读取，内容及模块摘要沿用历史版本。历史归档和共用素材保留独立路径。

│   └── ilce-7rm5-4.00.json
├── core/                         # 依赖解析、写入计划、组件构建与封包接口
├── presets/                      # 可选模块集合及锁定的组合

├── look-factory-six/
│   └── src/                      # 六款联合色彩与构建器
├── look24/
│   └── legacy/                   # 六个历史模块清单及说明
├── video-ntsc-prompt/
├── photo-electronic-shutter-sound/
├── photo-framing-markers/
├── photo-aspect-ratios/
│   └── src/                      # 取景、裁切与回放
├── lens-af-compat/
│   └── src/                      # AF 能力补丁
├── color-r6-st/
├── color-awb-priority/
├── independent/                  # 现有精确复现入口与冻结增量
├── native24-combined/            # 共享 AP／CP 构建、运行时及历史证据
├── materials/                    # 固定配方、色彩数据及来源材料
├── aspect-guide406/              # 构图标记研究与固定补丁

└── custom-filters/               # 32 槽研究家族
~~~

每个能力目录至少包含 `module.json`、`README.md` 和验收入口。模块私有的构建器、参数或资源迁入 `src/` 和 `resources/`，共同成像布局保留在共享组件构建器。模块文档记录原厂前像、效果与回退、源码入口、组合约束、离线验收和实机验收分别如何复现。

| 清单字段 | 约定 |
| --- | --- |
| `id`、`revision`、`supported_bases` | 唯一身份、实现版本及已适配的原厂基线 |
| `requires`、`conflicts`、`variants` | 自动解析必要依赖，显式拒绝互斥实现，选择经过验证的构建变体 |
| `provides`、`claims` | 声明菜单 ID、选择器、Gamma 行、CP 页或数据区、AP／CP ABI、模板属性范围等资源所有权 |
| `builder`、`inputs`、`outputs` | 模块只提交修改请求或组件产物。约束前像、目标、资源摘要与改动范围 |
| `checks`、`availability` | 必跑回归、已验证基底与组合、功能状态和证据引用 |

24 槽的开关拆分以现有 4.19 为完整预设。基础模块保留可浏览和中键应用的最小入口、原厂回退、机内库读取和事务保护。关闭自动预览时由中键显式应用。关闭两组记忆时切组从首个有效项开始。选择跨开机恢复只控制最后选择，微调记录仍由调参模块单独管理。停用冷启动扫描时，已有机内库仍可用，新机无有效库时显示空组。上述分离行为属于实施验收项。

## 构建流程与拒绝条件

~~~mermaid
flowchart LR
    A[原厂 DAT 与模块选择] --> B[基线和依赖解析]
    B --> C[列出写入计划与组合证据]
    C --> D[一次生成各组件和资源]
    D --> E[离线回归与归档封包]
    E --> F[独立回读与发布候选]
~~~

1. **计划。** 按机型与原厂 DAT 摘要锁定基线，解析依赖与互斥。计划明确用户选择、隐含模块、变体和每个改动归属。历史前像、未知基线和缺失实现变体分别报错。
2. **生成组件。** 从同一个原厂工作副本出发，按拓扑顺序执行。简单写入验证完整组件和局部前像。多个模块共用选择器、Gamma 路由、ELF 布局或语言资源时，由唯一构建器统一生成。AP／CP／AVCAM 的协议和资源作为配对合同验收。
3. **生成包。** 核对补丁前像、允许写入范围、段大小、内存预算和资源编码。由归档层一次写入 ext2／FAT、计算内部及外部校验值，复用现有 DAT 工具。WBI 策略由基线和组合验证决定，计划必须显式显示是否处理。输出目录在封包和回读均通过后发布。
4. **验收与锁定。** 输出候选、模块选择清单、基线和工具链摘要、组件变化、最终 DAT 摘要与验证回执。用相同锁文件再次构建应得到同一结果。实机证据按具体 DAT 摘要记录，旧包的启动结论不能继承给新组合。

同一区间写入相同字节且预期前像一致时可去重。写入不同值、占用同一语义资源、读写顺序无合同、只存在整合版前像或缺少组合验证时，计划说明原因并阻止该组合进入发布。历史分区增量只用于精确复现对应旧包。设备升级准入和安全机制由原有平台负责，构建器产物状态保持为离线候选，直到该组合另有实机证据。

拟定的配置文件只表达用户要的能力。版本号属于输出元数据，包的身份以摘要为准。

~~~json
{
  "base": "ilce-7rm5-4.00",
  "modules": ["video-ntsc-prompt", "photo-electronic-shutter-sound"]
}
~~~

构建入口提供 `plan`、`build` 和 `verify` 三个子命令。`plan` 可在缺少组合实现时给出拒绝原因。现有桌面端使用四个固定布尔开关和独立的 4.17 预设，后续接入同一个解析器和构建计划。 [现有桌面构建入口](../a7r5-desktop/engine/firmware.py#L12)

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
