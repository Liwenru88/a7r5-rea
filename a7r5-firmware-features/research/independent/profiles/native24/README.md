# 24 槽创意外观运行时

这份资源从原厂 4.00 精确复现相对偏移版 4.17，DAT SHA-256 为 `49ec00bd5c179fc0f784bf8c64e5025877fde5b50c3ce48fe05dd3d51a24dcda`。这也是镜头 AF、十档裁切和历史 4.18 对照的离线基线。已有 FL2／FL3、NTSC、声音、照片标记和地区参数模板包含在这份发布版本中。

## 实施单元

| 单元 | 实施细节 |
| --- | --- |
| 文件格式和槽位 | `R5NATIVE.BIN` 读取 v4 十二槽或 v5 二十四槽，空槽不进入可应用列表。AP／CP 同时绑定容量、位掩码、配方和消息布局。随包样例为十二款正式配方，空位由导出的新配方填充。 |
| 冷启动与持久化 | 冷启动扫描卡根目录，相同内容跳过重写。无卡、缺文件或空文件时使用已提交的有效机内库。换库失败回退，保存选择绑定配方身份，避免同号误用。 |
| 原厂入口 | 原厂组和 SD 自定义组共用创意外观。左键按方向映射切组，优先恢复该组上次成功项，失效时取首款有效项。中键确认，右键调参，调参页中键返回。两组独立记忆的有效期为本次开机，最后成功选择另有持久化恢复路径。 |
| 预览与恢复 | 同时只推进一个 E4 事务，连续输入合并最后目标，成功后自动保存。原生空闲推进和重绘让状态更新，失败后台回退到已确认状态。AP／CP 配方消费者沿用上游照片色彩和 Gamma 语义。 |
| 八项相对偏移 | 本次原生 E4 参数加偏移，再限制到合法值。初始和重置都显示 0。R5TUNE2 按配方身份保存，兼容读取 R5TUNE1。归零时输出应与上游原生消息逐字节一致。 |
| 语言与资源 | 两份图标容器配套生成，新增图标按原厂分块边界编码。名称处理、AP 容量和 CP 配方同一构建身份。 |

## 复现与验收

完成[公共准备](../../README.md#公共准备)后执行。

```sh
"$python" -B "$tool" native24 --base "$stock" --output "$out/native24"
```

输出包括 DAT、研究公钥、验收回执和 `R5NATIVE.BIN`。构建工具要求最终 DAT 摘要与上述发布版本一致。按源码复建时，先重建锁定的原厂派生基线，再使用 `firmware-runtime/build.py` 生成 AP、CP 和两份图标，使用相对偏移测试与封包入口复核。已经安装的机身是否接受同版本内容仍待实机确认。

功能验收按空库／部分库／满库、双卡／无卡、冷启动、切组记忆、快拨只应用最后项、八项调节、恢复和换库场景拆分。从原厂 4.00 实施单功能版请使用另一个配置。 [源封包回执](../../../firmware-runtime/releases/4.17/verification.json) · [整合版精确复现](verification.json) · [4.19 独立版](../native24-stock/README.md)
