# 首批设计与研究边界

复用 Qt、EmulatorSession、固定输入注册表和当前已优化的快照通道。当前菜单起点为原厂 My Menu，已有六键及限定 C4 帮助，其他控制保留证据门槛。

## 实施路径

1. 固定当前清单、源码和既有菜单验收作为回退基线。复用 `build/input-analysis` 的 ELF 副本，先与当前客体逐项核对，避免重复提取。
2. 静态追踪 libObj 的 InfraInput 分发表、appFw 的事件名/回调映射；候选先记录来源、代码和语义。需要动态观测时只在独占模拟器 RAM 中执行，并保存接收和页面回执。
3. 使用真实 Qt 入口遍历明确菜单路径。设置优先选择不依赖传感器和物理介质的显示、菜单偏好等；实际可用项由页面与参数回读决定。
4. 对已证实缺陷做最小修复。公共界面仍拒绝任意 shell、原始键码及未知控制；研究入口与已验收控制分开。
5. 新控制按场景启用，补充定向回归和 Qt 菜单/设置验收，再重建独立应用包。

## 风险与恢复

未知菜单可能等待未建模的 CP/镜头/介质服务；候选失败只停止本次模拟会话，保存日志并通过本实例 QMP 回收，不连续遍历事件值。现有初始化适配保持；不以新增成功回执掩盖未实现硬件。

当前交付包与运行清单保留。模拟库或辅助程序重建使用内容寻址归档，更新清单前核对允许的条目差异；注册表必须绑定相同客体摘要。已有真实菜单像素基线和退出验收继续保留。
