# Fn、DISP、回放无响应的定位与修复

后续已扩展拨轮、摇杆、模式和自定义键；新版首次设置按钮文字为“首次设置（启用功能键）…”。当前操作与交付状态见 [按键扩展说明](button-expansion.md)，本文保留本次定位的历史证据。

2026-10-20。仅操作 macOS 原生模拟器；未访问相机、SD 卡或桌面原始分区镜像。

## 结论

Fn 和回放的输入映射本来正确，原厂应用因首次设置中的隐私说明尚未完成而丢弃事件。补入原厂首次设置页面并通过其原有界面完成向导后，两者产生实际页面响应。DISP 原候选 `0x1f9` 在该固件的界面事件表没有对应项，正确路径是控制轮上键 `0x3`。

本轮已打通原厂 Fn 面板和五种信息布局，以及回放的空介质提示和返回。未实现实际照片回放、取景视频、拍摄、录像或完整 CP 硬件。

| 环节 | 静态证据 | 模拟器动态结果 |
| --- | --- | --- |
| 输入注册 | InfraInput 原回调 `+0x1800da4` | 固定来源和队列收到按下/释放，原回调参数完整转发 |
| 归一化 | Fn→UI `0x8d`，回放→`0x22` | 对应状态均到达原厂处理函数；初始释放和增加一秒等待均未解除问题 |
| 事件转换 | `+0x17fa6e8` | Fn→`0x02020000`，回放→`0x02020003`，映射本身正确 |
| 过滤 | `+0x1802264`，最终检查 `+0x18119cc..+0x18119dc` | 两个按下事件均被改成 `0x20000001`（无事件） |
| 状态来源 | 属性 ID `0x2406`：`is_accepted_privacy_notice`；getter `+0x28d6f08` | 初始值 0。其数值由属性元数据和访问代码交叉定位 |
| 原厂设置 | `scr7248_0001` / screen `0x1e3` | 初始说明确认后值变为 1，完成向导后变为 2；随后 Fn 和回放事件不再被过滤 |

Sony 的 [A7R5 帮助指南第 60 页](https://helpguide.sony.net/ilc/2230/v1/en/print.pdf#page=60)也将 DISP 分配到控制轮上侧。这与本次固件表和动态画面一致；手册自身不代替模拟器验收。

菜单 Setup→Privacy Notice 是查看模式，`selecting_item_id=0x472`，按 OK 不改变接受状态。`0x472` 是菜单项 ID，不是 screen ID。固定补入入口只允许初始菜单 `screen=0x2d6 / selecting=0 / accepted=0`，调用原厂 `manager.open` 打开真正的初始说明，不直接更改属性、过滤器或 Backup 数据。

`BKID_APP_IS_ACCEPTED_PRIVACY_NOTICE` 的名称表索引 `0x1464` 未被证明等于存储 ID；本轮没有按该索引写设置。

## 日常使用

1. 启动独立应用，在初始 My Menu 点击“完成原厂首次设置…”。如果已经离开该初始页面，退出后重新启动。
2. 查看原厂说明并确认；Creators’ App 页面按 C4“在相机上设置”，不连接手机。
3. 通过原厂区域、日期页面。验收采用模拟器的默认测试区域和 2022-01-01 测试日期；这些不是用户真实所在地或时间。温度提示选 Set Later，最后确认关闭说明。
4. 黑色启动页按 MENU，返回菜单后再按 MENU，进入拍摄信息页；Fn、DISP、回放按钮随上下文启用。
5. Fn 中方向键选择，确认进入项目；部分项目在智能自动模式下不可用，提示是原厂行为。确认关闭提示，Fn 或 MENU 返回。DISP 每次点按切换布局。
6. 回放显示未插卡提示，再按回放返回。退出使用客户端退出按钮，等待工作进程和 QMP 回执。

首次设置和接受状态只存在于本次 RAM，不跨启动保存。入口每次运行最多请求一次；取消向导后可正常退出再重开。客户端不会自动替用户确认说明。模拟器没有网络或物理设备直通。

## 实现与验证

- `source/guest/native-privacy-notice.inc`：可选固定请求，在 UI 线程核对管理器、页面描述符及状态后打开原厂说明。
- `source/guest/a7r5-input-trace.inc`：可选原回调、转换、过滤跟踪，默认正式客户端不开启详细跟踪。研究钩子要求准确序言指纹，继续调用原函数；跟踪写客体日志，避免串口调试文字打断快照。
- `tools/menu_bridge.py` / `input_context.py` / `input_registry.py`：显式首次设置请求、原厂状态回读、功能上下文门槛；公共输入仍拒绝任意 shell、页面编号、原始键码及独立保持。
- `client/`：首次设置入口、Fn/DISP/回放按钮、C4 在机内设置提示；正常退出沿用本次工作进程与 QMP 所有权核对。

当前 `runtime/menu-daf0f137f7a3230d.cpio` 与本轮基线逐项比较：1226 条中仅 `simulation/menu-observe-a7r5-baseline.so` 不同，原厂应用、库、资源、内核未变。见 `logs/key-dispatch/runtime-rebind.json`、`client-privacy-build.log`。旧归档和旧应用保留。

真实 Qt 验收记录为 `logs/key-dispatch/qt-function-keys.json`：最终 53 次操作、54 张原始帧与 PNG、条目层及分类层各四轮 MENU，以及 worker 退出 0 / QMP quit 0。五种 DISP 布局与已单独查看的原厂参考帧比对稳定区域；该区域只排除顶部闪烁提示。所有帧另做完整容器、摘要和逐像素转换校验，不以画面哈希变化充当功能成功。

## 续验发现的 MENU 分类层问题

窗口中执行五次 DOWN、LEFT、MENU 关闭后，再按 MENU，原厂正确返回分类层 `screen=0x2d5`。宿主只等待条目层 `0x2d6`，导致错误停止。CLI 独立复现已经取得实际分类菜单画面及重复开关；两页各有原厂注册描述符和工厂函数。

修复只让实时 MENU 等待接受这两个固定编号。分类层使用独立 `menu_group` 上下文，只开放六键导航，尚未验证的 C4 分类层帮助仍禁用。`0x2d7` 等未知页面仍失败。首次设置入口继续只允许原始 `0x2d6 / selecting=0 / accepted=0`，没有扩大该门槛。客体归档、原生 MENU 重入模拟库均未因这个修复变化。

该失败会话保留在 `logs/key-dispatch/menu-group-incident.json`，不作为成功验收。新增用例先失败、修复后通过；受影响的 27 项定向回归、53 次功能流程及原有 33 次设置/帮助流程均已重新通过，见 `menu-group-fix.json`、`menu-group-regression.log`、`qt-settings-final.json`。

macOS 窗口捕捉工具在解锁后持续报 ScreenCaptureKit `-3811`。异常工具会话已单独记录，不据此宣称完成桌面自动化人工复核。独立包改用显式 `--acceptance-functions` 固定测试模式：由包内真实 Qt 控件完成同样 53 个动作，验证原厂画面、按钮上下文及退出；日常启动不会自动执行该模式或代替用户确认说明。固定测试仅包含符号键和预期帧摘要，不接受外部脚本或键码。其结果另存 `package-functions.json`，并在包退出后独立核对原始帧。

## 限制与下一步

Fn 面板能操作不代表所有设置都能运行；模式限制和缺失传感器、镜头、CP 服务仍会使项目不可用。回放目前没有虚拟图片或虚拟介质；“未插卡”提示只能证明进入原厂空介质回放路径。DISP 的黑色背景没有传感器视频。真实拍摄、录像及恢复到实体相机均未验证。

后续如需照片浏览，应单独设计隔离的虚拟介质和测试图片，不将物理卡或原始固件镜像作为写入目标。
