# 相机功能扩展需求

用户已选择先完善菜单、按键和设置，后续接受明确标注的虚拟图像输入。当前首批限 macOS 原生模拟器，不连接相机、不操作 SD 卡、不访问或修改桌面原始分区镜像。

## 首批可交付结果

- 完整盘点菜单/控制的已验证、候选、受阻与未知状态，只有实际通过的功能启用。
- 检查原厂菜单各分类与子页导航，验证代表性设置修改、重新进入保持与还原；设置仅保存在本次客体 RAM。
- 优先从当前固件分发表建立 Fn、自定义键和拨轮候选的证据；确认消息语义及页面行为后才接入客户端。不穷举未知键码。
- 保持真实客体画面、按下/释放核对、新帧校验、独占 VM、沙箱、空闲暂停和正常退出。保留当前可运行交付作为回退。

## 验收标准

1. 新增控制必须有固件映射或分发证据、指定场景响应、释放及退出回执。只收到事件不算功能成功。
2. 设置至少验证“打开—修改—确认—重进读取—还原”的完整路径，记录真实画面；遇硬件缺失不伪造成功。
3. MENU 可反复进入退出，既有六键与 C4 场景不回归；原始容器与 PNG 一致，按键延迟保留记录。
4. 新增客体文件只进入模拟目录，重建后逐项核对原厂条目未变；交付包独立验证。

取景、拍摄、录像、回放及虚拟介质为后续阶段。虚拟传感器只提供图像输入，目标是尽量运行原厂处理链；不据此证明真实镜头、传感器、画质或物理相机功能。新硬件服务须先形成具体设计和失败边界。
