# CC1、BW／SE与相机JPG预览核对

本轮已解决指定相机JPG无法导入的问题，并将原厂CC1读取、参数应用和BW／SE控制函数接入每次AP／CP执行。参考像素开始使用本次实际返回的8个CC1系数；BW已经能输出单色。

仍有两个明确缺口：**SE的棕褐染色尚未还原；矩阵实际像素工作空间尚未在A7R5上证实。** SE当前显示的是原生零色度参数产生的单色基底，界面明确提示。原厂参数执行通过不等于原厂ISP像素通过。

## 相机JPG为什么打不开

用户指定文件 `R5_00287.JPG` 的实际情况：

| 项目 | 只读结果 |
| --- | --- |
| 文件长度 | 39,687,563字节，约37.85 MiB |
| 主照片 | 9504×6336，60,217,344像素，RGB |
| 内部容器 | MPF多图JPEG；Pillow标识为MPO |
| 第0帧 | Baseline MP Primary Image，主照片，代表图标志为真 |
| 第1帧 | 1616×1080大型缩略图，依赖子图 |
| 色彩配置 | 无ICC；EXIF ColorSpace=1，声明sRGB |
| SHA-256 | `7efc9bf92a0e52f8dd9de0c2a620f5e4c10a9db201b54e6c2b93f265edf1ad7f` |

不是超过100 MB／8000万像素限制。原导入代码仅接受格式名JPEG等，并拒绝多帧，因而把这张相机JPG挡在了解码前。

现在对MPO检查MPF索引，只接受唯一的第0帧基线主照片，不将附带缩略图或未知图像猜作主照片；其他多帧容器仍拒绝。主照片缩成384×256供参考渲染，支持大写JPG文件筛选。该图单独导入实测约0.34秒；原生Qt还验证了选图、ST／FL2／FL3／BW／SE切换和关闭，读后文件摘要相同。

文件始终只读打开；未重存JPEG、清理元数据或修改原照片。已完成渲染的JPG可能自带拍摄外观、白平衡和曝光处理，依然不能当成RAW或传感器输入。

## 原厂CC1接到了哪里

每次CP执行中增加三个原生函数输出：

1. `0x71e670`：读取风格CC1，应用原厂调整函数，生成24个int16，即三个8项端点。
2. `0x231eb8`：执行后续参数应用，输出结构 `+0x42..+0x51` 的8项当前应用系数。
3. `0x71f674`：由原厂选择器的模式生成结构 `+0x182` 的SE标志和 `+0x183` 的BW标志。

原厂调度函数 `0x719ef6` 的调用顺序确实包含选择器、CC1应用、矩阵处理、CC1色表处理及上述单色控制；不是根据函数外观名称猜测调用链。窗口仍以有边界的夹具调用这些函数，没有启动该整机调度器或提供固定成功返回。

原始控制台新增 `C`、`P`、`N` 记录，分别是24项系数、8项应用结果及两个控制标志。主机核对所有记录及长度；缺失、重复、系数错误或控制标志错位都会停止，实时入口不接受缺少这些记录的旧快照。

同一次选择中的ST基底与目标均重新执行。原机普通profile从固定种子的 `0x02a40001` 读取；FL2／FL3的54～57 profile进入候选内嵌的差分行。主机独立展开三端点差分，与原厂读取逐字节核对；当前零调整、显式夹具条件下应用结果对应第0组。端点控件仍仅作用于矩阵，不伪造真实白平衡权重。

| 外观 | 实际应用的8项CC1 | SE／BW标志 |
| --- | --- | --- |
| ST | -193,-269,-251,-51,408,554,563,563 | 0／0 |
| FL2 | -184,-263,-384,-269,356,260,563,253 | 0／0 |
| FL3 | -189,-51,-448,-269,389,283,563,285 | 0／0 |
| BW | 全零 | 0／1 |
| SE | 全零 | 1／0 |
| 六款自定义槽 | ST基底；各自候选色表另行执行与打包 | 0／0 |

18项的CC1读取和参数应用均已实际运行。不能把8项CC1当成另一个RGB 3×3矩阵，也不能因为BW／SE共用profile53就断言两个模式相同。

## 参考像素如何使用CC1

主机新增独立的带符号交叉耦合与正负增益模型，顺序先相对Gamma、再CC1色度，六款候选继续使用其原生打包银行。对已经渲染的ST-like JPG，先逆解ST色度基底，再应用目标CC1，避免重复增加饱和度。相同基底直接保持输入；零增益自然将色度变为零，不按外观名称硬编码灰度滤镜。

像素公式以公开的 [Imaging Edge逆向研究](https://github.com/Jannchie/llr/blob/main/sony_repro/PIPELINE.md) 的绿色差耦合模型为参考，本机CP到RAW的系数排列有既有静态证据。这是本项目独立实现，没有复制该项目程序或拟合染色资产。**该研究分析的是桌面引擎，不能当作A7R5机内硬件的等价证明。** 本次对原机参数的核对和对参考公式的数值测试是分开的。

因此，BW现在的去色有原生零增益和控制标志依据，但亮度权重、定点舍入、裁剪及整个处理顺序仍是参考。SE也能验证原生控制和单色基底；尚未定位并验证A7R5实际棕褐染色的逐像素语义，不借用其他相机、桌面引擎拟合曲线或通用棕色滤镜冒充完成。

## 矩阵实际颜色空间：本次结论

能继续确认的是16分区、1024对角标准基准、三端点及profile／银行读取。下游原厂 `0x71d37c` 还存在条件性转换：环境字节 `+3` 为1／2、根状态 `+0x34=1` 时，会进入 `0x71d87e..0x71dac0` 的矩阵重组及行和修正。原厂profile53另有单位阵分支。**同一个系数读取结果不能脱离运行条件就解释为通用线性sRGB矩阵。**

公开桌面研究支持在相机自身RGB域处理矩阵，但其RAW根层／外观层的取用与机内路径不能直接混同，也不能把跨机型结论直接写成A7R5像素证据。当前未完成原厂ISP像素输入输出对照，没有证明实际通道编码、色相零点与传递曲线。

因此本轮没有为了视觉效果改写已验证的矩阵系数，参考窗口继续显式标明线性sRGB和HSV分区假设。若要把“更充分的参考模型”提升为“实机色彩验证”，仍需要原厂像素级执行或受控色卡对照；当前没有申请或执行实机操作。
