# 等长内嵌矩阵：加载布局已修复，完整启动与 DAT 准入仍未通过

> 本页保留为此前的完整启动门槛记录。后续已按用户确认收缩范围，完成[矩阵内嵌整合DAT](矩阵内嵌整合DAT与验证边界.md)的离线构建；完整启动仍未通过。下文“不生成DAT”描述对应当时阶段。

本轮解决了两个实际问题：旧内嵌候选的完整引导页表异常，以及26.4MB文件超过原CP分区容量的问题。新候选保持 **17,617,008字节**，初始化data描述符不变，矩阵由新增的原入口复制器装入。已经从CP原入口运行，实际页表可读且矩阵内容正确，推进到与原厂基线相同的PLL0阻塞点。

**没有完成完整CP启动，没有生成DAT，不具备实机更新准入。** 当前不能把四核运行、原厂回调注册、矩阵函数通过或QMP退出0当作完整启动。默认参考预览切换为新等长候选，全部旧材料、失败现场与配置保留。

## 1. 旧布局实际失败在哪里

本轮新增 `tools/look_cp_boot.py`，使用保留的四核CP实验板，从 `0x108000` 启动全部四核，不启用semihosting，不写运行时ready、回调或页表。仅提供已固定的TOMCO、模拟备份种子，TOMCO沿用既有明确模拟条件 `wdt_on=0`。遇首次Data Abort后暂停并只读导出四核寄存器、页表、原厂头部影子和矩阵数据。

|---|---|---|

| 六款／Gamma CP `903bb0…` | 同样停于PLL0，构成同源对照 | `runs/native-look-cp-boot-rc4nld0z/` |

## 2. 新等长布局

### 数据与代码位置

| 项目 | 地址／长度 | 处理 |
|---|---|---|
| 文件内暂存矩阵 | 文件 `0x010cc000`，装载地址 `0x011d4000`，2304字节 | 原文件尾部零填充；在RTOS使用对应BSS全局变量前复制并清零 |
| 启动复制器 | `0x00108f40`，124字节 | 同一原引导前缀页内，避开头部影子、页表指针及引导栈 |
| 原厂ARM调用点 | `0x00108524`，4字节BLX | 复制器重放被替换的LDR，恢复callee-saved寄存器并返回原路径 |
| 运行时矩阵 | `0x01a3a000`，2304字节 | 扩展BSS覆盖这一页，无data/BSS重叠 |
| BSS大小 | `0x8a2448 → 0x8a3900` | 起点不变，映射末页扩展；全局变量地址不移动 |
| 原页表根保留位置 | `0x01a3c000` | 保持不变 |
| 原栈地址和描述符 | 保持不变 | 没有借用活动栈或移动栈 |

原data描述符 `(0xf57000, 0x117f5c, 0x107f000)` 完全不变。只扩展BSS末端到 `0x01a3a900`，页对齐后仍不碰到原页表／栈保留区。文件长度、FAT文件目录长度和原有簇链需求均保持原值，不再需要8.8MB零填充或FAT扩容。

复制器先对暂存系数做FNV-1a32一致性核对，然后搬运并清零暂存位置。重复调用时，若暂存区已被清理，只在目标矩阵仍完整时返回；两边都不匹配则停驻，不继续使用损坏系数。FNV用于偶发损坏检查，不替代外层文件摘要或升级包签名。

暂存位置在RTOS启动后可被正常BSS全局变量使用，**不能要求其启动后永久为零**。函数夹具已经检查复制后即时清零；完整引导快照验证的是目标矩阵继续存在及其实际映射。复制器代码在完整引导后也保持与候选字节一致。

### 原厂矩阵函数保持不变的部分

继续使用上轮的60字节读取辅助代码，只对profile54～57选取内嵌记录；矩阵展开、三个条件端点及校准值仍由原厂函数执行。其他profile回到原路径。没有改系数、Gamma、CC1或六款色表，也没有主机生成矩阵输出后伪装成原厂返回。

`998c6d36ddefad6ebd77a40108a11a77a418e73b6bf41dde856626b11ad54a20`

与内嵌供体系数逐字节一致。没有从主机写入目标矩阵或运行时指针，也没有使用独立函数入口替代本项观察。

## 4. 为什么仍未放行 DAT

当前完成的是**等长CP组件候选与引导阶段对照**，不是完整固件发布。

1. **完整CP服务启动未通过。** PLL0配置、复位条件和锁定语义仍缺证。原CP `0xb3d422` 会配置寄存器、置bit27并轮询bit24，现有材料不能支持直接给bit24固定成功。没有添加全零PLL占位或锁定值。
2. **外部加载链尚未实际执行。** 本工具从CP原入口运行，未执行AP／mini loader的传输过程；仍须确认其提供了CP完整文件，包括尾部暂存区。两份固定加载器中已查到固件DWORD计数日志，但不能仅凭字符串证明完整传输契约。
3. **最终整合包必须重新绑定组件。** 现有DAT构建器接受等长FAT替换，这一尺寸条件现在满足；实际FAT双解析、分区校验和、外层签名及独立解包回验尚未执行。当前研究CP前像为六款／Gamma版 `903bb0…`，不能冒充已有含type1声音改动的整合CP `fa52e3…`；最终封包须保留该既有差异并重新验收目标摘要。

保存的封包元数据表明原CP分区为24,531,968字节、原文件17,617,008字节；本轮只读取既有校验资料和构建器代码，没有读取原始分区或生成新分区镜像。`DAT-readiness.json` 单列“等长替换条件已满足”和“完整启动未通过”，总准入保持false。
