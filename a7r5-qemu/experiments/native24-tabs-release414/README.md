# 4.14修复组件满库与空库验证

固定015修复AP、原CP、两份F0图标、满24槽与合法空库两个固定BIN；全部组件在构建前及CPIO内分别核对。未知输入或其他归档条目变化立即失败，沿用原沙箱与真实Qt按钮，不写成功位，不连接设备。

满库与空库的AP虚拟器必须顺序运行。满库覆盖115次操作，空库39次；正式十二款的同组件103帧由015归档复用。`verify_receipt.py`逐帧核对PNG、检查正常退出、绑定实际CPIO组件及验证源码，生成供封包门禁使用的回执。

本实验仍以fwtool软件解码替代硬件LDEC，不证明新F0流已在机身验收；原E4初始化缺口和成像限制保留。合成13～24号配方仅验证容量，不进入升级包。
