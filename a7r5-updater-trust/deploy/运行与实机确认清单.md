# 第五模块独立部署工具v2：运行与实机确认清单

日期：2026-10-23。当前交付已完成本机故障注入、模拟USB会话、AArch64隔离QEMU和独立复制验证；**未连接相机、未创建真实操作包批准、未启动Terminal或sudo**。

## 1. 现在提供什么

`deploy.py`提供离线准备、检查、单次批准、专用Terminal启动、执行、查看结果和成功后的屏幕确认。通道沿用libJit，管理文件只有本次票据及固定`/tmp/jiritsu/libJit.so`两次上传；不写预加载、不DEBUG、不自动重试、不自动重启。

新增原生工作进程直接完成固定分区事务，不通过shell执行`dd`，不继承通用执行器的超时杀子进程行为。原始脚本、原执行工具、旧包、旧锁和失败证据保留。本模块不依赖被删除的analysis目录，也不在运行时导入旁边的a7r5-exec代码；若发现同级a7r5-exec，则仅共享其本机USB互斥锁并尊重其待恢复记录。

部署命令仅支持当前验证的macOS arm64、Homebrew LLVM／lld／libusb环境。Linux／Windows实机后端未适配。QEMU只是可选离线验证依赖，不是实机运行依赖。

## 2. 固定边界

| 项目 | 本版规则 |
|---|---|
| 机型 | ILCE-7RM5，普通USB 054c:0e0a，再同端口服务身份054c:0336 |
| 端口 | locationID=0x00100000，bus0／ports[1]；不自动换口 |
| 接口 | 与保存的两阶段完整指纹精确一致；第一对bulk端点129／2，不退选其他端点 |
| 写目标 | 只允许`/dev/cnflasha1`，252:129，25,100,288字节 |
| 完整前像SHA-256 | `acf32d30dd883ed349738e66fb081e85e0d6a3c746f5e3ca169031e8d69ed731` |
| 完整目标SHA-256 | `a3733332c2a1b336226bb9000e01665ce54bec970aefc3334b88863b80f40ceb` |
| 提交范围 | 257个initrd扇区→同步→1个p1chksum扇区→同步，合计132,096字节 |
| 预加载 | prepare时只选一个精确已知基线，前后相同，不接受两种基线间自动切换 |
| 观察时间 | 原生任务状态最多100轮、主机观察60秒；协议调度另有100秒上限 |
| 超时 | 停止主机观察，**不杀写入工作进程**；其状态可能未知，不重跑、不STOP |
| STOP | 成功终态、日志、25MB完整回读、预加载和重复终态全部通过后才一次 |
| 生命周期 | 每个包只能执行一次，永久ATTEMPT_LOCK；失败保留PENDING_RECOVERY，不提供强制解除 |

`profile-historical.json`是历史4.00、指定媒体和端口的模板，**不是本轮采集的当前机身状态**。当前相机若已更新4.04／4.05／4.06，不能因机型相同就直接使用这个版本摘要；执行前须只读核对实际版本内容、媒体和预加载，另备精确profile后重新prepare。接口指纹、加载库、端口或目标结构不同则停止，不能手工放宽校验。

如果当前完整分区已经等于目标，勿重复部署。原生任务发现完整前像不符时会在第一笔写入前拒绝；它不会自动把“已是目标”转换成继续执行，也不会自动退出未知服务会话。

## 3. 独立复制与依赖

可把整个a7r5-updater-trust模块复制到其他目录。复制后从原始镜像重新prepare，不沿用带原目录绑定的旧run。需要自己提供精确一号明文原件；模块不含索尼签名私钥、研究签名私钥、SSH密码或完整原厂镜像。

常规依赖为Python3.12及以上，以及模块requirements.txt中的pyelftools／capstone。已冻结的PyUSB、认证参考实现及Mac arm64密码库位于deploy/vendor；实机仍需要系统libusb，构建需要LLVM和lld。需要安装这些系统依赖时应另行审阅，本轮没有安装或改动系统依赖。

```sh
MOD="/path/to/a7r5-updater-trust"
SOURCE="/path/to/cnflasha1.original.img"
PY="/path/to/python"

# 若尚无环境，创建专用环境；已有环境可跳过这三行。
uv venv "$MOD/.venv" --python 3.14
uv pip install --python "$MOD/.venv/bin/python" -r "$MOD/requirements.txt"
PY="$MOD/.venv/bin/python"
```

也可设置`A7R5_PYTHON`再运行deploy/deploy.sh。包装器优先用模块自身.venv，存在原工程时才回退到工程.venv。工具不全局安装Python包。

## 4. 离线准备一次性包

以下命令不枚举USB、不运行ioreg／diskutil、不连接SSH、不提权：

```sh
PROFILE="/path/to/reviewed-exact-profile.json"
"$PY" -B "$MOD/deploy/deploy.py" prepare \
  --source "$SOURCE" --profile "$PROFILE" \
  --preload-baseline installed-boot-hook
```

若实际批准的基线是精确512个换行，最后一项改为`blank-512`。不能根据猜测选它，更不能为了通过而先改相机预加载。两种选择都不写预加载。

prepare会从原件与既有公钥完整重建目标，再生成随机新会话及`deploy/runs/<run>/`：

- `config.json`：精确版本、接口、媒体、预加载、RAM路径和期限。
- `materials/libJit.so`：无DT_NEEDED／无未定义符号的AArch64原生执行库，包含固定旧／新扇区。
- `materials/ticket.bin`：本会话票据。
- `materials/candidate.logical.img`：仅供完整回读逐字节比较的25MB候选，不是整区写入指令。
- `materials/write-plan.json`、两个生成头及`build.json`：258项计划和编译证据。
- `manifest.json`：代码资源、依赖、所有准备材料摘要及风险说明。
- `approval-template.json`：accepted=false，不能执行。
- `run-once.command`：只消费这个包，不创建新会话绕过锁；未批准时即使双击也拒绝。脚本先检查自身所在目录，复制或移动旧脚本时在sudo之前退出，不回指原目录运行。

构建只修改本机新目录，原镜像不覆盖。若构建中断，保留目录，不自动覆盖重做。准备输出中的风险短语不是已经取得的用户授权。

```sh
RUN="/prepare输出的完整目录"
"$PY" -B "$MOD/deploy/deploy.py" check --run "$RUN"
```

check仅验证封存材料，`verified=true`不代表当前机身符合。移动目录、修改配置／执行库／工具源文件或依赖以后应重新prepare，不改清单“补签”旧包。

## 5. 当前实机执行状态：未批准

交付时没有approval.json，没有对真实操作包创建ATTEMPT_LOCK，没有打开Terminal。本次只批准离线实现；下一次实机须由用户确认具体包、输入基线和以下写入／风险清单。

实际操作将包括两阶段认证／START，以及：

1. 一次票据、一次固定执行库上传，第二次上传本身触发；库构造函数解除固定库文件和票据，并创建本次claim／状态／输出。
2. `/tmp_wbshd/a7r5-trust-<run>/`中独占创建RAM日志及完整回读文件。
3. 仅提交固定258个逻辑扇区，不写物理视图、不挂卡、不写SD卡、不启动更新器或卡刷。
4. 前后精确预加载核对，不写预加载，不DEBUG。核对root、原始命名空间、容量、所有可观察的挂载和FD占用、RAM和文件大小限制。
5. 完整前像匹配后才提交；全部门槛通过才一次STOP，再观察普通USB／驱动／完整媒体并人工核对屏幕。

固定路径stat返回0x10000006不证明不存在，上传仍可能覆盖不可读既有内容；固定文件和RAM材料可能残留。258笔提交不是原子事务，掉电、驱动或日志错误可能留下部分写入；备份不等于独立救援。本模块没有证明断电持久化、官方更新兼容或损坏后恢复。

主机互斥锁只能协调使用相同锁的工具，不能代替机内全局互斥；执行期间应关闭其他相机管理工具。任何异常保持供电和现场，不自动断电、重插、换节点、重发触发、反写旧扇区或重试。

## 6. 只有取得下一次明确确认后才运行

以下命令列出实施步骤，本轮没有执行。先审阅本次config、manifest、计划、风险及离线证据，再取得用户确认：

```sh
# 将短语替换为本次prepare输出的值；不要复制另一包的短语。
"$PY" -B "$MOD/deploy/deploy.py" authorize --run "$RUN" --accept APPROVE-本次摘要

# 打开专用Terminal；只在本机Password提示中认证，不把密码写进脚本。
"$PY" -B "$MOD/deploy/deploy.py" terminal --run "$RUN"
```

授权只写本机approval；真正接入USB需要macOS管理员权限、该批准及显式`execute --device-io`三者同时满足。启动脚本只运行一次已批准的包。没有自动确认、自动提权、无批准试执行、强制换端点或自动清理锁的入口。

如果sudo已有缓存，打开Terminal后可能立即执行，所以必须先审阅并确认。不能把“没有密码提示”理解为还没有开始。

## 7. 执行结果与恢复门槛

```sh
"$PY" -B "$MOD/deploy/deploy.py" status --run "$RUN"
```

主要证据在`result/result.json`、`result/session/events.jsonl`、`native-journal.bin`、完整`partition1.logical.bin`、`session-result.json`和`host-recovery.json`。原始响应头和分块边界都会保存；协议失步后不再发送文件请求。

继承的通用session summary仍含一些历史默认字段，例如固定profile名称或写命令布尔值；以专用result中的`fixed_writes_attempted`、`trigger_attempts`、`partition_write_may_have_started`、完整回读和原始events为准，不能拿历史默认false宣称没有写入。

成功必须同时具备root DONE 0、解除加载、无活动后代、精确固定输出、522行完整原生日志、25,100,288字节全量回读与候选逐字节一致、前后预加载一致、重复终态一致、STOP恰一次及媒体恢复连续两次匹配。STOP的Pipe error不重发；只有后续主机完整恢复核对通过才可能判成功。

任务与主机恢复全部成功，再人工确认屏幕正常后：

```sh
"$PY" -B "$MOD/deploy/deploy.py" confirm-screen --run "$RUN" --screen-normal
```

该命令只保存人工回执并解除本模块的成功待确认记录，永久尝试锁和日志保留。失败时不能用它强行放行，也没有强制解除PENDING的命令。旁边a7r5-exec的待恢复记录同样不由本模块删除。

异常后不要重新执行。即使主机已恢复普通USB，原生任务仍可能完成、部分完成或阻塞，需要另行批准只读补证与恢复。主机超时不会发信号杀工作进程；**“停止”指停止后续主机请求及自动流程，不保证已进入内核的写入已经停止。**

## 8. 离线验证如何复跑

先安装独立测试依赖到同一个虚拟环境，QEMU路径可省略：

```sh
uv pip install --python "$PY" -r "$MOD/deploy/requirements-dev.txt"
"$PY" -B "$MOD/deploy/verify_offline.py" \
  --source "$SOURCE" --qemu-root "/path/to/a7r5-qemu"
```

测试默认禁止真实USB枚举、后端初始化、ioreg、diskutil、sudo、SSH及打开应用，只允许显式的无设备模拟后端。QEMU使用已校验原运行材料的隔离CPIO副本，`-nic none`且无物理设备；不修改原始镜像或原模拟器runtime。

本轮39项检查通过：

- 同一原生C扇区核心在普通文件上执行成功、错前像、短读、短写、写失败、同步失败、日志失败和回读失败，不自动补写／回滚。
- 实际Operation和分块Channel读取完整25MB，覆盖响应序号、空边界包、截断／摘要错误、终态／日志／预加载变化；失败不开放STOP。
- 实际两阶段session调度器使用明确模拟的设备和认证，完整通过才一次STOP；日志或完整回读失败为零STOP。
- 未批准、错误短语、用过的包、移动／篡改材料、夹具重标为生产均拒绝；元数据拒绝保留锁和pending，屏幕正常不能覆盖失败。
- 独立复制后可以重新prepare/check，认证依赖来自本模块，未批准execute在初始化后端之前拒绝。

两项AArch64 QEMU检查通过：精确生产库在缺少所需容量sysfs的普通文件目标环境返回FAILED 42且原件保持；仅用于隔离VM的夹具库完成实际258扇区提交、两次完整逻辑读取及关闭后重开捕获。夹具仅放开目标类型／路径、虚拟机无法提供的sysfs及占用枚举，不替代实机占用和驱动验收；其内部标记与生产不同，不能被实机入口接纳。
