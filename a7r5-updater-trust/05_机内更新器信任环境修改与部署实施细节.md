# 05 A7R5机内更新器信任环境：修改、部署与回读实施细节

日期：2026-10-23。适用对象为本项目精确绑定的A7R5／ILCE-7RM5原厂4.00一号**逻辑明文分区**，历史版本字符串为`31180_08.2025103103`。

本模块说明如何从原始镜像定位更新公钥和四个验签入口，重建与历史实机部署完全一致的信任候选，以及当时如何通过libJit提交并回读。初版恢复材料现已补齐为独立libJit专用部署工具，见第13节。**新增工具只完成离线与隔离QEMU验证，没有连接相机，没有创建实机批准。** 历史源码文本保留，实际新入口在deploy目录。

## 1. 核对后的结论与材料状态

目标是让独立更新器接纳本项目研究公钥签名的DAT。具体变化为：更新器initrd中的公钥替换、四个库的`verifyKey()`各覆盖8字节，以及容器校验更新。四个库的`VerifySignature()`原有372字节保持不变，后续包仍须用配对私钥产生有效RSA签名。

这改变了更新密钥的信任政策。不能据此声称未签名包可用、索尼官方包兼容、版本限制已经解除，或者BootROM／其他处理器的安全启动全部被关闭。

| 事项 | 本次能够给出的证据 | 边界 |
|---|---|---|
| 原始分区 | 当前保留镜像完整摘要与历史前像一致 | 不是相机当前分区 |
| 四库与公钥 | 从该镜像重新解析、按ELF符号映射偏移、检查指令和完整摘要 | 不是运行时追踪 |
| 候选 | 本轮完整重建，目标摘要与历史部署目标相同 | 不是新的设备部署 |
| 历史写入 | 会话记录保留了写入尝试及USB回收失败结果 | 不能把原事务记为全部成功 |
| 历史补证 | 当时报告记录SSH完整双读一致并匹配目标 | 原双读镜像及完整原包已不在原`analysis`路径；本轮没有重读相机 |
| 历史更新 | 用户随后报告4.04正常安装并进入拍摄界面 | 属于历史人工回执，不证明当前环境或故障恢复 |

旧`analysis/`目录目前不存在。本模块从保留会话中的明确文件创建／修改记录恢复七份源码文本，并从现存原始镜像重新构建。来源行号和恢复摘要见[恢复来源](evidence/recovered-sources.json)，移植调整见[当前适配记录](evidence/current-adaptations.json)。没有把缺失文件伪装成仍然存在。

## 3. 四个verifyKey入口和精确补丁

ELF架构为AArch64小端。四库导出符号一致：

```text
_ZN7Updater21SignatureVerification9verifyKeyEPKc
_ZN7Updater21SignatureVerification15VerifySignatureENS_13verify_info_tEPKc
```

`verifyKey`符号长度584字节，`VerifySignature`长度372字节。不要通过在任意二进制中搜索8字节序列后直接覆盖来代替定位。

| initrd内库名，均在`/usr/lib/` | verifyKey ELF VA | 映射后的文件偏移 | 保留的VerifySignature ELF VA |
|---|---:|---:|---:|
| `libupdaterapi.so` | `0x13324` | `0x13324` | `0x1356c` |
| `libsdfileinputupdaterapi.so` | `0xa9a8` | `0xa9a8` | `0xabf0` |
| `libseninputupdaterapi.so` | `0x5244` | `0x5244` | `0x548c` |
| `libuudfileinputupdaterapi.so` | `0x95ac` | `0x95ac` | `0x97f4` |

本次四个入口的文件偏移恰好与VA相同；实现仍必须经`PT_LOAD`计算：

```python
file_offset = symbol_va - segment['p_vaddr'] + segment['p_offset']
# 仅允许symbol_va落入该PT_LOAD的p_filesz覆盖范围，不能使用仅在内存存在的BSS。
```

四处原始8字节均为：

```text
fd 7b b2 a9 e0 03 01 aa
stp x29, x30, [sp, #-0xe0]!
mov x0, x1
```

替换为：

```text
00 00 80 52 c0 03 5f d6
mov w0, #0
ret
```

这是在函数建立栈帧之前直接返回0，不需要补一段栈恢复。不能只写`ret`而沿用未定义的返回值，也不能先执行原`stp`再跳到这个返回点。

固定做法为：先核对完整库SHA-256、ELF架构、符号VA及长度，再核对原8字节；修改后独立反汇编为上述两条指令，比较完整库差异范围，并核对原`VerifySignature`全部372字节不变。[二进制核对清单](evidence/binary-analysis.json)同时记录原／目标库摘要、RSA函数摘要、fragment位置及反汇编结果。

| 库 | 原SHA-256 | 修改后SHA-256 |
|---|---|---|
| libupdaterapi.so | `1b334b9fb100601b1f8bc764cd9244bb32c2906101f4b2a8c0bd2e8d684df351` | `f817ee56f78fc829a341229f89236fcf6d7ba4dd7fefab1a61da4d2d7c4a58d6` |
| libsdfileinputupdaterapi.so | `257164d1cdf88757b8c0e2ba08ac47b06c46007410af308b7a8571b442b00cd2` | `0624862064e43495d6291637d2e193d4656145d069550c58a4ce184bb9f5e354` |
| libseninputupdaterapi.so | `3240c3c70aaa645de3af74101cd4fb85263ec478cff830993a5cd4ba0a6bd704` | `6e62daaf5e4c216ab5920a841d2c5e90b7845fa7ae998b2bbbb5d7d9b7991dca` |
| libuudfileinputupdaterapi.so | `f8a622fd2b038080cf682b22febe60e379b916f72d8890687b1a6b2109c5182e` | `9d2181d1f63060271d9edc80b3580519d545529cdf753cff79796d3d36829ae7` |

## 4. 公钥、签名与容器校验

原公钥PEM：451字节，SHA-256为：

```text
8281413b5607446939613e07d020b2c7d8ee2371349099de56bc8288f7be0a43
```

目标为本模块[public-key.pem](public-key.pem)，同为451字节，SHA-256：

```text
7f65b296987df665da217de514e785f75238e686ddd18952fa425fc47e8c858a
```

目标身份是RSA-2048、指数65537。私钥保留在所有者本机，不上传相机、不放入一号分区。本模块不读取、生成或附带私钥。后续使用`a7r5-dat-tool`打包DAT时，另行使用与此公钥匹配的既有私钥；随意重新生成一对密钥，会同时破坏配对关系和这里的等长压缩条件。

`verifyKey`改为返回0解决的是该层的密钥可信检查。`VerifySignature`仍验证包签名，所以有效研究签名、合法容器和校验仍然必须满足。本轮仅证明这些函数字节保留，不通过“未改RSA代码”推导所有官方更新路径兼容。

`/p1chksum`只有下列两行，空格、路径和行末换行均应保留：

```text
8012c2a05301a39e5b4b34c96fdfc974  ./boot/vmlinux.bin
03b089579add2b8490d09c6fedc83b50  ./boot/initrd.img
```

第二行原值为`eeab3100b1f628df05695c4fcc0e52b2`，新值是**整个修改后initrd文件**的MD5。不是单个库的MD5，也不是DAT的CRC或SHA-256。内核行不变。

## 5. 如何保持SquashFS与FAT加载布局

不能把五个文件重新打一个任意布局的SquashFS，再用挂载复制替换当作同一个候选。本次目标是精确复现历史等长布局：

1. 解析原SquashFS的342个inode节点，定位公钥和四库。五个目标都完整位于fragment中，没有普通数据块列表。
2. 解压目标fragment；按节点的`fragment_offset`和原文件长度替换内容，保留共享fragment中的其他文件及空白。
3. 用zlib level9、DEFLATE、wbits15、memLevel8、默认策略压缩。需要时在明确位置执行`flush(Z_BLOCK)`再继续，**不能补零或扩展压缩流**。
4. 要求结果恰好等于原fragment的stored_size，解压器到达EOF，无unused_data和unconsumed_tail；否则拒绝。
5. 只覆盖原fragment的压缩数据区。inode表、fragment表及其他元数据保持，遍历所有普通文件，要求只有五个目标内容变化。
6. 原FAT目录项、簇链和文件长度保持。沿现有extent替换整个等长initrd和等长p1chksum，不重新分配簇；比较其他FAT文件及元数据不变。

| 库fragment | 本次压缩分段位置，均为fragment解压缓冲内偏移 |
|---|---:|
| libupdaterapi.so | 71767 |
| libsdfileinputupdaterapi.so | 不分段 |
| libseninputupdaterapi.so | 1349 |
| libuudfileinputupdaterapi.so | 321 |

这些位置不是库文件补丁偏移，更不是块设备偏移。公钥所在fragment直接level9压缩，要求同样等长。本模块绑定既有公钥，不再随机生成密钥寻找压缩长度。

最终initrd仍为9,097,216字节，SHA-256为`77e0b6d7754f1f93da2e1bbe8cfe3cbcaa22f9915a2ff31fbec1eabd332f3ca3`。原initrd SHA-256为`d08fd6f7606aef23f31f244fbda3cb335c55172d2b8d7ef84746e77139694528`。zlib或输入变化导致目标摘要不符时应停止，不能改预期摘要绕过。

## 6. 可直接执行的本机离线重建

在macOS／Linux上准备Python3.12及以上。本轮实际使用macOS arm64的工程Python3.14、pyelftools0.33、capstone5.0.9。以下是普通文件操作，不需要sudo，也不会查询USB或建立SSH。

```sh
# 替换为真实路径；模块可以单独复制，输入原始镜像由所有者另行提供。
MOD="/path/to/a7r5-updater-trust"
SOURCE="/path/to/cnflasha1.original.img"
PY="/path/to/python"

# 缺依赖时仅在专用虚拟环境安装；已有环境可省略这三行。
uv venv "$MOD/.venv" --python 3.14
uv pip install --python "$MOD/.venv/bin/python" -r "$MOD/requirements.txt"
PY="$MOD/.venv/bin/python"

cd "$MOD"
shasum -a 256 -c SHA256SUMS
"$PY" -B "$MOD/trust_tool.py" inspect --image "$SOURCE"
```

原始分区必须满足：

```text
长度       25100288字节
SHA-256    acf32d30dd883ed349738e66fb081e85e0d6a3c746f5e3ca169031e8d69ed731
```

然后在一个不存在的新目录重建：

```sh
OUT="$MOD/rebuild-$(date +%Y%m%d-%H%M%S)"
"$PY" -B "$MOD/trust_tool.py" build \
  --source "$SOURCE" --public-key "$MOD/public-key.pem" \
  --output "$OUT" > "$MOD/build-$(date +%Y%m%d-%H%M%S).json"
"$PY" -B "$MOD/trust_tool.py" inspect --image "$OUT/candidate.logical.img"
"$PY" -B "$MOD/selftest.py" \
  --source "$SOURCE" --candidate "$OUT/candidate.logical.img" \
  --public-key "$MOD/public-key.pem"
```

任一命令非零返回即停止，不继续使用输出。脚本拒绝设备、符号链接、错误原件、错误公钥及已有输出目录。输出失败会保留部分本机文件，不自动覆盖重跑。正文中的`SOURCE`必须是原件；已经部署后的目标镜像不能再次作为前像。

输出包括：25,100,288字节的`candidate.logical.img`、`write-plan.json`、各132,096字节的`before.sectors.bin`和`after.sectors.bin`、公钥及`rebuild.json`。原始镜像不复制、不覆盖。`before.sectors.bin`按提交顺序串接，**不是完整分区，也不是可以直接dd回去的文件**。

候选SHA-256必须为：

```text
a3733332c2a1b336226bb9000e01665ce54bec970aefc3334b88863b80f40ceb
```

`rebuild.json`应为`OFFLINE_EXACT_CANDIDATE_REBUILT`，五个SquashFS目标、内核保持、FAT／SquashFS元数据保持和正反重建均通过。当前恢复版本只有一套文件系统解析器；通过精确完整目标摘要与历史目标交叉约束，**没有宣称本轮重新完成历史第二套fwtool解析器验证**。

## 7. 从候选生成最小提交计划

本次逻辑分区共49,024个512字节扇区，实际差异128,469字节。按512字节写入粒度，计划为258扇区、132,096字节：

- 先提交257个initrd相关扇区，随后同步。
- 再提交1个p1chksum扇区，随后同步。
- 完整读取整个25,100,288字节分区核对，不能只核对258个扇区。

精确258项由`write-plan.json`给出；本轮重建清单另附于[258项扇区清单](evidence/reconstructed-write-plan.json)，不以首末地址推导连续范围。

| 边界 | 逻辑扇区号 | 字节偏移 |
|---|---:|---:|
| 第一个变化initrd扇区 | 828 | 423936 |
| 最后一个变化initrd扇区 | 17909 | 9169408 |
| 最后提交的校验文件扇区 | 30945 | 15843840 |

每项包含完整512字节前／后SHA-256及阶段。两阶段不是原子事务；先写initrd再写校验无法消除中途断电风险。132,096字节是逻辑提交量，不代表闪存实际写放大已测定。

## 8. 历史部署使用的实际通道与门槛

### 8.1 节点与视图

历史目标只有`/dev/cnflasha1`，块设备号`252:129`，容量25,100,288字节。`/dev/nflasha1`当时是该节点的别名。`/dev/pnflasha1`为物理视图`252:1`，父磁盘`252:0`，历史起点128扇区。**逻辑镜像偏移从0开始，不能加128扇区，也不能改写物理节点。** 具体身份每次部署前必须重新确认，历史值不是另一台相机的授权目标。

写入进程要求UID／EUID=0，`/proc/self/ns/mnt`与`/proc/1/ns/mnt`相同，并核对精确预加载原字节；所有可枚举进程的挂载视图和FD中不得占用252:129、252:1或252:0。读取权限不足、枚举损坏或截断均拒绝。检查有竞争窗口，不能称为完全排除所有内核占用。

### 8.2 libJit触发

历史专用操作先核对版本、`/usr/lib/libJiritsu.so`摘要、预加载和固定路径状态；两阶段认证／START后，只上传一次新会话票据及一次固定执行库`/tmp/jiritsu/libJit.so`。固定路径上传本身触发加载，不写预加载、不发DEBUG。

文件通道返回`0x10000006`只说明stat失败，不能证明固定路径不存在；上传仍可能截断不可读的既有文件。票据、库、claim及结果可能残留。这些管理文件风险必须与分区写入一起列入新会话清单，不能自动清理旧文件后重跑。

已有静态记录中加载库233,416字节、SHA-256为`ea2d9ba9dbeb56fc11ad88be7b5c30b6b237f8ccc55ce9f24c02546eb0ba07b1`；固定路径比较调用点`0x9bf4`，`dlopen`调用点`0x9c1c`，`dlclose`调用点`0x9c3c`。这里是管理载荷入口，**与上文四库的更新验签入口不同**。不能将它们混为同一个函数。

### 8.3 原生任务在第一笔写入前检查

历史`native_gate.c`逐项检查：

1. root身份、原始挂载命名空间及预加载原内容；sysfs容量字符串为`49024\n`。
2. `MemAvailable`至少65,536 KiB；`/tmp_wbshd`必须为tmpfs，剩余空间大于分区长度加1MiB，文件大小限制允许完整回读文件。
3. 在独占创建的RAM会话目录中创建日志；核对进程挂载和FD占用。
4. 仅以`O_RDWR|O_EXCL|O_NOFOLLOW|O_CLOEXEC`打开`/dev/cnflasha1`；`fstat`核对块类型和rdev，`BLKGETSIZE64=0x80081272`核对容量。
5. 完整读取原像并核对`acf32d…`；校验内嵌旧／新扇区、偏移、顺序及边界。

若完整前像已是`a37333…`，说明与该目标一致，不应重复部署；先保留只读证明，转入后续DAT配对及版本准入分析。既不是精确原像也不是目标时，不能用“看起来仍是4.00”放行。

### 8.4 固定扇区提交和完整回读

每扇区先`pread`512字节核对旧扇区，在独立日志写入并同步`WRITE_BEGIN`，只发一次512字节`pwrite`；成功记录`WRITE_RETURNED`。阶段结束同步并记`PHASE_SYNC_RETURNED`。短读、短写、同步或日志失败立即停止，不补写、不自动回滚。

完成后同一FD读完整分区，关闭目标，再重新只读独占打开，重新核对设备和容量，将完整分区写到RAM回读文件并核对摘要。日志必须依序包含：

```text
PREIMAGE_VERIFIED
(WRITE_BEGIN → WRITE_RETURNED) × 257
PHASE_SYNC_RETURNED
WRITE_BEGIN → WRITE_RETURNED
PHASE_SYNC_RETURNED
FULL_LOGICAL_READBACK_MATCH
REOPENED_FULL_CAPTURE_MATCH
COMPLETED
```

主机还需回收输出、日志和**完整RAM分区副本**，比较长度、SHA-256及所有字节，并核对预加载未变、重复终态一致及无活动后代，才开放一次STOP。STOP后只观察主机普通USB、驱动、媒体，再人工核对屏幕；不自动重启、写卡或开始升级。

## 10. 如何在未来重新组织一次部署

这一节是具体实施清单，**不是本轮运行命令或新的实机授权**。先完成第6节本机重建。若要复用到另一现场，应逐项形成新材料：

1. 由SSH只读采集当前精确原像、版本、节点身份、容量、预加载、命名空间和占用；连续双读完整镜像。读取失败可按另行允许的方式补证，但不能改为写入试探。
2. 精确分类：已等于目标则不写；精确原像才可能使用本配方；其他状态停止并另行分析。不得仅根据文件名或机型套用旧地址。
3. 重新绑定新会话、物理端口、固件和加载库摘要、预加载原字节、258项计划、RAM路径、任务期限与失败策略，审阅新专用载荷并离线演练。
4. 单独确认允许的一号分区写入和固定管理文件上传、一次触发、完整回读及STOP门槛。历史授权、旧锁和旧清单不直接复用。
5. 采用原始视图中的专用原生任务执行第8节流程，SSH继续承担读取与补充回读；不把SSH私有账户／挂载视图作为默认写入口。
6. 内容验收、USB／媒体恢复和屏幕核对通过后，再讨论DAT签名身份、版本准入、写卡及原厂菜单更新。信任部署与卡刷分别验收。

**不要用以下方式替代专用事务：** `dd`整区覆盖、挂载FAT后盲拷initrd、手工只改公钥不改校验、向物理节点写明文、把25MB回读塞进32KiB通用输出，或把旧C片段粘进普通shell。

当前`a7r5-exec/libjit.sh`默认准备后直接访问相机，只有`--prepare-only`才离线；当前工具已在2026-10-23调整了运行与门禁逻辑。旧专用事务要求的原生写入、日志、重开回读及“超时仅停止观察，不杀写入工作进程”语义，不能用通用shell任务的成功退出代替。本模块没有调用该工具，也没有为方便复用而取消旧门槛。

## 11. 失败停止与恢复

一号分区属于更新器／启动相关材料。失败可能使更新入口或其他管理通路不可用；本机有镜像不等于具备独立写回救援。多笔提交不具备原子性，`fsync`及逻辑读回一致也不等于已验证断电持久化。

| 情况 | 处理原则 |
|---|---|
| 第一笔目标写入前失败 | 保留现场；在明确未写入、载荷状态及预加载已核对后另行决定受限退出 |
| 触发后超时或通道错误 | 认为写入可能发生；保持供电和连接，不按退出码猜测工作进程已停止，不自动STOP、重试、重启 |
| 完整现场等于原件 | 不需要反写原分区；另查管理会话、预加载和服务状态 |
| 完整现场等于候选 | 不重复部署；若要撤销，需以该候选为新前像准备恢复事务 |
| 仅由已知旧／新字节混合 | 只说明变化来源受限，不代表可启动；另行组织恢复，不盲套逆补丁 |
| 扇区外变化、未知字节或短镜像 | 不覆盖现场，不换节点；先确认读取可靠性和变化来源 |
| SSH／USB均不可达 | 需要事先独立验证的救援；本模块没有该验收，不自动断电尝试 |

对本机完整现场镜像可只读分类：

```sh
"$PY" -B "$MOD/trust_tool.py" classify \
  --source "$SOURCE" --candidate "$OUT/candidate.logical.img" \
  --observed "/path/to/current-full-logical-readback.img"
```

工具只返回`EXACT_ORIGINAL`、`EXACT_CANDIDATE`或`KNOWN_OLD_NEW_MIXTURE`；未知变化直接拒绝，不提供自动修复。已知混合允许扇区内部存在旧／新字节混合，不能据此推算完成扇区数。

撤销应恢复成组匹配的原公钥、四库initrd及p1chksum，不能只改回单个公钥。恢复信任环境不会自动恢复已刷入的AP／CP、个人设置或版本。整份历史原像也不是可用于任意后续版本的通用回退包。

## 13. 独立部署工具v2

[运行与实机确认清单](deploy/运行与实机确认清单.md)给出完整新流程：prepare→check→用户确认后authorize→专用Terminal→单次执行→结果／媒体核对→人工屏幕确认。prepare/check不初始化USB；不能用通用libjit.sh默认执行行为代替这个流程。

新载荷直接运行固定原生扇区事务，不执行shell写盘，也不因主机超时杀写入工作进程。主机只有在完整终态、522行日志、25MB完整回读逐字节匹配、预加载和重复终态全部通过后才开放一次STOP。失败保留尝试锁及待恢复记录，不自动重试、回滚、重启或继续卡刷。

本轮实际完成39项本机检查、两项断网无物理设备QEMU验证和独立复制后prepare/check／未批准拒绝验证。QEMU中的普通文件目标不能证明真实块设备安全；当前准备包使用历史profile示例，仍需实机前只读核对并绑定当前版本、预加载和媒体。本轮没有批准或尝试设备操作。
