# GitHub 发布整理与本地保留

本次范围：清理可确认的临时构建产物、缓存和冗余记录，准备源码发布边界；不连接相机、不操作存储卡、不上传 GitHub、不创建提交。不删除模块源码，不更改信任规则和真实设备批准门槛。

## 清理规则

- 删除信任模块离线验证生成的三个 `probe.cpio`，保留对应结果、日志和生成代码。缺失固定 QEMU 输入时，需要补齐材料才能重新生成。
- 删除 QEMU 历次清理记录中两份冗长的 `retained-before.json`，保留其他摘要和验收记录。
- 删除普通开发目录的 Python/pytest 缓存及 `.DS_Store`，不递归清理最终 `.app`、`dist/`、`prepared/`、私钥目录和固件原件。
- 清理 Rust 已无实际构建内容的残留 `target/` 目录。

开发虚拟环境是当前脚本的必要运行环境，继续本地保留并排除入库；完整删除它们会使现有入口先要求重新安装依赖。本次没有为减少磁盘体积而破坏这些入口。

## 本地保留但不入库

- 全部 `a7r5-firmware-images/`，包括官方 DAT、分区原像和校验资料。
- 历史 SSH 私钥和最终 `a7r5-desktop/dist/final/` 测试包。当前研究签名私钥经持有人随后明确确认，改为随源码保留；其他私钥没有获得这一发布授权。
- 当前构建需要的 SDK、加载库夹具、QEMU 原始源码归档和 Desktop 准备材料。
- 所有真实设备包、失败现场、批准、活动状态和恢复锁；不因公开发布而清空安全状态。
- 历史回执、旧封印与包含本机身份的记录。这些材料可以辅助本地研究，但不代表新源码副本的验收结论。

精确删除项、保留材料的清理前后摘要，以及本机完整验证日志保存在忽略目录 `.local/github-preparation/`。对外的简短验证结论见 [验证记录](verification.md)。

## 源码发布检查

根 `.gitignore` 统一排除以上本地材料，仅对 `a7r5-dat-tool/keys/research-signing-private.pem` 增加明确例外。`scripts/release_check.py` 用 Git 实际规则列举候选文件，按精确路径与固定摘要允许这一个研究身份；其他私钥正文、固定口令哈希、开发机用户路径、可执行文件魔数、禁止路径和超过项目单文件 10 MiB 门槛的文件仍被拦截。这个大小门槛是项目的源码管理规则。

检查器不输出凭据内容，不扫描或改写 Git 历史。已建立仓库时会检查被跟踪的忽略文件；未经审阅的 `git add -f` 不能作为发布流程。第三方代码中的其他类型令牌和二进制编码秘密不保证由本检查器覆盖。

可使用 `--export` 在项目外生成检查通过的源码副本；输出目录必须不存在，复制后验证摘要。本次清理不会自动清除该源码副本，也不会将其上传。
