## 干净源码副本

由发布检查器在工程外导出源码，未带入私钥、固件、SDK、准备目录、操作包或原 `.venv`。使用 `UV_OFFLINE=1 sh scripts/bootstrap.sh` 从本机 uv 缓存建立新的两个虚拟环境，未借用原工程的 Python 包目录。

先执行发布测试 5 项、DAT 测试 20 项、四项功能合成测试 9 项，全部通过。缺少真实私钥时运行 DAT 的依赖安装入口，也正常完成。

随后只为集成验证补入指定官方 DAT、完整一号分区前像和 libc SDK，按固定包重建 SFTP 依赖；仍没有带入真实研究私钥。执行 `prepare.py payloads` 与 `prepare.py features`，6 个载荷模板和 16 组功能补丁全部与当前工程原有构建回执一致。

客户端集成测试的源码准备步骤为：将导出副本中的 `a7r5-desktop/engine/` 复制到其 `prepared/engine/`，将同一副本中的 `a7r5-updater-trust/deploy/vendor/engine/sources/workspaces/j/work/sony-pmca-re/` 复制到 `prepared/engine/vendor/pmca_source/`，再生成载荷模板。首次漏复制 PMCA 源码时有 7 项缺文件失败，补齐这项准备后，19 项全部通过。没有为通过测试而替换真实会话实现或放宽断言。

## 已知限制

- QEMU 固定清单的 initrd 与 DTB 在整理前已经缺失。本轮只验证输入缺失会明确报告，没有启动 QEMU，没有恢复客体或绕过清单。
- 新克隆的源码不带旧设备记录、原厂库或本机材料封印。依赖它们的旧入口须先按模块要求重新准备，不能直接沿用旧批准。
- Rust 源码未修改；本轮没有再次运行 Cargo 全量编译，以免重建刚清理的构建缓存。验证了现有最终包，不能把它称为本轮重新编译的安装包。
- 发布检查针对当前 Git 候选文件，不扫描 Git 历史，也不替代完整的秘密扫描或第三方材料分发授权审查。统一开源许可证仍由权利人决定。

完整日志、保留材料核对结果和逐项删除记录位于本地忽略目录 `.local/github-preparation/`，不混入公开源码。
