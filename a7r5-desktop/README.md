# A7R5 Studio 本地测试版

> GitHub 源码发布说明：当前研究签名公私钥经授权随源码保留；完整固件、其他私钥、SDK 二进制、真实操作包和历史验证现场仅留本地；旧链接可能指向未入库材料。环境与输入要求以 [根目录构建说明](../docs/build-inputs.md) 为准，本轮验证见 [验证记录](../docs/verification.md)。

Rust + Tauri 的 Mac Apple Silicon 客户端。随包携带 Python、固件处理与 USB 库、预编译机内载荷、当前研究私钥和配对公钥。用户无需安装 Python、Node、Homebrew、LLVM 或 QEMU。最低构建目标为 macOS 14；本次仅在当前 macOS 27.0.1 主机验证。

最新交付批次为 `dist/client-update-20261024-01/`，包含应用、ZIP、更新说明、使用说明、包描述和离线验证回执。`dist/final/` 及其他旧包保留。当前更新汇总见[2026-10-24客户端更新说明](docs/updates-20261024.md)；不要将旧包或旧实机回执当作新版本验收结果。

## 用户入口

先正常退出旧客户端，再解压最新 ZIP 并双击 `A7R5 Studio.app`。这是临时签名的本地测试包，尚无 Developer ID 签名、公证或完整实机验收；请保留整个应用包。现有任务记录沿用原目录，不通过删除记录或锁文件来切换版本。

| 页面 | 能力 | 使用方式 |
|---|---|---|
| 相机维护 | 完整备份更新器分区 | 相机选择 MSC，点击备份，阅读提示后在打开的终端输入 Mac 登录密码 |
| 相机维护 | 更新研究签名信任环境 | 普通模式选择已完成原厂备份的 `result.json`；强制模式使用独立按钮并阅读覆盖风险 |
| SSH 服务 | 上传三个程序并启动 SSH | 输入两次相机 SSH 密码，点击启动，再到终端输入 Mac 登录密码；上传与启动共享一次 USB 会话 |
| SSH 服务 | 停止本应用的 SSH 实例 | 在同一电脑选择 MSC，终端授权后按本次端口定位并核对原实例；不会停止未记录的其他实例 |
| 固件工坊 | 四项功能自由组合 | 选择指定官方 4.00 原包，选择新输出位置，勾选功能并封包 |
| 任务记录 | 回执、备份、失败现场和恢复确认 | 打开对应任务；完成机内操作后核对 MSC，再人工确认屏幕 |
| 使用指引 | MSC、管理员授权与卡刷说明 | 每次操作前阅读提示；生成 DAT 旁另附独立 HTML 说明 |

SSH 密码支持 8–128 个非控制字符、最多 512 个 UTF-8 字节。明文不写入请求、文件或命令参数；Rust 内部生成固定 10000 轮 SHA-512-crypt。任务材料中会保留机内认证所需的口令哈希和配置载荷，目录为本人可读写。备份、信任更新、SSH 启动和停止的 Mac 管理员密码均由终端内的系统 `sudo` 接收；客户端不接收或保存 Mac 密码。

SSH 服务的账户为 `root`，端口为 `2222`。IP 需要依据相机实际网络环境确定；应用不自动配置或探测网络。使用 SSH 客户端连接时核对任务目录 `device/session/host-public-key` 中的已验证主机公钥，不要禁用主机密钥检查。开启服务的回执不等于网络登录已经通过。

应用启动不枚举相机。用户点击设备动作、阅读准备提示并继续后，才申请管理员权限，观察 MSC 主机元数据并开始 USB 操作。不存在独立检测按钮或离线模式。

## 支持边界

- 仅支持 ILCE-7RM5、指定 4.00 版本文件与加载库、已知接口格式。普通安装要求已适配的完整原厂前像；显式强制模式跳过此前像限制，仍限定固定扇区与写后核验，不保证未知已有修改兼容。
- 官方 DAT 大小为 754525608 字节，SHA-256 为 `51e1176a255a9a4b4782dfbcfa6c5f332b71173bdfe9ed2bcf4fca6bcbc6c2e2`。
- 完整分区原像 SHA-256 为 `acf32d30dd883ed349738e66fb081e85e0d6a3c746f5e3ca169031e8d69ed731`；目标为 `a3733332c2a1b336226bb9000e01665ce54bec970aefc3334b88863b80f40ceb`。
- 每次新任务、SSH停止和独立MSC检查都重新识别当前唯一A7R5及其端口；不沿用历史端口。一次执行中的USB会话仍绑定本次设备。
- 信任更新非原子：完整校验前像、258 个扇区的写入日志、同步、完整回读和再次打开后的捕获，都不能保证任意断电或硬件故障下恢复。
- 四项为 FL2/FL3、六款自定义滤镜、关闭 NTSC 提示、电子快门声音。关闭某项恢复其入口，但部分组合仍共享必要的数据布局。全不选同样使用研究签名。
- 输出版本沿用既有客户端的 `4.06` 默认值，可按两位小数设置；只改变容器标识，内容仍来自指定官方 4.00，不代表同号官方固件功能，也不保证相机接纳。
- 卡刷接纳、相机启动/功能、真实 SSH 网络登录、管理员授权到实际 USB 接管、真实恢复均未在本轮验证。测试不会自动操作存储卡或启动卡刷。
- 现有研究私钥按用户授权随本地包携带。没有生成新身份，也没有公开上传此包或密钥。

## 操作提示与恢复

每次 USB 操作前：开机、可靠数据线连接电脑、在相机选择「海量存储器 / MSC」。尚未开始且没有模式选项时，才建议重新拔插。执行中或结果不明时保留连接、供电与现场，不自动重试。

完成机内验证并成功返回唯一 STOP 请求后，只观察主机元数据，等待本次媒体和驱动连续两次稳定恢复。历史待恢复标记与屏幕确认不再阻止新任务；旧`pending.json`和任务记录保留，不自动清理。当前执行中的设备任务仍互斥；已有SSH实例记录不再阻止备份、普通信任安装或强制安装。每次维护操作重新识别当前MSC连接，活动SSH记录与历史任务保留。SSH重复启动和停止仍按原实例管理，维护操作不会自动停止SSH。图形入口、后台和终端备份脚本采用相同规则。

STOP返回明确的libusb `-9`（STALL）时，保留原始错误，且只在机内全部验证完成、STOP仅发送一次后观察本次MSC恢复。媒体和驱动连续两次稳定恢复才能确认退出；其他错误、机内验证不完整或恢复失败仍为失败，不补发STOP。备份文件已经完整校验时独立记录`backup_complete`及其路径，即使退出未确认也保留这份完整备份，不把整项任务自动判为成功。

接口接管仅在首次服务命令发送前、本进程已分离驱动且 macOS 返回 `-99` 时，允许对同一端口的原接口最多申请三次，间隔 250 毫秒。其他错误、服务启动后的错误及持续失败均停止；不重置、不换设备、不重发服务命令。原始接管异常、回收异常及失败阶段分别记录。

MSC与屏幕检查是可选的任务记录操作。已核实完成或明确未启动服务的任务可单独重新检查当前MSC连接；检查以当前唯一A7R5的端口、媒体和驱动为基线，旧任务基线保留。执行中的位置变化、未知机型或未适配USB模式仍停止本次操作，不自动换设备或重发命令。SSH停止跨端口时仍核对原会话号和已验证主机公钥。成功启动/停止的SSH活动记录即时更新，不依赖人工屏幕确认。

本次回归命令、结果和实机验证边界见[USB接管与失败恢复离线验证](docs/usb-claim-recovery-verification.md)。

历史记录不阻塞与每次实时定位的后续调整见[动态USB离线验证](docs/dynamic-usb-verification.md)，该调整取代前一版本的全局待恢复门禁。

管理员授权用于 USB 接管；固件封装不需要管理员权限。用户取消系统授权时不执行设备事务。未知授权助手结果保留待恢复状态。

备份、信任更新、SSH 启动和停止按钮会自动打开终端授权，结果返回原任务卡片。终端尚未启动时，120秒后取消本次请求，迟到窗口不能再执行它；终端已经开始认证时，不套用此启动超时。授权取消、监督进程中断和未知回执均保留原记录，不重试设备动作；结果未知时仍继续接收迟到的固定助手回执，并同步核对 SSH 活动实例。完整回执原子发布，避免轮询读到半份JSON。授权命令只能执行当前应用的四种固定设备动作，不安装常驻助手、不调整系统权限。

卡刷说明会提示：将 DAT 命名为 `BODYDATA.DAT`，放到 SD 卡根目录并插入 SLOT1，从机身版本菜单进入软件更新。官方 4.00 参考状态是黑屏、存取灯 1→3→5 次分组闪烁、约 6 分钟后重启。异常的 5 慢+6 快、7 慢+7 快与正常进度分开说明；自定义包没有据此自动拔电或重复刷写的流程。

来源：[索尼中国 4.00 升级说明](https://service.sony.com.cn/download/firm/00003037.html)、[Sony A7R5 更新说明](https://www.sony.com/electronics/support/e-mount-body-ilce-7-series/ilce-7rm5/software/00292267)。这些现象描述官方更新包，不能作为自定义包实机成功的证据。

## 工程结构与实现

| 目录 | 职责 |
|---|---|
| `src-tauri/src/runtime.rs` | 资源摘要、固定动作、原生口令哈希、系统授权助手、提权隔离副本和退出 root 后导出 |
| `src-tauri/src/authorization.rs` | 四种设备动作的终端授权、取消令牌、监督进程及回执轮询 |
| `src-tauri/src/tasks.rs` | 单实例/任务锁、任务回执、待恢复状态、SSH 活动记录和人工屏幕确认 |
| `web/` | 无前端构建依赖的中文界面；自定义 Tauri 命令与本机文件选择 |
| `engine/device.py` | 分开的备份/更新与合并 SSH 事务；完整门槛通过后才认为任务完成 |
| `engine/host.py` | 当前端口绑定与 MSC 恢复观察；只在显式动作后运行 |
| `engine/firmware.py` | 16 种预构建补丁组合、原 DAT 引擎和卡刷 HTML |
| `sources/` | 原生载荷源码副本；原始模块不修改 |
| `scripts/` | 构建材料、固定 USB 库、依赖版权、封装与独立沙箱验证 |
| `tests/` | 真实会话调度器+协议替身、普通文件写入故障注入、路径/状态契约 |
| `prepared/` | 可重建运行材料；不包含原官方 DAT 或开发机分区镜像 |
| `verification/` | 载荷一致性、组合、测试、构建和独立运行证据 |

Rust 不重写既有 Senser 协议。管理员助手只接受四种固定动作，先把摘要匹配的引擎复制到 root 私有目录后运行；导出前退出 root 身份。用户路径不作为任意 shell 命令执行。SSH 的 load/start 两阶段共用同一 Channel 的序列号及失步标志，不能在阶段之间重建同步状态或发送 STOP。

载荷可变字符串位于独立 `.a7r5_cfg` 段，运行时只替换等长会话号与口令哈希。各模板均验证替换后与另一份独立重编译结果逐字节相同。新源码副本还把 AArch64 `O_NOFOLLOW` 修正为 32768；原封存源码不变。该修正与配置段均只有本机/静态证据，没有据此宣称机身动态加载通过。

用户任务保存在 `~/Library/Application Support/local.a7r5.studio/tasks/`。备份任务的外层 `result.json` 包含完整备份路径；不要选 `device/result.json` 代替外层结果。活动记录只说明本应用过去的操作，不证明相机现在仍运行服务。

相机维护页可选择“备份保存目录”。未选择时沿用任务目录；选择后，客户端在目标目录中新建唯一的 `A7R5-backup-<任务号>/`，将核实的完整备份另存为 `partition1.logical.bin`，同时保存可用于后续操作的 `result.json`。开始授权前会创建该独立目录，检查路径及写权限；完整文件另存后再次校验长度与摘要，不覆盖现有文件。目录路径不传给管理员设备助手，另存由普通用户进程完成，任务中的原始备份和回执保留。任务卡片显示另存位置并提供“打开备份目录”；另存失败会明确提示，不改变机内任务结论，也不重试设备操作。已获完整备份但清理或退出失败时也可另存，导出的回执继续保留原失败状态。快捷脚本的 `--backup` 入口仍沿用任务目录。

## 开发构建和验证

日常开发可双击仓库根目录的[启动A7R5客户端.command](../启动A7R5客户端.command)，无需生成 ZIP 或安装包。脚本按当前 Python 引擎、Rust 和网页源码摘要判断是否重新编译，缓存位于 `.local/studio-dev/`；未修改源码时复用缓存，但每次仍执行离线自检。需要现成的 `prepared/engine/`、项目 `.venv`、Rust 与 Xcode Command Line Tools；缺少材料或离线依赖时会停止，不自动安装或联网下载。

```sh
./启动A7R5客户端.command              # 按需编译、自检后打开客户端
./启动A7R5客户端.command --selfcheck  # 仅按需编译及离线自检，不打开界面
./启动A7R5客户端.command --backup     # 正常退出GUI后，通过终端授权备份，不更新信任
```

运行时仍需 `.app` 目录结构，因此脚本生成本机开发运行缓存并临时签名，不执行发布封装。构建仅在缓存副本中同步与封存引擎，不改原 `prepared/engine/`、旧安装包或任务记录。界面继续使用原任务记录目录及单实例锁；更新前请先正常退出旧客户端，脚本不会强制关闭程序或清除锁。引擎以外的预编译载荷或第三方运行材料发生变化时，需先按下方流程重新准备与封存材料，再启动。首次编译会较慢，后续复用编译缓存。

开发入口会在新缓存中重编捕获、工作区诊断和信任更新模板，因此构建还需现有 LLVM/lld 和项目环境内的 `pyelftools`；SSH与固件模板沿用已封存材料。信任模板从已封存的258个前后扇区重建，原厂前像与完整候选摘要门槛不变。新捕获模板将完整备份保存为1532个16KiB的RAM分块，客户端核对各块长度、合并后的完整摘要及重复终态后才确认备份。准备正式包时需重新运行 `prepare.py payloads`，不能仅同步Python源码而沿用旧维护模板。

2026-10-24的16KiB候选版用于减少单个长响应内的传输边界：每个完整分块响应含4字节结果码，共16,388字节，低于32KiB协议块；底层仍按8KiB读取。捕获模板、清理模板及配置均带新版布局标记，混用旧模板会在上传前被拒绝。16KiB完整备份及旧版强制安装1532块回读的固定请求预算为4096，新版强制安装9块回读、普通信任更新等其他动作和旧96块只读接续为512；序列号连续递增，不清零绕过上限。路径白名单按本次格式限定1532块或9块及必要控制文件。
