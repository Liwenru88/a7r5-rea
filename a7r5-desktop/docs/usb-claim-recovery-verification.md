# USB接管与失败恢复：离线修复验证

本轮只修改客户端源码并运行离线测试。没有连接或枚举真实相机，没有执行管理员授权、相机协议、存储卡操作或真实任务恢复；现有应用包未替换。

## 修复内容

- 接口等待默认关闭，由会话层仅在首次服务启动前显式开放。本进程已分离驱动、macOS返回`-99`且端口未变时，同一接口最多申请三次，间隔250毫秒。其他错误、端口变化和服务启动后的错误立即停止，不重置设备、不换设备、不重新认证或重发服务命令。
- 接管原始异常与驱动回收错误分别记录，回收错误不覆盖原异常。会话保存失败阶段、底层错误码、完整调用栈及相机协议请求尝试计数。
- 有完整“服务未启动”证据的失败任务可以只观察主机MSC元数据，核对原端口、媒体与驱动连续两次稳定恢复，再由用户确认相机屏幕正常。原错误和`task_complete=false`保持不变，原待恢复记录归档，永久尝试锁和日志保留。
- 兼容带有完整明确阶段旗标的旧失败回执；缺失阶段字段、已启动服务、已有协议请求或恢复证据不完整时，不开放失败任务结束入口。浏览任务不改写这些旧回执，也不自动解锁。
- 失败的SSH启动或停止任务结束恢复状态时，不创建或删除活动SSH实例记录。归档中断后可以复用一致的确认记录继续完成，拒绝覆盖不一致记录。

## 原问题复现

修复前，Python定向回归有4项按预期失败：短暂接管错误未等待、回收异常覆盖原始异常，以及旧/新两种未启动服务回执无法进入恢复检查。Rust状态回归有3项按预期失败：缺少恢复能力字段、无法结束早期失败状态、SSH早期失败恢复被拒绝。

修复后使用内存USB设备执行真正的会话与接口接管实现，覆盖首次接管持续失败、回收同时失败和第二阶段接管失败。首次失败没有发送START或认证命令；第二阶段失败不等待重试、不开放恢复结束入口，也不追加STOP。
