# A7R5 4.00 固件转存实施：默认19项，扩展模式37项

## 1. 目标、适用范围与当前状态

目标是在一次批准的服务会话内，把相机内部所选闪存视图转存到指定备用卡，再从卡中直接取回目标文件到Mac。**默认标准模式19项，共1,872,691,200字节（1.873GB / 1.744GiB）**，即17个明文分区加2个启动区，与a7c2-re口径一致。扩展模式需显式选择，才导出37项共5,691,539,456字节（5.69GB / 5.30GiB）。

参考的是 a7c2-re 的“服务文件通道 → 预加载载荷 → 一次 DEBUG → root 工作进程 → 闪存只读转存到卡”流程。Mac 适配和 A7R5 差异已经处理，不能原样运行 A7C2 的 Linux 格式化脚本、卡回退逻辑或旧载荷。

历史37项转存已在本人的A7R5 4.00上取得DONE 0，并在Mac独立验收成功。**第二版19/37项模式选择载荷，以及按文件直接取回入口，仅完成离线验证；下一次实机执行仍需独立确认。** 19项数据此前已作为37项的子集完成真实导出和校验，但没有把“新版单独只导出19项”冒充已实机复验。不承诺零风险、隐藏区域全覆盖或可刷回。

当前已有镜像在 Mac，单纯为了拿到固件，无需再执行本流程。

## 2. 时间与空间：保留什么、去掉什么

| 对象 | 默认处理 | 原因 |
|---|---|---|
| SD 整卡、118,286,712,832 字节 ext2 分区副本 | **不创建、不顺序读取整分区、不做整分区 SHA-256** | 这是盛放文件的容器，包含大量空闲空间，不能当作相机固件 |
| 标准明文/启动区镜像 | **默认19项，约1.87GB** | 与a7c2-re一致，适合常规固件内容研究 |
| 物理分区17项＋整闪存1项 | 默认不选，显式扩展模式才导出 | 用于底层布局、加密视图等扩展研究，增加约3.82GB |
| inventory、COMPLETE、MD5、五份主机盘点对照、卡标记 | 保留 | 用于拒绝旧会话、错卡、缺文件和数据不一致 |
| 每镜像 SHA-256、采集收据、状态、原始响应头 | 保留 | 供后续复核和发现本机文件变化 |
| 原卡中其他旧会话目录、照片、无关文件、空闲区域 | 不提取、不清理 | 减少读取，不为本次任务增加无关写入 |
| 既有 Mac 镜像和旧包/锁 | 不覆盖、不删除 | 每次使用新会话和新输出 |

旧方案先复制约118.29GB分区，再提取5.69GB文件并扫描整分区做摘要。第二版只通过只读 `debugfs` 获取所选文件和必要ext2元数据：标准模式本机空间门槛为 **1.873GB＋1GiB余量**，扩展模式为5.69GB＋1GiB。标准模式在相机选源阶段便排除物理节点，并非先转存37项再丢弃18项；数据量较37项减少约67%，不保证总耗时按相同比例下降。

37项中：物理视图18项共3,818,848,256字节，明文17项共1,864,302,592字节，启动区2项共8,388,608字节。`pnflasha`整设备与物理子分区有覆盖重叠；物理和明文不能凭长度相同认定字节相同。标准模式明确不保留物理视图，符合“获取明文固件及启动区”的研究目标；它不是物理闪存全覆盖备份，也不承诺日后能由19项重建全部物理视图。

| 模式 | 命令选择 | 数量 | 总字节 |
|---|---|---:|---:|
| 标准（默认） | `--profile standard`，可省略 | 19 | 1,872,691,200 |
| 扩展 | `--profile extended`，必须显式指定 | 37 | 5,691,539,456 |

## 4. 离线准备一次新转存

先按 README 校验包摘要、设置 `TASK_PY`，以下路径仅作本机命名示例。`$TASK_WORK` 必须是此前不存在的目录。

```bash
TASK_WORK="$HOME/A7R5-Operations/dump-20261018-next"
"$TASK_PY" -B kit.py prepare-dump --operation "$TASK_WORK"
"$TASK_PY" -B kit.py check --operation "$TASK_WORK"
```

以上默认标准19项。确有物理视图研究需求时，使用另一个全新目录，并在准备时显式选择：

```bash
TASK_EXT="$HOME/A7R5-Operations/dump-extended-next"
"$TASK_PY" -B kit.py prepare-dump --operation "$TASK_EXT" --profile extended
```

模式编入C选源逻辑和固定脚本，并绑定到操作摘要；准备后不能改模式再复用批准。`check`应同时显示 `dump_profile`、`image_count` 和 `image_bytes`。未发现的块设备仍会使主机拒绝，不会因标准模式而静默忽略未知设备。

这两条命令只读写本机普通文件，不枚举 USB，不请求 sudo。产物包括新 run_id、配置头、AArch64 `.so`、目标 libc 的符号/版本检查、准备/转存/清理脚本、预加载精确字节、GO/ABORT 令牌、卡收据和诊断绑定、操作摘要及未批准模板。

必须审阅：

1. `operation.json`的 `kind=dump`、新run_id、固定输出，以及默认 `dump_profile=standard`、19项和1,872,691,200字节。
2. `bundle/prepared-card-receipt.json` 的上述身份、容量和 UUID。
3. `bundle/prepare-task.sh`、`dump-task.sh`、`cleanup-task.sh`。
4. 载荷检查和摘要；`expected_card_device` 必须为 `/dev/mmcb2`。

`examples/prepared-dump-standard/`、`prepared-dump-extended/`分别供比对两模式中间材料，不重用其会话。`bundle/bundle.json`中的 `expected_inventory`封存完整所选集合，主机READY盘点若与它不同，不发送GO。

## 5. 实机前需要接受的具体写入和风险

部署只接受读到的 `/etc/ld.so.preload` **恰为 512 个换行**。不可读、空文件、服务码 `0x10000006` 或任何其他内容均停止；不会重新采用未知覆盖策略。

相机发生的写入是 `/tmp/jiritsu/a7r5-<run>.so`、预加载武装条目、随后中和为 512 换行，以及 `<run>.state/.parts/.mounts/.devices/.topology/.sources/.go` 等工作文件。`/tmp/jiritsu` 属于持久 Work 区，不能因名字含 tmp 就认为重启会清空。默认不删除这些研究残留。

只读内部闪存，输出写到指定 `/dev/mmcb2` 的新会话目录；不会格式化。一次 DEBUG 启动的工作进程先中和预加载，再做选卡/准备；主机盘点通过才发一次 GO。DEBUG 不重发，失败不自动重试或断电。

中和不是还原最初未知配置；此前最初原字节已缺失，无法由本流程追溯恢复。USB 接管、内核存储调用或退出服务可能失败；即使有超时，也不能保证阻塞 I/O 已撤销。相机工作时导出的各文件不是原子快照。发生异常可能需要在保留供电的状态下单独准备恢复步骤。

只有确认接受上述具体操作后，才把 `check` 显示的本次 `consent_phrase` 手动填入下条命令。不同操作的短语不同，以下 `ACCEPT-...` 是占位符：

```bash
"$TASK_PY" -B kit.py approve --operation "$TASK_WORK" --accept 'ACCEPT-把本次短语填在这里'
```

## 6. 一次 Terminal 实机执行

在相机关机时插入已准备、已解除 LOCK 的指定卡，取出其他卡，开机，连接原 Mac 端口。确认稳定独立供电、屏幕正常且没有初始化/格式化提示。不接受格式化提示。

可在另一个 Terminal 手动运行 `/usr/bin/caffeinate -i` 防止 Mac 空闲休眠；任务及恢复核对结束后在该窗口 Ctrl-C，不终止其他原有进程。

```bash
sudo "$TASK_PY" -B "$PWD/kit.py" execute --operation "$TASK_WORK"
```

仅在本机 Terminal 输入管理员密码。程序先核对批准、材料和外部依赖，再创建一次性 `ATTEMPT_LOCK`，核对相机/媒体，认证并切服务模式。依次完成固定版本及精确预加载基线读取、载荷上传完整读回、武装读回、一次 DEBUG、READY 盘点、中和独立读回、一次 GO、RUNNING、DONE、最终中和读回和卸载回执。符合退出门槛时仅尝试一次 STOP。

不得因窗口暂时没刷新、Pipe error 或退出码非零就重跑。实际相机端成功的历史耗时约 9 分 26 秒，仅供了解量级，不是新会话的超时保证。

关键输出在 `$TASK_WORK/result/`：`summary.json`、`events.jsonl` 中的原始响应头、`deployment.json`、`worker-last-state.txt`、主机独立清单和 `kit-result.json`。

## 7. 恢复核对与安全取卡

首先核对 DONE 0、`worker_done_receipt`、`card_unmounted_verified` 和 `preload_neutral_verified` 全部为 true。再看相机屏幕是否正常。如果这些门槛不满足，立即停止，不运行下面步骤。

历史 STOP 返回 Pipe error 后存在延迟回到普通 USB 的情况；退出码非零不能直接改判为 dd 失败。若已有 DONE/卸载/中和，只允许后续主机元数据观察，不补发 STOP 或重跑转存。**当你实际看见正常屏幕时**，可运行一次：

```bash
"$TASK_PY" -B kit.py confirm-recovery --operation "$TASK_WORK" --screen-normal
```

它仅观察主机元数据一次，要求同端口 `054c:0e0a`、存储驱动和指定卡/PMHOME 媒体恢复，写入 `host-confirmation.json`，不发送相机协议请求。仍为 `0336`、`096f`、媒体不符或屏幕异常就停止，保留现场另行分析；不自动重插、重启或断电。

通过后，在 Finder 中正常弹出相机显示的所有卷，或在磁盘工具按设备身份确认后对相机整盘执行正常弹出；**不要套用历史 disk7/disk8 盘符，不强制卸载**。弹出失败就停止。

正常弹出后，保持电池/独立供电，拔 USB 数据线，正常关机，等待屏幕和存取灯熄灭，再取出指定卡、置 LOCK，插入原内置读卡器。相机保持断开。不接受初始化、格式化或修复提示；关机或存取异常就停止。

## 8. 只取回所选19或37项，不做整卡中转

完成上一节后，准备单独读取操作。`--safety` 是对已完成取卡步骤的人工声明，不会代替你执行关机或取卡。

```bash
TASK_READ="$HOME/A7R5-Operations/collect-20261018-next"
"$TASK_PY" -B kit.py prepare-collect --dump-operation "$TASK_WORK" --operation "$TASK_READ" --safety CAMERA-OFF-CARD-LOCKED-MEDIA-EJECTED
"$TASK_PY" -B kit.py check --operation "$TASK_READ"
```

审阅 `binding.json`，确认run_id来自刚完成的新转存，模式、数量、总字节、设备实际选源和独立主机盘点一致：默认应为标准19项。取回模式自动继承转存模式，没有独立扩容或回退选项。批准只读采集后，手动填写此操作自己的短语：

```bash
"$TASK_PY" -B kit.py approve --operation "$TASK_READ" --accept 'ACCEPT-把采集操作的短语填在这里'
sudo "$TASK_PY" -B "$PWD/kit.py" execute --operation "$TASK_READ"
```

程序先核对本机 APFS/HFS 输出空间、指定卡全身份、内置读卡器、系统 `WritableMedia=false`、几何及分区。正常卸载后再次核对身份，只用 `O_RDONLY` 打开固定整卡/p2 描述符，验证 MBR 与超级块。随后 `debugfs` 默认只读方式经继承的 `/dev/fd/N` 读取固定会话中的文件，期间不改选其他设备。

**LOCK 位置不够。** 若系统仍报可写，程序在原始卡打开前停止。保留本次锁和输出，不删除锁再试、不通过忽略写保护继续；先单独排查识别问题。软件只读不能证明操作系统此前从未自动写入，也不能冒充硬件写阻断器。

逐项检查COMPLETE、该模式完整集合、长度、相机MD5、五份元数据摘要，计算每镜像SHA-256。默认是19项；扩展模式是37项。缺项、混入物理项、模式数量与字节不符均拒绝，不会因为文件更少而自动放行。再核对身份/超级块没变，关闭源描述符，正常弹出并确认盘符消失，全部完成才生成 `ACCEPTED.json`。

## 9. 验收与长期保留

必须同时满足：

- `$TASK_READ/result/ACCEPTED.json`：`execution_succeeded=true`、模式正确、数量和字节对应上表、正常弹出、长度/MD5/SHA-256通过。默认19项、1,872,691,200字节。
- `verified/images/`：恰好该模式的19或37个已验收镜像，没有被当作成功的 `.partial`。
- `verified/audit/COMPLETE`：run_id、数量和总字节与本次独立主机盘点一致。
- `verified/manifest.json`：每文件摘要齐全。该清单的 `ejection_verified=false` 表示它生成于弹出前；最终弹出及全流程结论以 `ACCEPTED.json` 为准。
- 没有 `card.ext2.img`；无需为生成整分区 SHA-256 再扫描 118GB。

保留整个小体积操作目录及 `verified/`。不要双击镜像让 macOS 可写挂载；此前 `cnflasha1.img` 发生过符合 `.fseventsd` 写入特征的变化，具体触发程序未确定。分析时使用单独工作副本；可将副本命名为 `.bin`，如必须挂载则明确只读。

## 10. 停止和恢复边界

| 情况 | 处理 |
|---|---|
| 版本/预加载/卡身份/容量/接口或文件读回不符 | 停止，不放宽门槛、不改用其他卡 |
| READY 前失败、明确 FAILED_UNMOUNTED 且中和通过 | 原引擎仅在满足自己的安全门槛时尝试一次 STOP；看日志，不手工补发 |
| GO 后失败/超时、传输失步或卸载未知 | 停止；任务可能仍读写，保持供电，不自动 STOP、断电或重试 |
| STOP 后仍为服务/过渡身份 | 只保存日志并观察主机状态；另行制定受限恢复，不复用旧恢复包 |
| 取回时 MD5/长度/元数据、只读状态或弹出失败 | 不生成最终接受标记；保留 partial/证据，不修复文件系统、不自动再采集 |

本包没有自动清理相机研究残留、恢复最初未知预加载、拍摄测试或刷回入口。两份实施流程不能并发执行；一次失败恢复核对完成后，才考虑新的操作。

## 12. 当前本地37项的分类

现有原件继续位于原 `verified/images/`，没有迁移、改名、删除或复制镜像数据。已在同级新增 `classified-20261018/`，结构如下：

classified-20261018/

│   ├── plaintext-17/       17个明文分区链接
│   ├── boot-2/              2个启动区链接
