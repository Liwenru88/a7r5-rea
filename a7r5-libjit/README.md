## 入口与证据

- `src/runner.c`：无 libc/DT_NEEDED 的 AArch64 动态库。脚本在构建时封存，加载器只调用原始系统调用。父侧立即返回，独立监督进程收集退出码，不让脚本承担最终状态发布。
- `operation.py`、`transport.py`：固定两文件上传、单次触发、原始响应头留证，协议失步后封锁，完整门槛后才允许一次STOP。
- `runner.py`：无批准时在任何设备查询前拒绝；绑定材料、外部运行依赖、端口、接口、版本和库摘要，保留一次性锁。
- `build.py`：仅在本机封包；`rebuild_check.py` 在临时目录重建比对，不替换已封存产物。
- `run_offline_tests.py`：拦截真实USB、网络连接、原始磁盘和设备查询；只允许 `/dev/null` 供本机子进程使用。
- `verify_guest.py`：使用既有无网、无物理设备的原生QEMU运行真实AArch64产物。所有写入仅在客体RAM，不修改模拟器输入。
- `packages/libjit-info-20261021-02/evidence/`：保留的镜像和库摘要、机器指令、静态结论；固定库位于同包 `test-fixtures/`，不把整机分区镜像放进实施包。

## 核验结果与边界

主机协议/状态机、封包篡改和尝试锁、STOP许可、完整媒体观察和依赖导入的定向测试40项通过。AArch64 QEMU中，精确生产库的固定只读任务及8类失败路径通过，父侧立即dlclose后子进程仍能完成；最终QMP正常退出，原运行清单未变。详细证据随一次性包保存。

测试曾复现默认SIGXFSZ进入原厂异常监视器，已修正为忽略该信号、以EFBIG和监督者输出饱和检测收敛。原 analysis 失败现场已随用户要求清理；现存包与 QEMU runs 中的历史记录保留。

**当前仍是离线适配，不是A7R5实机libJit成功证据。** 固定路径潜在覆盖、自删失败、原厂服务崩溃、无法执行前完整读回、USB恢复受限等风险见 `实施与恢复.md`。没有授权文件，不能双击运行实机包后绕过门槛。

## 本机验证命令

Python使用工程根目录 `.venv/bin/python`；已安装 pytest、pyelftools、capstone，仅用于本机测试与构建。通信依赖由实施包携带，未调用USB初始化。

```sh
.venv/bin/python -B a7r5-libjit/run_offline_tests.py
```

最终包内从 `runner.py check` 开始，只核对本机材料。实机动作必须另获本包确认，逐次批准后才打开专用Terminal；本轮不生成 `approval.json` 或实机尝试锁。
