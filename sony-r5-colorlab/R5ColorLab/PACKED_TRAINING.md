# 正式训练的整数候选筛选与旧配方回退

当前本地训练修订为 `06c3557+native24/2`。保留上游 Hybrid 数值模型、Adam 0.015 × 600、原生 12 起点及每阶段 2000 次评估上限，增加最终整数配方的候选筛选和验收。BIN v4／v5、24 槽及原十二槽兼容格式不变。

## 工作台上的行为

在工程中训练已保存的槽位时，排队就冻结该槽位的完整配方和来源。未保存草稿不参与保底；训练期间编辑工程、重试任务，也不会改变已冻结的基准。单槽与批量入口一致。训练生成单独的任务结果，仍需点击保存才会进入工程槽位。

没有已保存配方的空槽，用本轮原生拟合的五轮网格结果作基准。页面会明确显示采用了新配方还是保留了基准，不能把“BIN 编解码通过”解释成“拟合效果提升”。

## 从原生搜索到最终配方

1. 原生拟合保存每份候选的完整参数、连续向量、来源数据摘要、辅助补偿评分和原生灰阶误差，文件为 `fit/native_candidates.json`。
2. 从去重档案选至多四份参数，包括辅助评分最好的分解和原生灰阶较好的分解；再加入本轮原生选中项、旧参数及旧曲线的单调凹投影，按原生参数去重。短名单控制额外计算量，不保证全局最优。
3. 每份原生参数先由冻结编译器转换、打包和解码，在最终 BIN 的单位下拟合实际 `5×9×9` 网格，统一最多五轮。拟合只接收 TRAIN。每轮落盘的整数表都进行验证评分；不是只看电脑端曲线补偿效果，也不是无条件采用最后一轮。
4. 在验证色卡、训练灰阶、开发照片和 `.53` 相位双域渐变上过门禁后，选择三轮联合优化的起点。旧参数还检查温和的整数网格混合候选。
5. 三轮联合优化后，重新比较合格的网格候选和联合优化提案，再对唯一胜者进行独立终检。终检使用色卡 test、留出照片和 `.87` 相位渐变；失败只回到冻结基准，不继续利用留出数据尝试其他候选。
6. 对最终接受的 BIN 独立解码、重新编译并进行 CPU 原生回放。预览、色差统计、工程载入及 BIN 下载通过同一个 `selected_config` 读取最终结果。原生阶段的配方、电脑端补偿及 `stack-proposal.BIN` 保留作诊断，不当作最终配方。

## 采用条件

相对冻结基准，验证与最终色卡的 RGB RMSE、平均 ΔE00 都要严格降低；灰阶和颜色 P95 不得超出校准容差。双域暗部曝光、完整曝光、色相、饱和度路径继续检查色度二阶变化的 P95、单点严重突变和连续三个异常点。

有照片验收集时，开发／留出阶段分别要求场景等权平均 RGB RMSE 与 ΔE00 都改善，并保护每张照片的 RGB、平均 ΔE00 与 P95。沿用既有 `calibrated_guard.py` 的舍入相位容差和上限，不为取得通过而放宽阈值。

门禁通过之后，才用固定加权色差排序。加权总分降低不能抵消任一保护失败。基准不是“新候选”，无需满足相对自身严格改善。

## 照片验收集

验收集保存在运行目录的 `_quality_sets/<清单摘要>/`，包含已经对齐的离线照片缓存和开发／留出划分。清单、文件和训练目标均绑定 SHA256；HTTP 请求只接收登记后的标识，不能指定任意本机路径。

训练目标的文件摘要与唯一登记集匹配时自动绑定。当前三款推荐滤镜使用已有的十场景缓存，六张开发、四张留出；输入曝光对齐、目标与划分均沿用已有验证数据，不是新盲测。

需要登记新的冻结数据，可在 `R5ColorLab` 目录使用现有环境执行：

```python
from pathlib import Path
from quality_data import register

identifier = register(
    Path('web/runs'),
    Path('/absolute/path/frozen-validation/manifest.json'),
    target_sha256='64-character-sha256-of-the-chart-target',
    target_key='target_5',
)
print(identifier)
```

运行时须设置 `PYTHONPATH=web:scripts`。冻结清单的 `scenes` 包含 `scene`、`file`、`sha256`、`role`；角色为 `development` 或 `holdout`，两者都必须存在。每个缓存为无 pickle 的 NPZ，包含 `inputs: N×9×3` 和对应目标键 `N×3`。输入与目标必须已经按照同一流程对齐；登记功能不进行 RAW 解码、曝光拟合或图像配准。

没有匹配照片集仍可训练；此时明确记录 `photo_scope: not-bound`，不能声称照片已验收。灰阶和渐变仍按原相位方法校准，颜色 P95 使用零额外照片容差。

## 可复核文件

- `request.json`：冻结的 `packed_baseline`、来源响应身份、目标和照片验收集。
- `fit/native_candidates.json`：原生候选档案，不覆盖主配方。
- `packed_candidates/`：每个候选、每轮整数表和评分；`selection.json` 记录起点、拒绝项及校准容差。
- `quality_selection.json`：筛选结果、唯一终检、回退原因及最终配方摘要。
- `stack-proposal.BIN`：联合优化提案，可能被拒绝。
- `R5NATIVE.BIN`：最终实际接受的结果，可能与旧配方相同。
- `grid_distillation/<key>/result.json`：绑定品质审计和完整已选配置；审计变动会导致预览／导出校验失败。

这些证据针对离线模型的标准 B 端点。旧配方回退保留其完整 A1／A2 字段；新配方仍按既有导出规则生成端点。离线颜色统计不代表机内 JPEG 或其他光源条件已经验收。ARW 原生参数导出仍属于原生拟合阶段的诊断，不包含最终网格，应使用单网格照片预览核对最终 BIN。
