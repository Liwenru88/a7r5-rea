# C/D 分级保护规则

本轮参考[保护规则讨论](thread://01a1d3dd-302c-7fb1-b487-603f636437c8?hostId=local)落地独立实验规则，不更新正式工作台，不连接相机，不改变 BIN 格式。旧实验报告和配方保留。

## 哪些问题硬拒绝

- BIN 结构/CRC、原生参数越界、非有限值、Gamma 非单调或零起点不合法，继续硬拒绝。
- 色卡验证/测试集的 RGB RMSE、平均 ΔE00 仍须同时降低。
- 灰阶和颜色 P95 超出冻结的数值容差，硬拒绝；训练侧允许颜色持平，验证侧要求改善。
- 每张照片及固定 3×3 区域分别检查 RGB RMSE、平均 ΔE00、P95，超过数值容差即拒绝；不让照片平均改善掩盖单张或局部退步。留出照片平均 RGB RMSE、平均 ΔE00 仍须改善。

## 容差来自哪里

**这是数值舍入不确定性的上界，不是已经验证的人眼可见阈值。**

对参考图像的每个像素，在小于半个 8 位码值的舍入扰动内，每个通道只能取 `floor(x×255)` 或 `ceil(x×255)`。八个离散 RGB 角点覆盖全部组合：

1. 灰阶 RMSE 取各通道最差平方误差的总上界。
2. 每个像素计算八角点中最大的 ΔE00，再计算整体均值和 P95 上界。
3. 容差是上界减去原参考指标，不再截断成固定的 `0.05`。
4. 用另外 12 组固定种子的舍入扰动验证覆盖。源自 TRAIN 色卡与六张开发照片的容差，在候选评分前冻结；测试集不参与调整。
5. 整张照片与区域分别汇总开发集容差，避免小区域的波动直接放宽整张照片。

区间包含独立像素/通道的组合，可能比实际全局舍入波动保守。报告保留 `perceptual_threshold_validated=false`，不把数值通过解释为肉眼或实机确认。

## 过渡保护如何改变

旧规则把同一位置二阶差分增加直接当作退步，还在校准容差之上叠加零退步。本版保留旧指标用于对照，实际按以下方式判断：

- 同时统计最终 8 位输出与取整前浮点输出。
- 在 `.17/.53/.87` 三种采样相位、`1/2/4` 三种采样跨度下，分别统计两个域四类渐变的 P95 和最大值。
- Lab 八角点区间向三个采样位置传播，得到过渡统计的量化波动上界，不再把局部容差固定截成 `0.5/0.75`。
- 比较过渡分布，不强迫新曲线每个转折位置接近旧配方。轻微、非持续异常保留诊断。
- 同一轴至少两个相位、各至少两个尺度持续超界，或单处增加量超过量化界限的两倍，进入图像复核。这是安排复核的启发式，**不是已经校准的可见色带阈值**。
- 未确认异常只标记“需复核”，不自动当作严重缺陷硬拒绝，也不自动采用。经过图像确认的严重异常应另行记录为拒绝依据；本轮不伪造确认结果。

图像复核保留原 73 点条带，并重新生成同一 HSV 路径上的 4609 点输入，重新执行完整离线前向；不是放大或插值已有模型输出。高密度图、输入和输出 NPZ、相邻色差统计一并保存，供核查粗采样假象与模型真实跳变。

## 训练过渡项跟随真实目标

现有数据能提供 24 条实测目标明暗射线，每条排除重复黑点后有 255 个采样，共 6120 个 TRAIN 样本。训练用它们的 Lab 一阶与二阶差分，在三种跨度下拟合目标梯度；真实目标的转折不会因为偏离旧曲线而被惩罚。

目标梯度项在起点按颜色数据损失的 10% 校准权重，后续独立记录；灰阶/P95 约束仍受原有的数值与归一化梯度预算控制。原生参数平滑保留。

合成探针没有直接对应的目标图，尤其不能把原生域色相、饱和度探针的旧配方输出当作真实目标。本版不对这些探针施加“保持旧形状”的训练惩罚，它们仍参与多相位、多尺度离线诊断。

## 结果分级

| 状态 | 含义 | 文件处理 |
|---|---|---|
| `rejected` | 合法性或颜色质量存在硬失败 | 保留原配方 |
| `review_required` | 数值指标可行，过渡仍有未确认疑点 | 保留原配方，待图像复核 |
| `eligible_offline` | 本轮数值检查通过，未发现需复核疑点 | 仅作为离线候选，不替换正式库或证明机内效果 |

C/D 筛选把数值资格与复核状态分开记录。候选锁定后才评测试集和留出照片；失败后不依据测试结果重选。`accepted.BIN` 只是单槽审计文件，需复核/拒绝时回退原配方；正式库始终不自动更新。

## 使用与验证

新规则训练入口：

```sh
.venv/bin/python -B scripts/benchmark_native_feasible.py \
  --bin /absolute/path/to/original/R5NATIVE.BIN \
  --manifest /absolute/path/to/frozen/manifest.json \
  --output /absolute/path/to/new-output \
  --steps 2000 --checkpoint 50 --protection-policy reviewed
```

`--pilot --steps 3 --checkpoint 3` 用于 GPU 整批链路验证；`--protection-policy legacy` 保留上一轮零退步行为。
默认同时运行 C/D；追加 `--arms C` 可只复测直接参数联合拟合，预算和保护规则保持相同。实际方案列表写入 `protocol.json`。
分次对照可以追加 `--arms D --normalization /absolute/path/to/C/normalization.json`，逐值复用 C 的敏感度尺度。起点必须完全一致，尺度须为 1448 个正有限数；输入摘要纳入保护清单。未指定时保留原有估计方式。

已有 BIN 复评：

```sh
.venv/bin/python -B scripts/reassess_native_protection.py \
  --bin /absolute/path/to/original/R5NATIVE.BIN \
  --manifest /absolute/path/to/frozen/manifest.json \
  --candidate C=/absolute/path/to/C/proposal.BIN \
  --candidate D=/absolute/path/to/D/proposal.BIN \
  --output /absolute/path/to/new-reassessment
```

复评是事后诊断，不改变原实验结论，也不是新的盲测或完整重训。只有源配方和校准数据决定阈值，候选不参与放宽容差。当前实现只接入 C/D 实验入口，正式工作台默认训练流程未改变。
