# A7R V 接线与诊断

当前 USB 连接方案依据用户于 2026-11-12 转述并确认的 A7R V 同型号实测反馈，Fastboot 数据使用 Multi→USB-A，相机 USB-C 留空。该方案尚未在本次故障机上完成 Fastboot 数据传输验证。此前本机通过 USB-C 观察到 Sony HID 设备，RP2040 也回复了桥接版本，但这些结果只证明当时的 USB 枚举和桥接通信。[此前诊断记录](private/evidence/usb-mode-tmz3x7nr/report.json)

旧研究笔记记载使用相机 USB-C 传输 Fastboot 数据，目前两份接法记录存在差异，旧笔记作为历史参考保留。[历史接线记录](../sony-r5-colorlab/analysis/R5_FL2_FL3固件色彩与RAW参数研究总结.md#L383)

## 物理连接

- Mac 用一根 USB 数据线连接 RP2040‑Zero。
- Multi 转接板引出的 USB-A 数据线连接电脑，承担上述反馈方案中的相机 USB 数据传输。相机 USB-C 留空，相机使用电量充足的 NP‑FZ100。
- RP2040‑Zero 通过下列四根线连接相机的 Sony Multi 15 针口。先确认公头朝向，用万用表逐根测触点到焊盘导通，并确认相邻触点之间没有短路。RP2040 的 `5V` 和 `3V3` 留空。

| RP2040‑Zero | Sony Multi 公头 | 用途 |
| --- | --- | --- |
| GP28 | 7 | 相机 RX |
| GP29 | 8 | 相机 TX |
| GP27 | 9 | 相机 RESET |
| GND | 2 | 共地 |

## 诊断结果怎样看

确认相机已停止更新且接线检查通过后，`probe` 才是设备操作入口。它要求显式提供 RP2040 串口、新的输出目录和 `--confirm-reset`，会尝试复位一次并保存完整的串口和 USB 回执。遇到失败时保留原回执和当时设备状态。

| 证据 | 含义 |
| --- | --- |
| `reset_acknowledged` 与 `records_acknowledged` | RP2040 应答了复位命令及相应数量的发送记录 |
| `uart_ready_observed` 与 `uart.bin` | 记录中观察到载荷发出的 `[mira] fastboot ready` |
| `usb_transport_verified` | 通过 USB Fastboot 0.5 和后续只读校验 |
| `layout_matches_reference` 与 `sdm2_matches_reference` | 当前分区布局和 SDM2 回读与历史参考匹配。是否同一机身仍需另行确认 |

当前入口读取分区布局、64 KiB SDM2 和 48 KiB AP BootROM。进一步诊断 WBI 需另外取得故障机的 `nflasha5` 只读证据，与实际刷入的 DAT 和同机备份对照。[4.18 故障分析](../a7r5-firmware-features/firmware-runtime/4.18启动故障离线分析.md)

归档中的 A7 IV 案例仅用于对照串口和 USB 两个诊断阶段。机型、更新器和分区内容不同，不能凭该案例判断 A7R V 故障原因或选用旧 WBI 镜像。[A7 IV 讨论截图](private/wiring/a7iv-recovery-case.png)
