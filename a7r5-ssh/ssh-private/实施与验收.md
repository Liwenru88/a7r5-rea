# A7R5 私有视图限时 SSH：实施与验收

日期：2026-10-20。对象：ILCE-7RM5 / 4.00。当前状态：**离线集成通过；经后续确认完成一次实机尝试，但指定IP未出现，sshd未启动。**实机只读回收得到精确失败终态，原入口未放行STOP；[本次结果](packages/private-ssh-20261020-02/实机结果.md)与[待批准受限恢复](recovery-20261020-01/恢复方案.md)为当前进展，下文保留原部署和验收设计，不代表已全部通过。

## 1. 结论和参考路线

采用 a7c2-re 的“原厂 `/usr/sbin/sshd` + 独立 2222 端口 + 指定公钥”路线。本次不沿用参考脚本中的持久 root shell 改写、全地址监听和按名称结束进程。

参考材料：[报告](https://github.com/chocotan/a7c2-re/blob/433737ae5a8a241ae86eb307a12bb6a2c33600c7/report/2026-10-19-ssh-feasibility/REPORT.md)、[脚本](https://github.com/chocotan/a7c2-re/blob/433737ae5a8a241ae86eb307a12bb6a2c33600c7/report/2026-10-19-ssh-feasibility/ssh-camera.sh)。未执行上游脚本。

A7R5 原始 root shell 是 `/bin/false`，原厂 22 端口配置禁止 root 和公钥会话。使用独立实例时，必须处理账户 shell；本次仅将私有 RAM 账户副本中唯一 root 行末尾改为 `/bin/sh`，再只读绑定到子进程挂载视图。外部原账户、原 SSH 配置及 Sony NSS 保留。

用户此前从机身界面提供地址 `10.10.10.117/24`，Wi-Fi 已连接且 USB 仍连接 Mac。N0 对 TCP 22 的单次连接超时；这既没有建立当前端到端连通性证据，也没有证明独立 2222 不可用。本次用“内核出现精确指定 IPv4 才启动监听”和“一次严格指纹 SSH 实验”直接补证，不扫描、不重复 N0、不修改 WLAN、路由或防火墙。相比旧 v3，此次不再把原厂 22 可达作为必须先通过的门槛；若 2222 仍超时，保存失败，停止。

## 5. 第一阶段执行清单（待批准）

1. 用户确认相机仍是 `10.10.10.117`、屏幕正常、稳定独立供电，保持已有 Wi-Fi、USB 和卡状态。若地址变化，废止本包，不能临时改地址或扫描；不要求拔卡、换 USB 模式或关闭原厂网络认证。
2. 获得绑定本包的新批准后才创建 `approval-deploy.json`，再打开 `run-deploy.command`。管理员密码只在本机 Terminal 输入。没有批准时程序在 sudo 前停止。
3. 本机核对材料完整性，一次性锁先落盘，才读取主机 USB 元数据；核对既有物理端口 `0x01100000`。使用已封存 libusb 引擎，一次认证/START，固定接口指纹和端点选择，保存原始响应头。
4. 核对固件版本和精确 512 换行基线；上传并完整读回两个固定文件，武装预加载，发送一次 DEBUG。root 固定任务还核对原厂 sshd、版本、NSS 和原 SSH 配置摘要。监督器核对原始账户摘要。
5. 私有视图准备、sshd 配置检查、RAM 主机密钥生成通过后才 READY。客体只等待精确 IP 出现，最多启动一次前台 sshd。**如果 IP 已存在，监听可能在 STOP 前开始；不会声称只在 STOP 后开启。**没有 IP 则不监听并到时清理。
6. 主机读取 DONE/READY、公钥和推进心跳，再重复 READY/终态，确认中和及余量。心跳年龄不超过 60 秒；临近 STOP 时还需保留不少于约 110 秒，用于退出、既有引擎普通身份观察、主机独立媒体恢复和 SSH。
7. 所有门槛通过才发送一次 STOP。STOP 的 Pipe error 原样记录；是否恢复依据同端口普通身份 `054c:0e0a`、存储驱动及原媒体连续两次核对，不能以 Pipe error 本身认定成功或失败。主机独立观察上限 45 秒；恢复未通过不连接 SSH。
8. 恢复通过且无协议失败后，仅向 `10.10.10.117:2222` 建立一次连接，完成加密握手后逐字节核对 USB 回收的主机公钥，之后才提交唯一客户端密钥。总 SSH 客户端窗口最多约 20 秒；不使用密码、agent、keyscan、重连或其他地址。
9. 客户端请求固定 `id`；服务端 `ForceCommand` 实际强制执行 `/bin/busybox cat /proc/self/status`。只验收 UID/GID 各四项均为 0、退出码 0，输出小于 4096 字节。此阶段**不提供交互终端或任意命令**。
10. 保存本次状态、主机恢复和 SSH 原始输出。用户仅查看屏幕确认正常。成功也仍需等待寿命结束和第二阶段清理回执，不能立即称为全部验收完成。

## 6. 自动结束及第二阶段（另行确认）

监督器使用单调时钟。私有子视图 READY 后约 180 秒结束实验，清理只针对本次仍存在亲缘关系的子进程和 subreaper 接管后代，先 TERM 再 KILL/wait，有界约 6 秒；外层有约 5 秒额外看护上限。不会按进程名 killall，不读旧 PID 文件杀进程，不延长寿命，不重新启动 sshd。

第一阶段报告生成后至少等待 190 秒，且人工屏幕正常、前次 USB/媒体恢复已通过，再另行批准 `run-collect.command`。第二阶段仅认证/START 和固定读取，不上传、不 DEBUG、不登录 SSH：

1. 重新核对版本及精确中和基线。
2. 读取本 nonce 的最终父结果和子结果，保存原始内容；需要父结果 `code=0`、外部账户/NSS/配置和相关挂载视图未变、后代已回收、子终态已见、2222 监听消失；子结果需要 sshd 尝试与监听观察、私有账户变化及回收均成立。
3. 重复读取父终态并再次核对中和，全部通过才一次 STOP；再独立核对 USB、驱动、媒体和人工屏幕。

监听检查来自 `/proc/net/tcp` 的端口状态，不是监听 inode 与 sshd PID 的独立归属证明；首次端到端身份依靠可信公钥与 root 命令。没有监听或端口冲突会被报告为失败，不用其推断网络配置故障。SIGKILL、内核不可中断状态或服务程序异常仍可能使清理不能确认，必须保留失败状态。

## 7. 停止和恢复

| 失败点 | 自动动作和人工边界 |
|---|---|
| 身份、版本、精确预加载基线不符 | 停止，不覆盖未知基线，不换端点或改配置 |
| DEBUG 前已武装且通道完整 | 仅在读到本次精确预加载条目时允许一次中和并核对；不盲写。主入口仍保守停止，不因此自动再试部署 |
| DEBUG/协议失步、状态不符、中和不符、心跳停滞 | 不重发 DEBUG，不自动 STOP，不写补救文件；保留供电和 USB，查看屏幕，另行准备受限恢复 |
| 配置、NSS、账户或隔离失败 | 没有持久账户改写兜底；私有后代有界清理，主机未取得完整门槛则不自动退出服务 |
| STOP 错误或普通媒体未恢复 | 不重发 STOP、不自动拔线/断电；只按已批准的主机观察判断，超时即停止并另行评估 |
| SSH 超时、指纹不符、密钥拒绝、非 root 或输出不符 | 单次失败即停止，不扫描、不试密码、不重连；实例仍按原寿命结束。最终回收单独确认，不能依赖 SSH 进入来恢复 |
| 最终清理回执缺失、非零或与预期不符 | 不宣称账户安全或实例已消失，不继续交互；固定读取已保存，不自动重启、断电或删除证据 |

全程不访问 SD 原始设备、不挂卡、不格式化、不修复、不更新固件、不改原始镜像。自动期限不是断电恢复保证；持久载荷和中和文件残留保留，不自动删除。
