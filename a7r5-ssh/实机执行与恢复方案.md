# A7R5 SSH：待确认的实机执行与恢复方案

> 历史方案，保留供审计。其预检已于2026-10-20执行一次，旧包已锁定；源码修复后摘要也已变化。下一步以 [最小部署方案 v2](A7R5-SSH最小部署方案-v2.md) 为准，不按下文再次运行旧包。最新恢复观察要求见 [修复与验证记录](离线修复与验证-20261020.md)。

本文件是后续执行清单，**本轮不执行**。所有历史实机授权均不复用。当前包只能执行固定预检，不能启动 SSH 或修改账户。

## 一、下一次可批准的最小操作：固定预检

1. 审查本包 `verification/summary.json`、`packages/preflight-once/operation.json` 和 `task.sh`。确认 ILCE-7RM5 / 4.00、同一物理端口 `0x01100000`、普通 USB 身份 `054c:0e0a`。
2. 相机稳定独立供电，正常屏幕，无格式化/修复提示。先确认本次写入与恢复风险，再生成本次批准；当前包不含有效批准。
3. 运行一次专用 Terminal。只在本机 sudo 提示中完成认证，不使用聊天密码、不保存密码。脚本检查批准后才请求管理员权限。
4. 主机精确核对同端口相机及媒体，正常卸载相机卷；复用已验证协议完成普通/服务两阶段认证与 START。同端口服务身份应为 `054c:0336`。
5. 核对版本对照和精确512个换行预加载基线。任一不符或读取未知即停止，不能解释成文件不存在，也不能覆盖。
6. 上传本次固定 `.so` 并完整读回；武装精确预加载条目并完整读回。只发送一次 DEBUG。
7. 载荷仅在精确 DEBUG argv 下运行；先中和本次预加载，再核对 UID/EUID，运行固定预检脚本，限制45秒、输出少于32768字节。
8. 读取状态→输出→中和→同一状态，检查 nonce、UID/EUID、脚本退出码、输出长度、完整标记、版本与 sshd 摘要。预检输出也必须保存。
9. 仅门槛完整时允许一次 STOP；不把 STOP 返回当作恢复成功。独立核对同端口普通 USB、存储驱动及前后媒体集合，再由用户查看屏幕。不会自动拔插、断电、重试。
10. 预检结果只用于审查，不自动进入 SSH 部署。正常拍摄、休眠及 Wi-Fi 共存仍需之后分别确认和验收。

## 二、预检写入清单

`N` 为本次 `operation.json` 中的32位随机 `run_id`。下列文件是会产生的相机写入或残留，不能称为零写入。

| 路径 | 内容及方式 | 恢复边界 |
|---|---|---|
| `/tmp/jiritsu/a7r5-N.so` | 本次固定载荷；完整字节受主机白名单限制 | 可能位于持久分区；本包不自动删除 |
| `/etc/ld.so.preload` | 基线必须为512换行；短暂写入本次 `.so` 条目，触发后写回512换行 | 中和是本次约定基线，不证明最初原厂状态 |
| `/tmp/jiritsu/a7r5-N.state.new`、`.state` | 工作进程状态及原子替换 | 保留现场，不自动清理 |
| `/tmp/jiritsu/a7r5-N.output` | 空间、账户摘要、挂载与网络元数据 | 上限32768字节；不含账户密码字段或私钥 |

预检不写 `/etc/passwd`、`/etc/shadow`、原厂 SSH 配置，不创建密钥、不启动监听、不挂载卡、不执行固件更新或格式化。认证/START/DEBUG 属于有副作用的设备操作，不因任务脚本只读而省略批准。

## 三、预检将返回什么

- UID/EUID、版本摘要、sshd摘要、账户文件摘要。
- root/sshd 的 UID/GID、home、登录 shell；不回传 password 字段。
- `/etc`、`/tmp`、`/tmp/jiritsu`、`/tmp_network`、`/var`、`/dev/pts` 的实际挂载记录。
- 三个关键路径的 statvfs 空间或即时 errno，目录/PTY 元数据。
- NSS passwd 查找顺序、接口地址、TCP 状态。

不会扫描局域网，不读私钥或 shadow 内容，不输出完整 passwd，不把某条 TCP 记录当作认证/终端成功。

## 四、账户修改风险：本包保持禁用

参考项目曾将 root 的 `/bin/false` 改为 `/bin/sh`。这会持久改变系统账户的登录行为，重启未必还原，可能同时影响 login/su/sshd。只改 shell 也不能保证 Sony NSS/PAM 或锁定状态允许密钥登录。

若 A7R5 预检显示需要账户改动，下一份方案必须包含：

1. 本机当前文件、文件类型、实际挂载、权限、长度和完整摘要；明确不同机身、旧备份不得覆盖。
2. 只针对已确认 root 记录的最小差异，以及其他记录逐字节不变的验证。
3. 相机与主机两份原始备份、回读摘要、空间及失败时的退出条件。
4. 恢复必须基于本次原件；现状与预期不符即停止，不能盲目整文件覆盖。
5. 账户恢复会影响后续 SSH 登录；需要事先确认不依赖该 SSH 自身的恢复入口。

本包没有 passwd/shadow 修改脚本或解锁功能。不能把历史 A7C II 的“改后仍正常拍摄”当作本机保证。

## 五、SSH 候选的具体范围

候选使用原厂 sshd、独立端口2222、明确的局域网地址、指定公钥；只允许固定 `/proc/self/status` 读取，运行5–30秒，不开放任意命令、PTY、密码、转发、SFTP或开机自启。

必须先确认 `/tmp_network` 实际为 tmpfs、空间充分、root 登录条件满足、监督器/sshd 摘要及子收割器能力正确。禁止绑定 `0.0.0.0`；客户端不关闭主机指纹校验。客户端私钥只留在 Mac。

| 候选写入 | 生命周期 |
|---|---|
| `/tmp/jiritsu/a7r5-N.supervisor` 和本次载荷/状态 | 固定上传文件，可能持久；仅未来独立批准后允许 |
| `/tmp_network/a7r5-ssh-N/authorized_keys` | 本次公钥 |
| 同目录 `host_ecdsa`、`host_ecdsa.pub` | 相机端主机密钥，仅允许已确认的 RAM 路径 |
| 同目录 `sshd_config`、可能的 `sshd.pid` | 独立服务配置和运行元数据 |

不自动创建或修改 `/var/empty`，不存在时停止。候选使用全新 nonce 目录，拒绝已存在目录，不复用历史主机密钥。相机端私钥不得写到 `/tmp/jiritsu` 或主机日志。

当前没有实机部署入口。预检后需绑定真实接口地址、公钥、账户条件、目标摘要与恢复计划，重新封包并确认。完整 root 交互终端是此后独立阶段。

## 六、停止和恢复

| 异常 | 自动行为及后续 |
|---|---|
| 批准缺失、摘要/路径变化、已有锁 | 不观察设备，不启动sudo或设备后端 |
| 身份、端口、版本、预加载不符 | 不上传未知文件，不猜测或改选设备 |
| DEBUG前武装失败 | 只有通道仍完整且读到本次精确条目时，才允许一次中和；否则保持现场 |
| 协议/传输失步、DEBUG失败、旧状态、超时、非root、输出不完整 | 不重发DEBUG、不自动STOP、不重试、不断电；保存完整现场，另行审查恢复 |
| 预检完整且中和/重复状态通过 | 只尝试一次STOP，再独立核对USB、驱动、媒体、人工屏幕 |
| STOP失败或恢复不完整 | 不补发、不自动断电或拔线；后续恢复单独绑定本次状态 |
| SSH候选超时或收到停止信号 | 监督器只处理本次直接子进程及其收养后代；先TERM后有界KILL并回收。清理不完整则失败，不能报告已恢复 |

监督器停止不自动恢复账户、不删除目录、不证明拍摄模式恢复。候选未使用 `pkill -f` 或 `rm -rf`；后续残留清理需要先核对本次文件身份，再按明确清单批准，不删除未知文件。

实机异常时请保持独立供电和连接，仅观察屏幕，不自行重跑、拔卡或断电。不能承诺 SSH 可以救援不能启动或无线控制面损坏的固件。
