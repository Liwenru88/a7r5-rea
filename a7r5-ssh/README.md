# A7R5 SSH 离线适配材料

> GitHub 源码发布说明：当前研究签名公私钥经授权随源码保留；完整固件、其他私钥、SDK 二进制、真实操作包和历史验证现场仅留本地；旧链接可能指向未入库材料。环境与输入要求以 [根目录构建说明](../docs/build-inputs.md) 为准，本轮验证见 [验证记录](../docs/verification.md)。

本目录独立于 `a7r5-qemu` 和旧转存包。目标是先核实 A7R5 4.00 的原厂 sshd、账户及网络条件，再进行有限寿命的 SSH 验收。当前实机入口仅提供固定预检，**没有启用 SSH 部署、账户修改、交互终端或开机自启**。

2026-10-20 已完成一次实机预检：root 执行及中和门槛通过，STOP 一次报 Pipe error，即时媒体核对失败，随后仅主机观察确认恢复，用户确认屏幕正常。原始记录见 [实机预检结果](../a7r5-ssh-live-20261020-preflight-01/结果与下一步.md)。最新离线修复及部署规划见 [修复与验证记录](离线修复与验证-20261020.md)、[最小部署方案 v2](A7R5-SSH最小部署方案-v2.md)。本次离线修复没有查询相机或 SD 卡。

**历史包已使用且不再有效。** `packages/preflight-once` 的批准、锁、结果和根目录旧清单均保留；源码修复后其摘要不再匹配，不能再运行或删除锁重跑。旧 ZIP 和 `verification/summary.json` 是实机前的封存快照，不表示当前源码状态。

新增无SSH隔离/跨STOP补证实现：见 [执行与恢复清单](隔离与跨STOP补证-执行方案.md)、[离线验证](隔离与跨STOP补证-验证记录.md)。仅准备了未批准的一次性材料；账户副本保持原字节，不启用SSH。最终RAM结果需独立批准的只读会话取回，不自动开启第二次认证。

## 当前交付

- `lab.py`：离线准备、摘要检查、严格批准门槛及一次性预检入口。
- `device.py`：批准后才加载的 USB 适配，复用封存引擎；固定型号、版本、端口、文件路径、内容与请求上限。
- `src/preflight.sh`、`src/preflight_fs.c`：固定只读检查脚本和 statvfs 空间查询，不输出密码字段或私钥。
- `src/root_once.c`：来自旧包的精确触发、中和、限时执行器；仅条件增加只读 statvfs 输出，保留既有触发门槛。
- `src/supervisor.c`：5–30 秒前台 sshd 生命周期候选；Linux 子收割器追踪后代，不使用 pkill、历史 PID 或递归删除。
- `src/prepare-smoke.sh`：受限 SSH 候选模板，要求已确认账户 shell、sshd/监督器摘要、tmpfs、空间和子收割能力；只运行固定身份读取。
- `qemu_verify.py`、`src/relay.c`：原厂 sshd 的隔离验证；客体 TCP 仅回环，经现有串口传递 SSH 字节，不给 QEMU 增加网卡、主机监听或沙箱例外。
- `recovery.py`：只解析主机元数据并有界观察恢复，不加载 USB 后端；连续两次匹配身份、驱动和媒体形状才通过。
- `packages/preflight-once/`：已使用的历史预检载荷、批准及结果，禁止复用。
- `verification/`：实际执行证据及失败记录；`summary.json` 是旧封存快照，最新离线修复记录位于 `reporting-recovery-v2/`。
- `reference/`：参考提交与来源摘要。上游脚本未直接运行。
- `vendor/`：封存的协议引擎、目标 ABI 样本、Python 依赖与许可证；约10 MiB，没有复制37个分区镜像或整个 SD 卡镜像。

执行与恢复步骤见 [实机执行与恢复方案](实机执行与恢复方案.md)。验证范围见 [离线验证说明](离线验证说明.md)。

## 本机命令

复用当前工程已安装的 Python，不安装或修改系统依赖：

```sh
TASK_PY="../.venv/bin/python"
"$TASK_PY" -B -m unittest discover -s tests -v
```

仅在未来确需重新准备预检时使用新目录，不删除旧操作或尝试锁；以下命令只构建材料，不批准或执行实机：

```sh
"$TASK_PY" -B lab.py prepare-preflight --output packages/preflight-next
```

QEMU 验证额外复用 SSH 技能现有虚拟环境中的 Paramiko/cryptography，仅在本次进程加载。不会调用该技能的服务器配置、连接守护进程或自动重连功能，不修改 `~/.ssh/config`。测试私钥仅在主机内存，只有测试公钥进入客体；主机指纹从本次客体串口取得后逐字节匹配。

## 一次性入口的保护

双击 `start-preflight.command` 时，没有本次有效 `approval.json` 就立即退出：不启动 sudo、不执行 ioreg、不加载设备后端。CLI 还要求显式 `--device-io`、macOS 管理员身份、操作/源材料/解释器/libusb 摘要及唯一尝试锁。批准模板本身不能执行。

当前没有提供自动批准命令。后续在用户明确确认具体实机步骤后，才生成绑定本次摘要的批准文件。不得通过编辑旧批准、删除锁、降级摘要检查来复用会话。

包与操作绑定当前本机路径；移动或从 ZIP 解压到其他目录后，旧操作应检查失败。保留它作证据，在新位置重新准备新操作，不修改清单中的旧路径。

本机材料根目录已设为700。ZIP解压到新位置后，先对新材料目录执行 `chmod 700 /新位置/a7r5-ssh`，再准备新操作；检查入口会拒绝其他本机账户可访问的材料根目录，避免待sudo运行的依赖被其他账户替换。

## 已知边界

QEMU 的账户、挂载与网络是测试夹具，不证明实机现状。当前模拟器 `/etc` 未包含真实账户与 SSH 配置。sshd 二进制与 A7C II 报告一致，不意味着账户/PAM/NSS、联网和服务模式共存也一致。

当前候选固定 `ForceCommand`，关闭 PTY、密码、转发与 SFTP，不能称为已完成 root 交互终端。root 账户若为 `/bin/false` 或其他不满足条件的状态，必须停止；本包不修改 passwd/shadow，不解锁账户。

SSH 不是已验证的损坏固件救援入口。服务可能受休眠、模式切换、无线控制进程和看门狗影响；退出 QEMU 也不等于实机正常关机或恢复。
