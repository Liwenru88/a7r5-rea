## 2. 账户：首选私有视图，不先改持久 passwd

计划增加一个小型 AArch64 隔离启动器，流程如下。**该启动器本轮未实现。**

1. 在创建任何目录或写入副本前，记录原挂载命名空间标识，调用 `unshare(CLONE_NEWNS)`。失败即退出，禁止退回全局环境继续。
2. 将本命名空间内挂载传播改为递归私有，读取 `mountinfo` 确认隔离；只创建挂载命名空间，保留原网络命名空间。
3. 在该私有视图的既有 `/var` 挂载点覆盖独立 tmpfs。然后才在其中创建运行目录和 `/var/empty`。不对原 FAT 分区创建同名目录。
4. 从新读取并校验的 `/etc/passwd` 生成 RAM 副本，仅将唯一 root 记录的最后一项 `/bin/false` 改为 `/bin/sh`。UID/GID、密码字段、home、其他记录、换行和长度差异均需逐字节验收；不使用 A7C2 或别的机身备份。
5. 在私有视图中将该副本只读 bind 到 `/etc/passwd`。验证内部 NSS 查询返回预期 root，而父进程视图的账户摘要和挂载未变化。失败即终止子树，不做全局恢复写入。
6. 本次不增加用户、不修改 shadow、不解锁口令，不改变原厂 PAM/NSS 配置。若账户锁定或 Sony 定制认证仍拒绝密钥，停止并给出脱敏原因，禁止靠自动解锁继续。

挂载命名空间用于隔离挂载视图；共享挂载仍可能传播，所以“先切断传播，再做覆盖”是硬门槛。它不隔离网络，也不是能约束恶意 root 命令的安全沙箱。[Linux 挂载命名空间说明](https://man7.org/linux/man-pages/man7/mount_namespaces.7.html)

实机尚未知：相关内核配置、`CAP_SYS_ADMIN`、安全模块限制、bind/remount 支持、NSS 查询及 sshd re-exec 是否符合该方案。QEMU 即使通过也不能替代实机能力检查。不能只比较命名空间编号就声称隔离完成，必须验证父进程视图未变化。

如果这条路线不支持，才另行准备“持久 passwd 单字段修改＋原件双备份＋独立恢复入口”的方案，并重新说明风险、取得批准。本方案不带该回退代码，不写持久 `/var/empty`，不关闭 StrictModes 规避问题。

## 3. 临时目录与材料预算

计划在私有 `/var` 视图挂载 `tmpfs,size=4m,mode=0755,nodev,nosuid`，只允许 root 所有者；需先验证可用内存并设置空间门槛。4MiB是容量上限候选，不是已测内存需求，也不是预先分配4MiB。

| 私有路径 | 内容 | 权限/上限 |
|---|---|---|
| `/var/empty` | 原厂 sshd 可能要求的空降权目录 | root:root，0755，保持空 |
| `/var/run/a7r5-ssh-N` | 本次独立目录 | root:root，0700；N为新nonce |
| 同目录 `passwd.view` | 本机账户副本，仅root shell单字段差异 | 0600，bind视图只读，不记录密码字段 |
| `authorized_keys`、`sshd_config` | 指定公钥和封存配置 | 0600；配置与公钥合计≤64KiB |
| `host_ecdsa`、`.pub` | 现场生成的主机密钥 | 私钥0600，仅RAM；公钥可随USB回执导出 |
| `sshd.pid`、受限运行日志 | 本次状态 | 日志≤32KiB；不含私钥或密码字段 |

写前要求私有 tmpfs 可用空间≥2MiB，写后复核余量；这些是待验证的保守预算。不要把整个 firmware 或 SD 镜像复制进来。原厂 sshd、ssh-keygen、BusyBox 使用既有程序。

`StrictModes yes` 不变，检查解析后的真实路径、所有者和写权限，拒绝链接。现有 `prepare-smoke.sh` 仍使用 `/tmp_network` 并拒绝本次实测环境；不得把本节当成它已经适配完毕。[上游7.9p1路径权限检查](https://github.com/openssh/openssh-portable/blob/V_7_9_P1/misc.c)

## 4. 网络：先补最小证据，再启动 SSH

当前没有相机局域网IP和服务退出后的网络回执。最短下一步是一个**不启动SSH的跨模式补证阶段**，而不是先改账户并开监听。

未来单独批准后，先由用户在相机正常功能下确认可用的 Wi-Fi/局域网模式和指定地址；不由脚本修改无线配置、启动 supplicant、加载模块、改变路由或关闭原厂访问认证。不扫描网段、不试探未知地址。

随后使用新的固定补证包，检查命名空间能力和上述隔离视图，并运行有硬截止时间的元数据观察器，记录 STOP 前后的接口、IPv4、路由、原厂进程存活和命名空间标识。观察器不启动 SSH，不挂卡、不写 SD。目标是确认：普通 USB 恢复时 WLAN/IP 是否恢复，以及受监督进程能否跨 STOP 存活。

**这需要新状态机。** 当前 `root_once.c`/`PreflightOperation` 只在任务 DONE、中和和重复状态通过后允许 STOP；若直接等待前台 sshd 退出再 STOP，普通模式网络可能一直等不到。不能把“sshd启动”当作放宽该门槛的理由。下一版必须区分：

```text
固定入口中和 → 初始化完成、受监督后台任务READY回执 → 有条件的一次STOP
→ 仅主机核对USB/媒体 → 普通模式网络出现 → 后续独立SSH验收窗口
→ 本次子树全部退出 → 外部原账户/挂载未变化 → 屏幕确认
```

READY门槛必须证明：本次nonce、root、精确中和、持久写入已结束、监督器启动身份与硬截止时间、父视图不变；子进程不能继承会使结果管道一直不关闭的文件描述符。旧入口不会因本方案而自动放宽门槛。

若无接口/IP、身份异常、进程被切换终止或窗口已过，则到时退出，不重发DEBUG、不重发STOP、不延长寿命、不重新拉起。该阶段通过前，不生成可执行SSH实机批准。

## 5. 首次 SSH 部署的边界

在隔离和跨模式补证通过后，再制作绑定实测地址、设备位置、程序摘要、公钥、状态机及清理门槛的新一次性包，并交用户确认。

- 原厂 `/usr/sbin/sshd` 的独立前台实例，端口2222；只绑定相机当次明确的局域网IPv4，不绑定0.0.0.0，不改原厂22端口配置、不停止原厂进程。
- 仅指定 Ed25519 公钥；客户端私钥只在Mac保存。关闭密码、键盘交互、PAM、PTY、代理/端口转发、隧道及SFTP，只允许root。
- 第一阶段 `ForceCommand /bin/busybox cat /proc/self/status`，`MaxSessions 1`。成功仅表示受限root SSH命令；交互shell、传文件、固件写入都未开放。
- 主机公钥在监听前经已验证USB通道导出并绑定nonce；Mac使用独立known_hosts，开启严格指纹校验。拿不到可信指纹就停止，不使用关闭校验的参数。
- `sshd -t`、私有视图和权限检查通过后才可启动；配置检查通过不代表认证、TCP连接或恢复通过。
- 后续监督器总寿命候选≤90秒：普通模式等待≤45秒，固定命令窗口≤20秒，清理有界且预留余量；不得自动续期。现有监督器仅支持5–30秒，本轮未改，90秒设计须在新实现中单独验证。
- 自动恢复观察可能消耗整个窗口；若错过就停止，不能为赶时间跳过USB/媒体核对。跨模式补证的实际时序用于最终定值。

实机首次只连接指定地址的一次SSH会话；错密钥和各种注入失败测试在隔离环境完成，避免对相机反复尝试认证。

## 7. 退出、异常与验收

1. 监督器只管理本次未回收子进程及收养后代，先TERM再有界KILL并wait；不用进程名匹配、历史PID或全局kill。需要保留并核对父子关系和启动标识。
2. 后代不为空、私有挂载仍被引用或2222监听不能证明消失，记为恢复未确认，不宣称成功，不向相机自动发送恢复命令。
3. 从外部视图核对原账户和SSH配置摘要、原临时目录权限、原挂载未改变。不能仅依赖被覆盖视图中的自我报告。
4. STOP最多一次，只有该新包全部READY/中和门槛通过才允许。Pipe error保留原样；不因响应失败重发，也不因返回成功就宣布恢复。
5. 本机只观察同端口054c:0e0a、驱动和会话前媒体形状；已知过渡可等待，最多45秒，连续两次完整匹配通过。陌生身份/端口/媒体、主机查询异常即停止。此检查不读卡、不验证卡内内容，也不证明已正常拍摄。
6. 用户查看屏幕。屏幕异常、USB/媒体未恢复：保持独立供电和现场，不自动拔线、断电、重试。后续恢复单独设计并确认，不依赖已消失的SSH连接自救。

首次验收必须分别取得：指定公钥认证、固定命令Uid/Gid四项为0、可信主机指纹、本次监听及子树消失、外部原文件/挂载不变、USB/媒体恢复、用户屏幕正常。任何一项缺失都不能称为“SSH部署完成”。拍摄、休眠、长时间运行、PTY及固件升级不在这次最小验收内。
