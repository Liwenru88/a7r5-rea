# A7R5 无 SSH 隔离能力与跨 STOP 联网补证

日期：2026-10-20。对象：ILCE-7RM5 / 4.00，同端口 `0x01100000`。**本文件供确认，尚未执行实机。**

已实现本机准备、私有命名空间启动器、有界 RAM 观察、跨 STOP 主机门槛和独立读回入口。此包不启动 SSH，不生成密钥，不改任何账户字段，也不开放任意命令。当前没有有效批准；双击入口会在 sudo 和设备查询之前停止。

本轮只在本机及无网卡、无物理设备直通的 QEMU 中验证。实机前需要另行确认固定文件写入、认证/START、一次 DEBUG、私有挂载、一次有条件 STOP，以及保持供电到结果读回的风险。

## 1. 包的位置及两阶段边界

本机一次性材料：[packages/isolation-once-20261020-01](packages/isolation-once-20261020-01/operation.json)。

本次run_id：`cbbcadcbdc9b4cd7b7238e65f9e7face`；启动器22,000字节，固定载荷8,872字节。源码、两份机器码、固定脚本和运行依赖均由operation摘要绑定。

- `run-probe.command`：首次补证。允许未来已确认的固定文件写入、认证/START、一次DEBUG；门槛通过才一次STOP。后台仅向RAM写元数据。
- `run-collect.command`：**独立确认后**的固定读回会话。有认证/START及有条件的一次STOP，没有文件写入、chmod或DEBUG。绝不由首次入口自动调用。
- `approval-probe-template.json`、`approval-collect-template.json`：均为`accepted=false`，不是有效批准。读回批准还须绑定前次恢复收据的SHA-256和用户屏幕正常确认。
- `operation.json`、`build.json`、两份头文件、`task.sh`、AArch64载荷/启动器及预加载字节：用于逐项审查与摘要验证。

为什么需要独立读回：服务退出后，已验证的USB文件通道不可继续使用。为避免在STOP后写内部FAT分区或SD卡，最终结果仅留在`/tmp_network`的RAM目录。本包不会借此偷偷重新认证或切回服务模式。若只批准第一阶段，只会取得READY、USB恢复及屏幕结果，最终联网轨迹仍标为待读回。

归档 ZIP 不含有效批准、历史锁、真实账户原件或原始分区镜像。操作绑定当前Mac路径及运行依赖；解压到别处不能直接执行旧operation。ZIP用于审查/保存，实际执行以原位置的新一次性目录为准，不能改旧路径、删锁或重写摘要绕过检查。

## 2. 启动器实际做什么

1. 固定执行器先核对精确DEBUG argv和本次预加载条目，中和为512换行，再启动固定任务。没有新的通用shell接口。
2. 固定任务核对启动器SHA-256，仅为本次新上传文件设置执行权限，并执行`--launch`；没有其他可选命令。
3. 后台监督器建立独立会话，关闭继承的任务输出描述符。先验证`/tmp_network`实际为tmpfs、root所有者、权限为1777/0755/0700之一、剩余空间至少512KiB；拒绝已有本次目录。
   全局RAM目录用于后续读回；使用已核对tmpfs类型的父目录描述符创建，之后的create/rename都绑定本次RAM目录描述符。即使原路径被移走或重新挂载，也不向替换路径写入。读回找不到原RAM对象就失败，不创建替代目录。
4. 私有子进程只执行`unshare(CLONE_NEWNS)`；挂载传播递归设为private，并核对mountinfo。随后才覆盖子进程的`/var`为4MiB上限tmpfs。
5. 子视图创建原字节`passwd.view`，将它只读bind到本视图的`/etc/passwd`，验证内容一致且写打开返回EROFS；写入唯一RAM证明标记。**不把root的`/bin/false`改成`/bin/sh`，不解锁、不读shadow。**
6. 父监督器在原命名空间核对账户字节、相关挂载记录、命名空间标识、原临时目录权限、原`/var`中不存在证明标记；子进程则必须具有不同挂载命名空间。
7. 观察器从内核读取接口计数、IPv4地址和路由；不改网络、不bind/listen/connect/send，不扫描地址，不创建监听。IPv4通过本机内核ioctl查询，使用UDP类型描述符不等于发送UDP数据。
8. 观察75秒，每5秒采样，轨迹最多32768字节，沿用固定执行器的32KiB文件上限。超限、读取失败、子进程消失或父视图变化均记失败，不截断后冒充完整结果。
9. 到时只终止并回收本次尚未回收的直属私有子进程，先TERM后有界KILL；子进程另有父死SIGKILL和有限循环。没有按名称kill、历史PID操作或递归删除。

命名空间隔离的是挂载视图，不是完整的root安全沙箱。`/proc/self/ns/net`若不暴露，记录`net:unavailable`，不将其解释为网络不存在或已独立验证网络命名空间。本包没有调用NEWNET，也不修改网络配置。[挂载命名空间](https://man7.org/linux/man-pages/man7/mount_namespaces.7.html)、[unshare权限与错误](https://man7.org/linux/man-pages/man2/unshare.2.html)、[父进程死亡信号限制](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html)

本包未实现未来SSH需要的账户字段变更、NSS登录/锁定判断、`/var/empty`、密钥或sshd配置。通过本包只能推进隔离与网络证据，不能直接宣布root SSH可用。

`N`取本包`operation.json`的run_id。二进制各不超过128KiB，实际长度和摘要见build/operation文件。所有持久文件使用新nonce，不覆盖历史研究文件。

| 位置 | 内容/写入者 | 生命周期和恢复边界 |
|---|---|---|
| `/tmp/jiritsu/a7r5-N.probe` | 固定AArch64启动器；完整上传、读回；固定任务chmod 700 | 位于已观察的nflasha6持久映射，保留残留，不自动删除 |
| `/tmp/jiritsu/a7r5-N.so` | 固定预加载执行器；完整上传和读回 | 同上 |
| `/etc/ld.so.preload` | 只接受512换行→本次`.so`条目→512换行 | 位于持久nflasha10；中和是本次基线，不证明原厂初始状态 |
| `/tmp/jiritsu/a7r5-N.state.new`、`.state`、`.output` | 固定执行器状态、输出，输出少于32768字节 | 持久小文件；主机取得DONE及稳定状态后才通过READY门槛 |
| `/tmp_network/a7r5-ns-N/` | root 0700目录；ready、heartbeat(.new)、trace、result | 仅tmpfs；轨迹≤32KiB，其他单文件≤4KiB；任务后保留待读回，断电/重启可能丢失 |
| 私有子视图 `/var/passwd.view` 和 `/var/a7r5-ns-proof-N` | ≤8192字节的原字节副本及20字节证明标记 | 仅私有tmpfs，不输出密码字段；子进程释放挂载引用后消失 |
| 私有子视图 `/etc/passwd` 挂载 | 同内容RAM文件的只读bind视图 | 不写原文件字节；父视图必须保持原样 |

主机确认READY之后，固定执行器的白名单写入调用已结束，输出和状态已fsync；后台只更新本次RAM元数据。这不宣称全机没有其他原厂后台I/O。

不写原账户/SSH配置、无线配置、固件更新区或SD卡，不挂载卡、不发送GO、不格式化、不创建开机服务。主机为服务切换正常卸载相机媒体是已有协议流程，有设备状态副作用，需要纳入实机批准。

## 4. 第一阶段：待确认的执行步骤

1. 相机稳定电池/独立供电，USB连接已验证端口，普通海量存储身份，屏幕正常、无格式化/修复提示。本包不自动改变Wi-Fi设置；若希望观察联网，需先由用户在正常功能中确认所选无线模式。本轮不要求现在操作。
2. 审阅本包材料、写入表、失败表，取得新的明确实机授权。旧SSH预检批准、旧包和旧锁均不复用。
3. 才生成本阶段绑定operation摘要的有效批准，在专用Terminal完成本机sudo认证。密码不进入聊天、脚本或日志。
4. 主机元数据核对普通型号、端口、驱动、媒体形状；正常卸载相机媒体；按原流程认证/START进入服务身份。身份不符停止，不换设备或端点。
5. 读版本和精确512换行基线，再上传/读回启动器；载荷武装前再次核对版本与基线。未知、空内容或服务错误都不当作可覆盖状态。
6. 上传/读回固定`.so`和预加载条目，DEBUG仅一次。记录原始响应头、部署状态、固定入口状态/输出。
7. 根据结果分两种门槛：
   - **READY_FOR_STOP**：固定入口DONE 0、root、输出长度准确；READY会话/父子身份/账户摘要匹配、父子挂载命名空间不同；心跳在7秒内向前推进且剩余≥30秒；READY不变、512换行中和、重复入口终态不变。还预留10秒STOP安全余量，耗尽则不退出。
   - **NEGATIVE_CLEAN**：固定入口DONE 0，明确负结果代码与errno，root、父账户/挂载不变、私有子进程已回收；RAM轨迹长度/SHA-256和重复终态通过。这仅允许安全退出，不表示隔离可用。
8. 仅上述门槛通过才尝试一次STOP。Pipe error保留，绝不重发。之后仅观察主机元数据：最多45秒，连续两次同端口普通身份、驱动与会话前媒体形状完整匹配才通过；未知身份/媒体或查询异常立即停止。
9. 用户仅查看屏幕并确认。第一阶段结束，不自动开启读回。READY时最终客体诊断仍待取回；NEGATIVE_CLEAN已在同一会话采集终态，无需为负结果自动再认证。

`execution_succeeded`只表示该阶段门槛及主机恢复通过；`acceptance_complete=false`、屏幕待确认、`ssh_deployment_allowed=false`保持分层。阶段成功不代表75秒轨迹、网络或SSH成功。

## 5. 第二阶段：独立批准的固定读回

仅第一阶段READY、一次退出、主机恢复通过，且用户确认屏幕正常后，才可准备读回批准。该批准绑定前次收据SHA-256，并至少等待首次会话结束后90秒，不自动等待后启动。

需要保持相机独立供电，不重启，否则RAM结果可能丢失。90秒是保守主机等待；相机休眠、内核阻塞或异常暂停不由墙钟证明已经结束，仍必须读到完整终态。

读回会话重新核对身份并认证/START，只读：版本、512换行预加载、本次RAM result/trace和重复result。完整检查nonce、root、父/子PID与启动ticks、原件不变、子进程已回收、长度及SHA-256。成功及已清理的负终态均可保存，不能只保留成功结果。

只有读回和中和门槛全部通过才一次STOP，再核对USB/媒体及屏幕。没有上传、chmod、DEBUG或账户操作，不自动补文件，不把`0x10000006`解释成文件不存在并另寻路径。

网络轨迹里的非回环IPv4只表示当次内核有该地址；不证明Wi-Fi关联、Mac可达、路由可用或SSH可登录。客体elapsed_ms和主机STOP时间可作有采样间隔误差的时序对照，不伪造精确跨STOP时间点。原厂应用、拍摄和休眠共存也尚未验收。

## 6. 失败与恢复

| 失败位置 | 自动行为 | 后续恢复边界 |
|---|---|---|
| 批准缺失/未接受、摘要变化、已有本阶段锁 | 在sudo/设备查询前拒绝 | 保留旧包和锁，重新审查，不编辑摘要或删锁重试 |
| 普通身份、端口、驱动/媒体不符 | 不打开USB会话 | 保留主机记录；不换设备、不操作卡 |
| 预加载/版本/读回不符，尚未DEBUG | 停止；只有仍完整的通道和本次精确武装条目才尝试一次中和 | 无完整退出门槛则不自动STOP；另行审查恢复，不盲写 |
| 协议/传输失败、旧状态、超时、非root | 不再发送后续文件请求，不重发DEBUG，不自动STOP | 相机可能停在服务身份；保持独立供电和现场，单独准备受限恢复方案 |
| 固定入口DONE但非零退出 | 仅保存已声明长度的固定输出后停止，不继续启动器操作或STOP | 启动阶段步骤/errno在固定输出中；父子存活未确认时不猜测已清理 |
| 命名空间或私有挂载失败，完整NEGATIVE_CLEAN | 保存负证据，允许一次STOP | 不回退到全局mount、持久账户改动或SSH |
| READY后观察器失败/被模式切换结束 | 有界回收并尽力写RAM终态，不拉起重试 | 若不能证明回收/原件不变，后续读回不能自动STOP；保留原始失败另行审查 |
| trace超限或原件变化 | 记录失败及部分轨迹，不按截断数据验收 | 原件变化不会自动覆盖恢复；不得宣称账户已还原 |
| 读回结果缺失、哈希/身份/清理不符 | 保存已取得原始数据，立即停止，不写文件、不重试、不自动STOP | 不能把缺失当成已结束；可能需另行批准受限恢复 |
| STOP错误或USB/媒体未恢复 | 只进行已批准的主机观察，不补发 | 不自动拔插、断电、重启或重跑；保持供电，记录屏幕状态 |

信号和截止时间约束的是有界等待及本次进程；不能保证处于不可中断内核等待的任务必定消失。清理回执缺失就是未确认，不能用“超时”替代回收证明。

持久载荷/状态/输出不自动删除；RAM目录也保留待读回。不做全局umount、chmod旧目录、按名称kill、历史PID清理或`rm -rf`。若外部账户或挂载异常，当前包没有回写原账户的功能，恢复必须独立确认并基于本机原件。
