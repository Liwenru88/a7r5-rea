# A7R5 交互 SSH、SCP 与后台服务候选

## 当前状态与授权边界

本版提供交互 root shell、PTY、默认 SCP/SFTP、无固定寿命的后台监督器，以及独立启用的开机自启候选。材料包默认不启用自启，不含实机批准，不自动联网或启动 Terminal。安装、永久预加载修改、相机重启验收必须另行确认。

包内 `manifest.json` 给出本次会话、所有摘要、精确上传路径、安装目录和 RAM 结果目录。`qemu_only=true` 的测试包使用模拟触发程序，禁止安装相机。正式候选使用 `/usr/bin/bootin.elf` 触发；此前实机通过的600秒包保持不变。

“无固定寿命”表示不因600秒到期退出，不保证睡眠、网络断开、原厂模式切换或重启期间始终在线。服务不自动重启，不改名绕过原厂网络管理器的关闭策略。

## 实现与写入清单

- 继续使用原厂 `/usr/sbin/sshd`、`/bin/sh` 和内部 SFTP；端口 `0.0.0.0:2222`，密码沿用用户指定值，仅在私有 RAM passwd 副本写入加盐哈希。原 `/etc/passwd`、NSS、原厂 sshd 配置不改，原 shadow 必须不存在。
- 移除 `ForceCommand`，设置 `PermitTTY yes`，私有挂载视图建立 devpts；后台持续核对父视图。私有命名空间用于避免账户落盘，**不是约束 root 的安全沙箱**：登录后手动执行写命令仍可能修改共享的相机文件或设备。
- `Subsystem sftp internal-sftp` 支持现代 OpenSSH 默认 SCP 和 SFTP。原厂缺少独立 scp 程序，**不承诺 `scp -O` 旧协议**。[OpenSSH 9.0说明](https://www.openssh.org/txt/release-9.0)
- 初次安装上传 `manifest.json:upload_map` 中5个固定文件；一次性载荷先将预加载中和为精确512换行，再运行固定 stage 脚本。stage 只新建本包安装目录，已有目录拒绝覆盖。
- 安装目录包括 `ssh-service.arm64`、`boot-hook.so`、`control.sh`、精确基线备份 `preload.backup`，以及相机生成的一对稳定 ECDSA 主机密钥。私钥不上传回 Mac，不在每次启动重新生成。
- 运行结果写入 `/tmp_network/a7r5-ssh-<run>/`。私有 `/var` 为4MiB tmpfs，私有账户和 sshd 配置只在该视图存在。SCP 不受固定命令限制，建议只向新建的 `/tmp_network/` 测试目录传输；RAM空间有限。
- 自启启用阶段额外写安装目录 `enabled`，将全局 `/etc/ld.so.preload` 从已知512换行原子替换成本包库路径加换行。禁用时只接受本包精确内容，恢复精确备份；未知内容拒绝覆盖。

## 为什么只能称为自启候选

静态证据显示：根分区、`/usr`只读；启动脚本在挂载 fstab.ext 后执行动态 `/usr/bin/bootin.elf`；`/tmp`、`/etc`、`/var`来自同一可写 FAT 设备。没有已验证的安全可写 rc.local。

钩子只在 root、精确 bootin argv[0]、本包 enabled 标记匹配时派生后台子进程；原厂 bootin 不等待服务。子进程有界等待30秒 RAM 挂载就绪，启动一次，不等待固定IP。非触发程序只经过构造函数检查。

但库本身仍会被动态加载器加载至许多进程。库缺失、损坏、ABI变化、FAT权限语义和启动时序可能影响启动，USB恢复也可能不可用。FAT没有日志，临时文件、sync和rename不能承诺断电安全。QEMU模拟触发通过，不能证明相机冷启动安全。禁用标记仅阻止新派生，不能使损坏库停止被加载；必须恢复全局预加载。一次禁用后本包拒绝再次启用，保留原停用证据。

## 离线材料与核验

在研究工程根目录使用已有 Python 环境：

```sh
./a7r5-qemu/.venv/bin/python -B a7r5-ssh/ssh-service/package.py check <材料包目录>
```

包内 `sources/` 是本版源码快照，含ABI头、启动汇编和模板；重建入口仍使用研究工程的 `package.py`、原厂 glibc 与 LLVM/lld，不是脱离研究工程的独立工具链。所有新 ELF、配置、预加载候选和USB固定脚本都封入材料包。包内哈希可离线猜解短密码，应保存在受限目录，勿公开分发。

`verification/验证结果.md` 和相关 JSON 区分当前离线证据与未验证项。失败日志保留，不把早期失败改写为成功。

3. 单独批准安装阶段后，使用已验证的服务入口上传本包 `upload_map` 五项，逐项回读摘要；认证/START、一次 DEBUG 执行 root 载荷，保存原始响应头。载荷执行 `task.sh` 固定脚本，`stage.sh` 校验原厂版本/sshd/账户及材料摘要，创建新安装，生成主机密钥并启动后台服务。**此阶段不启用自启。**
4. 验收 root DONE 0、READY、心跳、父视图未变、精确中和，以及可信回读的 `host-public-key`。全部符合才一次 STOP；若失败不重发 DEBUG、不重试STOP、不自动断电。核对普通USB、媒体和屏幕。
5. 将可信USB回读的公钥文件交给下述本机绑定入口，再连接相机当前机身显示的单一IP，验收终端、文件往返和 exit。不能拿未认证 `ssh-keyscan` 代替可信绑定。网络失败不表示 sshd 未启动，应分别核对服务回执、IP和USB恢复。
6. 交互功能与外部停止清理完成后，**另行批准**自启启用。父视图运行本包 `control.sh enable-autostart ENABLE_AUTOSTART_<run>`；先核对脚本摘要、安装完整性和已知基线。脚本无冷启动动作。启动失败或系统异常立即停止，不能靠反复重启测试。
7. 另行安排一次正常关机/开机验收：同一持久主机公钥、服务READY、终端/SCP、原厂菜单与正常关机均须有证据。未完成前不能称为永久可用。

上述USB实机调度需要基于新盘点生成并审核单次执行清单；本包不附会自动创建批准或直接接管USB的入口，防止把旧600秒固定命令执行器误用为无期限安装器。

## 正常使用（部署成功且可信绑定以后）

```sh
python3 mac_client.py bind-host-key /可信USB回读路径/host-public-key
python3 mac_client.py ssh --ip 10.10.10.177
python3 mac_client.py upload ./test.bin /tmp_network/test.bin --ip 10.10.10.177
python3 mac_client.py download /tmp_network/test.bin ./received.bin --ip 10.10.10.177
```

密码由系统SSH提示输入，不使用聊天口令自动 sudo。直接系统 SSH/SCP 也可以，但应保留本包 known_hosts、HostKeyAlias 和 `PubkeyAuthentication=no`，避免代理提交多个密钥导致认证次数耗尽。

交互 `exit` 只结束当前 shell，后台服务继续运行。原厂 BusyBox 是裁剪版本，不保证含桌面 Linux 的 `id`、`tty`、`scp` 等命令；可用 shell 内建和 `/proc/self/status` 核对身份。默认 shell 没有“全套 Linux 工具”的含义。

## 停止、恢复与卸载

先从本包父视图管理入口执行 `control.sh disable-autostart`：核对 marker/库/备份，停用标记并恢复精确512换行。只恢复本包owned内容，任何未知内容或并发变化立即拒绝。失败会保留互斥目录和临时文件，不自动清理后重试。

随后在**本服务外部**执行 `control.sh stop`，等待精确 `code=0 parent_unchanged=1 child_tree_reaped=1 child_terminal_seen=1 listener_absent=1` 终态；`--stop` 非零或缺失结果均停止。不能在唯一SSH连接里依赖自身停止后继续收取结果；应由独立USB受限管理会话回读。已结束的RAM目录再次启动会归档，活动实例重复启动拒绝。

恢复不能依赖相机必然可达：若进不了系统或USB，则不能保证软件恢复；没有已验证的刷回/硬件救援能力。不要为了重试自动断电。

卸载前必须确认全局预加载已恢复、标记停用、服务及后代消失、USB/媒体/屏幕正常。目录和上传残留只在新授权下归档或删除，本版不提供 `rm -rf` 自动卸载，也不删除旧包、锁和证据。

## 仍存在的风险

固定短数字密码配合通配监听、无限期服务和完整root shell，风险高于旧600秒只读包。单连接一次认证与 MaxStartups 不能阻止长期反复猜密；不能端口转发到公网。根账户能操作系统和原始设备，SCP没有写入路径沙箱。命名空间只隔离本工具预定账户变更，不保证任意root命令可回退。

尚未证实的项目包括真实冷启动、长时间运行资源占用、待机/模式切换共存、网络管理器killall行为、持续全局预加载对原厂应用的影响及损坏库时的救援路径。
