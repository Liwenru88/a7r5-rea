# 网络触发自启离线验证记录

验证范围：新增network_hook.c、common.h、control.c及主机SSH调度，使用隔离临时文件和断网QEMU。没有相机、USB、SD或外部网络操作。

## 本机回归

执行命令见verification/regression.json，输出见verification/regression.txt：**62 passed**。C夹具以AddressSanitizer及UndefinedBehaviorSanitizer编译运行，覆盖：

- 20路并发及后续重复触发只有一次固定helper调用；非目标、错误argv、错误命名空间、不可用RAM、坏权限、claim符号链接、半写claim、fork失败均不启动。
- 健康实例、空目录、陈旧/PID复用证据都不删除、不杀进程、不启动第二个实例；端口占用、坏TCP表、启动器摘要/权限/FIFO、最终门槛前禁用、exec失败均保留终态并拒绝再试。
- 模拟恢复前后持久配置保留但RAM重新建立的生命周期；这是普通临时目录模拟，不是实际休眠恢复。
- 安装成功后当前RAM证据不变；未知指针、材料变化、当前实例变化、锁、空间和同步/rename失败不能报告成功；旧入口损坏时拒绝回滚，但仍能静态中和。
- 主机预检绑定真实挂载栈及本次人工启动READY；6个传输失败阶段分别验证立即停止、不重试、不自动回滚、敏感口令脱敏；恢复动作只调用一次静态控制器；模板不能充当批准，失败锁不能复用。

一次检查发现静态控制器错误地拒绝内核固定的/proc/self/exe链接：先将夹具改成真实链接形式，复现stage=17失败，再只针对固定内核路径修复并通过定向测试；其他上传路径继续拒绝符号链接。最终62项回归包含该契约。worker另行重置自身SIGCHLD，覆盖宿主忽略SIGCHLD的继承场景，不更改原调用进程。

## AArch64及QEMU

两个生产ELF由本机LLVM构建，使用目标glibc 2.25链接。静态控制器没有INTERP或NEEDED；触发库有正确构造入口。rebuild.py在临时目录重建，**两个ELF逐字节一致**。

断网NativeVM采用固定运行输入、macOS沙箱、-nic none和QMP正常退出。verification/guest.json记录passed及以下结果：

1. 旧bootin-only构造器面对有效的网络夹具程序不启动helper，复现实机入口遗漏。
2. 新控制器安装会抑制当前开机，网络调用不启动第二个实例。
3. 仅重建夹具RAM模拟恢复到安装前状态后，网络程序新加载触发固定AArch64测试helper，execveat从已校验描述符运行成功。
4. 重复触发不增加调用；恢复陈旧RAM则拒绝，保留原证据。
5. 回滚恢复旧指针；新库及旧helper损坏时静态中和仍成功，恢复512换行。
6. 精确生产ELF仅执行非目标程序加载及只读inspect拒绝；完整成功路径使用相同核心源码、仅替换路径/摘要常量的RAM夹具。

没有运行真实wpa_supplicant、sshd、账户修改或原厂联网操作。QEMU没有重启或进入原厂WARMBOOT；原始运行清单摘要未变，QMP退出码0。详细证据只复制有限RAM夹具输出，不打包巨大的虚拟器trace。
