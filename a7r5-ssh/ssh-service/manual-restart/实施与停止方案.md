# A7R5 单次手动恢复 SSH

目标为恢复当前开机的 SSH。自启02包的冷启动失败原因尚未确定，本包不修复或重新安装自启。

## 已知状态

2026-10-21，用户确认机身地址10.10.10.177、屏幕正常、供电稳定。主机观察到原端口普通USB身份054c:0e0a；一次SSH检查返回Connection refused，未进入认证。这不证明自启钩子在哪一步失败。

## 执行清单

1. 原端口普通USB、机型及完整媒体基线必须匹配。保持稳定独立供电、USB和Wi-Fi，不操作SD卡、不重启。
2. 两阶段认证/START，保存接口描述符、端点选择和全部文件响应头；不换端点。
3. 固定读取版本、现有预加载指针、启用标记、启动器；保存claim及RAM启动回执。只接受02包的精确预加载指针及已知启动器摘要。
4. 任何RAM实例证据已存在都停止，保留失败现场，不删除目录、进程、锁或回执。文件服务0x10000006只表示不可读，不当作不存在证明。
5. 仅上传一个新nonce的执行库到/tmp/jiritsu，回读一致后临时改写/etc/ld.so.preload并只发送一次DEBUG。执行库在调用启动器前恢复原自启指针；固定脚本再次校验原账户、版本、sshd、启动器与启用标记，确认RAM目录确实不存在才调用现有启动器一次。
6. 启动器沿用既有私有命名空间、RAM账户、0600 RAM密钥副本、密码认证、正常PTY、internal-sftp及0.0.0.0:2222无超时服务。不生成持久密钥，不改变原账户或自启启用标记。
7. DONE 0、精确输出、RAM密钥回执、READY、可信公钥、监听/banner、前进心跳、重复终态和恢复后的原预加载指针全部通过才允许一次STOP。失败不自动STOP、不重试、不自动断电；相机可能停留服务态。
8. 普通USB、驱动及完整媒体连续两次恢复后，仅一次已知主机密钥约束的root PTY登录，读取/proc/self/status并退出；不创建SCP测试文件。最后仅查看屏幕确认正常。

## 写入、风险和恢复

- 文件写入仅一个新执行库及临时预加载指针；执行器产生同nonce的state/output。库、state/output可能留在持久映射中，不自动删除。
- 恢复目标是既有自启指针，不是512换行；不借本次操作禁用或修复自启。若指针已不同，停止。
- 持续监听、固定root密码和终端误写风险与已安装服务相同；私有命名空间不是强安全沙箱。
- 临时预加载恢复失败、协议失败、启动器拒绝或心跳门槛不符时立即停止，保存日志；不强行中和、改账户、清理现场、换端点、重发DEBUG、重启或断电。根据保存状态另行准备受限恢复。
- PTY失败时不重连，已启动服务可能仍在运行。屏幕和供电状态只由用户确认。

## 批准与证据

离线检查为runner.py check，不联网、不枚举USB。实机入口要求本包operation.json摘要及完整风险文本对应的approval.json，并有不可复用ATTEMPT_LOCK。模板accepted=false不构成执行批准。旧包、旧锁和失败证据保留。

离线测试证明的是恢复指针、拒绝已有实例、协议与退出门槛；不是机身自启、实际SSH恢复或Wi-Fi可达性验收。实际执行须单独确认。
