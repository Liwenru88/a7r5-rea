## 1. 本次推荐路线

通过当前可用的 SSH 完成安装，不再进入 USB 服务模式，不认证/START、不 DEBUG、不 STOP。先验证现有私有命名空间、READY、主机密钥和挂载；然后上传三个固定载荷至 RAM，使用静态控制器写入独立的 `/etc/a7r5-autostart-<本包ID>` 目录，最后原子替换本包精确识别的 `/etc/ld.so.preload`。

启用时预先在 `/tmp_network` 建立“本次开机已占用”凭证，因此**不启动第二个 SSH 实例、不停止当前服务、不重启**。用户另行确认正常关机/开机后，RAM 凭证消失；原厂 root `bootin.elf` 的加载构造函数才可能派生一次后台启动尝试。父进程不等待网络或 SSH，后台最多等 `/tmp_network` 为 tmpfs 30 秒；固定通配监听 `0.0.0.0:2222`，无需先获得指定 IP。失败不自愈、不循环重试。

选择 `/etc` 的静态依据：`init → setup_rootfs → init2 → mount fstab → mount fstab.ext → bootin.elf`，其中 `fstab.ext` 将 `/dev/nflasha10` 挂载到 `/etc`。目前缺少 `/tmp/jiritsu` 在 bootin 执行时已可用的证据，因此不用它承载新自启库。此顺序是离线文件证据，不等于实际冷启动已通过。

## 2. 绑定与写入清单

具体 ID、路径、摘要见 `operation.json`，载荷总计约 54 KiB，不转存系统或 SD 镜像。

| 对象 | 动作与用途 |
|---|---|
| `/tmp_network/a7r5-auto-stage-<ID>/` | 新建 RAM 暂存，上传 `control.static`、`boot.so`、`ssh-service.arm64`；已有路径拒绝覆盖 |
| `/etc/a7r5-autostart-<ID>/boot.so` | 新自启构造库；仅 root、固定 argv0、真实可执行路径和启用标记匹配时派生 |
| 同目录 `ssh-service.arm64` | 已验证服务实现的重定位版本；保留私有账户、RAM 0600 密钥、devpts、SFTP、无超时后台及清理机制 |
| 同目录 `host_ecdsa`、`host_ecdsa.pub` | 在相机内部复制当前私有 RAM 密钥和可信公钥；Mac 只获得派生公钥，不导出私钥，不生成/替换现有密钥 |
| 同目录 `control.static` | 无动态加载器依赖的固定启用/禁用/恢复工具 |
| 同目录 `preload.baseline` | 保存精确 512 换行的已知中和基线 |
| 同目录 `enabled` | 本包 ID 启用标记，非口令；允许已知 VFAT 0755，拒绝组/其他用户写入 |
| `/tmp_network/a7r5-autostart-<ID>.claim/` | 本次开机防重复凭证；下次开机最多一次尝试，不因失败删除 |
| `/etc/ld.so.preload` | **持久改为本包 `boot.so` 的唯一绝对路径加换行**；只接受原内容精确为 512 个换行 |
| `/etc/.a7r5-preload-edit.lock`、`.a7r5-preload-new-<ID>` 等 | 原子写入的锁与临时文件；异常可能残留，不自动删除或重试 |

原 `/tmp/jiritsu` 安装、当前 SSH 进程、原厂 `/etc/passwd`、NSS 和 `sshd_config` 均不覆盖。不改系统分区镜像、不操作卡或网络设置。原厂根分区仍只读。

当前包绑定 `10.10.10.177:2222`、可信 ECDSA 指纹 `SHA256:GTxuohSMHGxvvFE3ZuRonvkA80YcLaC4Wy+a/DOgMUM` 和现有私有命名空间 `mnt:[4026533196]`。现有实例、IP、READY 或密钥变化时停止，不能靠改配置或跳过检查继续。

## 3. 启用的精确执行步骤（尚未批准）

1. 保持相机独立供电、当前 Wi-Fi/USB/媒体不变，确认屏幕正常。保留一个已登录的 root 终端，不退出、不重启。
2. 本机执行包完整性及 `--dry-run` 核对，不会联网。人工确认本包封印和写入风险后，才创建本动作的批准文件；当前仅有 `approved=false` 模板。
3. 一次只读 SSH 预检：root UID/GID、私有命名空间、完整 READY、`/etc` 的既知 VFAT 设备、`/var` 与 `/tmp_network` tmpfs、RAM 私钥派生的公钥配对。拒绝变化，不尝试找其他地址。
4. 一次 SSH 新建 RAM 暂存，三次 SCP 各上传一个固定载荷。
5. 一次 SSH 校验并执行静态控制器：重验会话、密钥 0600/505 字节、精确预加载基线、源/目标类型与所有权、固定载荷摘要、至少 256 KiB 可用配置空间及独占锁；建立本次开机抑制凭证，写入和回读后才替换全局指针，最后同步并回读。
6. 总计最多六次 SSH/SCP 连接，每次一次密码认证；非零返回、超时、输出异常均停止，不重试、不自动恢复或断电。保存原始 stdout/stderr 和本机结果，不记明文口令。
7. `A7R5_AUTO_ENABLED1 ... current_boot_suppressed=1 service_preserved=1 rebooted=0` 只证明安装回读和本次抑制，不证明开机成功。当前正常 SSH 仍可用；请只观察屏幕。后续重启必须另行确认。

包中 `01-启用自启.command` 只是该固定调度入口，不包含重启命令。本地缺少精确批准文件时立即拒绝，不会索取口令或联网。SSH 认证使用已存在的本机 0600 口令文件，不把密码放入命令参数、包或日志。

## 4. 首次重启的验收计划（另行确认，不在本包自动执行）

先确认启用收据和剩余访问手段，再由用户正常关机、待存取灯熄灭后开机。不开机前不能宣称通过。保持独立供电、禁止无人值守反复试启动。

启动后先查看屏幕和正常菜单；确认 Wi-Fi 已正常联网，再从相机或路由器读取当次 IP（DHCP 地址可能变化，不扫描）。在另行批准的单次会话中校验原指纹，验证 root PTY、`Uid/Gid`、固定只读命令和 RAM 中小文件 SCP 往返，读取自启 claim/attempt、READY、心跳及父视图原件摘要。检查无重复 2222 监听和后台实例，观察一段时间后再宣布“单次开机验收通过”。这仍不证明长期稳定、待机/休眠、录像功耗、升级兼容或所有开机路径。

网络设置本包不改；通配监听可等待后续接口地址出现，但不会自动开启相机 Wi-Fi。若菜单关闭联网，不能据此推断服务未启动。

## 5. 风险与可逆性

- **启动故障风险高。** 全局 `ld.so.preload` 被每个动态可执行程序的加载器读取。构造函数虽有限定，加载库本身发生在限定检查之前；库损坏、ABI/挂载时序变化、加载器或闪存故障可能影响 bootin、菜单乃至 SSH/USB 恢复。恢复文件和哈希不能保证救回无法启动的相机。
- **已有 root SSH 不等于独立救援通道。** 静态工具在现有可用终端里可绕开动态加载器；若新 SSH 无法认证、原终端断开且 USB 也不可用，本包没有已验证的物理/引导级恢复能力。不能把“重启看看”作为恢复方案。
- **落盘与掉电。** 原子重命名、回读和 `syncfs` 减少中途错误，但不能消除 VFAT、供电中断或满盘问题。写入失败可能留下新目录、锁、临时文件甚至已启用指针；本机连接超时也不能证明远端已停止。需人工判断后另行恢复，不自动回滚。
- **持久密钥与固定密码。** 相机配置分区可能按 VFAT 回报 0755，不能依赖 chmod 保证落盘私钥 0600；新目录会多保存一份同一密钥。运行时仍只用私有 tmpfs 0600 副本。包含密码哈希和可执行载荷，须保密。固定数字密码、root 和通配常驻监听增加局域网暴露，不要将 2222 暴露到公网；本包不添加防火墙或改密码。
- **常驻及兼容。** 无超时不等于守护进程重启策略：服务失败会停止，本包不循环拉起。可能增加内存、耗电及休眠影响；固件升级、账户原件变化或启动路径变化可能使门槛失败。钩子派生的短命启动进程若 bootin 不回收，可能留下一个僵尸记录，尚未验证原厂 bootin 的回收行为；每开机只允许一次助手执行，但重复调用 bootin 仍可能产生短命检查子进程。
- `/etc` 锁只协调本工具，不能阻止其他 root 程序同时写预加载；实施期间不能运行其他安装/清理工具。

## 6. 禁用与恢复步骤

**正常禁用（不终止当前后台服务，不要求重启）**：另行确认 `02-禁用自启.command`。静态控制器只接受本包唯一指针或已中和状态；将精确 `enabled` 重命名为 `disabled`，新建并同步 512 换行临时文件，原子替换并回读。无需校验正常的 helper/hook，故它们损坏不阻断禁用。已有服务继续运行，后台终止/目录删除应另行安排，不能把禁用自启写成“卸载SSH”。

**标记或材料损坏但当前 root 访问仍可用**：另行确认 `03-受限恢复.command`。其 `recover` 不依赖标记或载荷完整性，只识别本包精确指针；恢复已知 512 换行中和内容，保留目录和当前服务作为证据。不覆盖未知预加载。若已知中和则返回无操作成功；实际状态以收据为准。

若新动态程序无法运行，但已有 root 终端仍接受命令，可在明确确认后由该终端直接执行相机上固定的 `/etc/a7r5-autostart-<ID>/control.static recover`。不要先调用动态 shell、cat 或复制工具。该静态程序仍可能因存储故障、锁冲突等拒绝；遇到锁不得直接删除，须先核对是否还有写入进程及实际预加载/临时文件。

若所有 SSH/USB 都不可用：立即停止，不自动断电、重试、格式化、刷写或假定原厂升级可修复。需要另行评估独立恢复手段；本包不能提供已验证的救援保证。

所有禁用/恢复动作有独立本机尝试锁和批准文件，失败后不复用。同包不会自动发起第二次尝试。恢复后还需核对屏幕、USB/媒体正常状态；本包的 SSH 收据不能替代这些观察。

## 7. 离线证据

见 `verification/`：本机控制器与主机假传输测试、AArch64 构建/逐字节重建、ELF 依赖审查及断网 QEMU RAM 夹具。QEMU 测试使用替换路径和无害测试助手，不启动 sshd；真实生产静态工具另外执行过拒绝未知指针的只读检查。RAM 凭证的删除仅模拟下次开机 RAM 清空，**没有做相机冷启动**。

历史实机证据与静态启动链副本见 `proof/`。旧包、尝试锁和原始镜像不修改。包不含原始固件镜像、相机私钥或明文密码；运行依赖本机 Python 3、系统 SSH/SCP 及包外已有的受限密码文件。重建另需本机 LLVM/lld 和项目内经摘要校验的原厂 libc，不需要连接相机。
