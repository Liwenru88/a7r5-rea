# 本次 code=85 离线核对与一次受限恢复方案

本方案只绑定会话 `2f94aea65af84dc6ab01a667752d283c`，原安装包为 `no-ttl-install-20261020-03`。本轮仅准备本机材料和离线验证，不查询当前 USB、不发送相机请求。包准备完成不代表已经批准或执行恢复。

## 结论与证据层级

**已保存的实机回执：** root 工作状态为 `DONE 68 uid=0 euid=0 bytes=140`；140 字节输出为父结果 `code=85 parent_unchanged=1 child_tree_reaped=1 child_terminal_seen=0 listener_absent=1`。安装停止时没有 STOP、SSH/SCP 或重试。用户随后确认屏幕正常。依据：包内 `proof/result-install/worker-state.txt`、`worker-output.txt`、`phase-result.json` 和屏幕确认文件。

**静态代码证据：** `proof/materials/sources/launcher.c:150` 在收到非空子通知后，若通知不是 `PRIVATE_READY `，或该时刻父视图核对失败，就令父错误码为85。它不等于某一个具体子错误，也不能直接归因于 devpts、密码或网络。

`launcher.c:156` 只在后续监督主循环中将 `child_terminal_seen` 对应变量置1；85分支直接跳到清理，跳过这个赋值。`launcher.c:29` 的 `cleanup_children` 仍调用 `waitpid` 回收，最终父结果中的 `child_tree_reaped=1` 来自这一步。因此，`child_terminal_seen=0` 不能独自证明后代仍运行；也不能只因这个解释就放行 STOP，必须补齐本次子结果、ENDED心跳、重复父终态和当前账户/监听核对。

**仍未验证：** 本次 RAM `child-result`、可选 `diagnostic` 尚未回收，真实子错误未知。子结果的 errno 是清理入口保存值，不保证就是失败调用的即时 errno。即便取得 errno，也须结合子错误阶段，不能单靠它归因。

### 历史结果表述纠正

原日志共45个响应头；第35个响应的服务结果为 `0x10000006`，发生在状态轮询初期，后续第37个响应已读到76字节状态，最终读到140字节父结果。依据 `proof/result-install/events.jsonl:100-105`。旧失败说明中的“结果全零”不准确，原 `independent-failure-assessment.json` 已记为 `all_file_results_zero:false`。本轮另行纠正，不覆盖历史文件。此错误码不直接证明文件不存在。

## USB 判定差异与证据限制

旧 `proof/runtime/host.py:22-23` 对0336也要求产品名为 `ILCE-7RM5`，会拒绝同一端口下使用服务态通用产品名的节点。离线样例已复现这条拒绝分支。失败现场只留下“型号或位置不符”，未保存原始树，**不能确认当时是名称还是端口导致，也不能声明当前仍是0336。**

新入口先保存原始 IORegistry plist，再解析；严格要求唯一Sony设备、VID `054c`、原位置 `0x00100000`。libusb进一步要求 bus=0、ports=[1]。

| 主机状态 | 允许动作 |
| --- | --- |
| `0e0a`普通身份 | 型号必须为ILCE-7RM5，仅主机元数据核对；不打开libusb、不读相机文件、不STOP |
| `0336`服务身份 | 服务产品名如实记录；同端口后核对版本和本次nonce终态，全部门槛通过才一次STOP |
| `096f`已知过渡身份 | 仅限45秒主机元数据观察，不打开libusb、不STOP |
| 未知PID、端口改变、多Sony、初始无目标 | 立即停止，不猜测、不重新认证 |

本次成功通信引擎使用接口0/alt0、描述符顺序中第一对bulk端点，但没有留下完整服务接口指纹。新包沿用这个选择规则，记录配置号、接口类、全部接口端点描述符和选择结果，**不能声称与失败现场完整指纹逐项相同**。缺少方向、重复/非法端点、错误接口立即停；不切换配置或alt、不换端点、不reset、不detach内核驱动。若Darwin不支持驱动状态查询，只记录此限制并claim一次；若报告驱动活动或claim失败则停止，不尝试接管第二次。

## 一次退出门槛、执行步骤和时限

1. 用户确认本方案后，才创建绑定本包摘要的 `approval.json`；Terminal先离线检查材料、依赖、批准和未使用状态，再请求本机sudo。密码仅在Terminal本机输入，不从聊天或脚本传递。
2. 一次性锁先于所有主机/USB观察创建，失败也保留。先保存主机原始树。已普通或096f走仅元数据分支；0336走固定读取分支。
3. 0336只枚举并claim一次；固定读取窗口最多60秒，每次传输最多5秒，最多14次文件读取、28个select/get请求。每个成功内容和所有响应头/结果码保存到本机。协议/传输错误不轮询、不重发。
4. 固定版本、本次root状态/输出、父终态A、512换行A、已回收子终态、账户/配置原件、无监听、ENDED、父终态B、512换行B全部通过后，最多发送一次既有STOP：`bmRequestType=0x43,bRequest=1,wValue=0xc800,wIndex=0x2855`。这次只退出服务，不触发安装、停止请求文件或新载荷。
5. STOP返回Pipe error也不重发。之后只允许45秒主机元数据观察：原端口普通身份、指定媒体容量组合和存储驱动连续两次完整匹配，才报告主机恢复通过。STOP返回本身不代表恢复成功。
6. 最后请用户仅查看屏幕，单列屏幕确认。若起初已普通，则报告“主机已恢复、未回收客体诊断”，不会假称本次客体清理补证完成。

基线媒体：67108352、8589934592、118286712832字节分区；67108864与126877696000字节整媒体；三个既有MassStorage驱动。无需访问SD卡内容，不弹出、不挂载、不格式化或修复。

## 停止条件和恢复限制

- 包/依赖/原会话证据变化、缺批准、锁或结果已存在：在sudo或设备访问前拒绝。
- 身份/端点异常、claim失败、任何固定核验失败或读取超时：立即停，不STOP、不换端点、不重试。
- STOP只尝试一次；USB/媒体观察超时或不符：保留全部记录并停止，不再发送协议，不自动拔线/断电/重启。屏幕异常时也停止，由用户另行确认后续方案。
- 相机固定上传、生成密钥等残留保留；本次不删除、不覆盖、不重新安装或启用自启。只读核验与STOP仍可能遇到设备不响应；不存在保证恢复的证据。
- 这份包未进行实机验证，不能据离线测试声称当前预加载已中和、sshd已退出或USB已恢复。
