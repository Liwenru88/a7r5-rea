# N0 单地址联网补证：执行与停止方案

日期：2026-10-20。状态：**本机实现与离线验证；未批准、未执行相机联网检查。**

## 1. 本次固定目标与依据

用户本轮提供：

- 相机当前 IPv4：`10.10.10.117`；掩码：`255.255.255.0`，前缀 `/24`。
- 地址来源：相机当前网络信息界面。
- 正常网络角色：连接路由器 Wi-Fi。
- USB：仍连接这台 Mac。没有查询 USB 元数据，所以不将其写成“已核实海量存储模式”。

此前没有网络的原因，按用户反馈为当时未连接 Wi-Fi；本轮不继续下钻驱动或内部网络控制接口。上述地址、角色和连接状态是用户反馈，尚未用主机网络检查独立核验。

本次一次性材料位于 [packages/n0-20261020-01](packages/n0-20261020-01/plan.json)。默认仅 TCP，不启用 ICMP。批准模板为 `accepted=false`，没有 `approval.json`，没有有效联网批准。不要现在双击执行。

## 2. 正常菜单核对：保持当前已联网状态

未来实机确认前，只核对并记录：

1. 相机屏幕正常、电池或独立供电稳定，无初始化、格式化、修复提示。
2. 相机网络信息界面仍显示 `10.10.10.117/24`，仍连接刚才的路由器 Wi-Fi；Mac 位于可访问该相机的同一受控网络。地址变了就停止，另备新包，不修改现有封存计划。
3. Wi-Fi 保持当前连接状态，不重新登记 AP、不复位网络、不清除配对、不修改无线凭据。
4. 记录“遥控拍摄/PC Remote”和访问认证的当前状态。**本次不要求打开遥控功能，也不关闭访问认证。**开启正常遥控功能可能启动原厂应用服务，应另行确认，不能混入本次单地址检查。

菜单文字以相机 4.00 当前界面为准。Sony 正常联网流程见 [v3 方案](../正常模式联网与SSH最小方案-v3.md)。Wi-Fi 已连通不等于 TCP 22 已监听；22 拒绝连接不能直接判断驱动或 SSH 程序故障。

## 3. USB 处理：本次保持连接

- 按用户当前状态，保持 USB 连接；本机入口不枚举 USB、不发认证/START/STOP，不挂载、卸载或弹出媒体，不改变 USB 模式。
- 本次不需要管理员权限，不运行 sudo，不触发 DEBUG，不读取 USB 相机文件。
- 如果 USB 连接导致 Wi-Fi 地址消失、菜单禁止联网或屏幕提示异常，停止本阶段。不要为赶进度自行拔线或切换遥控/海量存储。
- 如后续确需拔 USB，应先另行明确确认范围：只读识别对应媒体、正常弹出，再由用户在独立供电下断开数据线；不自动断电、不移动卡、不重启。当前 N0 入口不包含这些动作。
- 本次即使网络检查通过，也不自动证明“海量存储与 Wi-Fi 并存”；USB 具体身份仍未查证。

## 4. 实际联网范围，待明确确认后才可执行

本次包只允许：

1. 对数字 IPv4 `10.10.10.117` 的 TCP 22 调用一次连接，超时 5 秒。
2. 若连接成功，仅在同一连接中接收，最多 256 字节、读取窗口 2 秒；分片读取不会重新开始计时。不发送客户端 SSH 标识、KEX、用户名、密码、公钥、认证或命令。
3. 接收结束或超时即关闭连接，不重连、不换端口、不替换地址。整个联网工作预算 12 秒，不包含无法保证的操作系统/本机磁盘调度延迟。

**TCP 建连/关闭本身会发送网络包**；“不发送 SSH 应用数据”不等于不发包。内核可能按其 TCP 规则重传，入口不会应用层重试。相机原厂网络栈或日志也可能因连接产生自身状态变化；程序不会调用文件写入或相机服务协议。

无 DNS、mDNS、广播发现、网段扫描、端口列表或监听服务。没有使用 ssh、ssh-keyscan、Paramiko 或 PyUSB。不更改 Mac 防火墙、路由、网络设置或相机配置。

通用代码另有 `--icmp-fallback` 候选，仅在单独准备且批准的包中，TCP 明确拒绝或超时后最多一包 ICMP。**本次 `n0-20261020-01` 的该值为 false，因此任何结果都不会触发 ping。**不因失败临时扩大范围。

## 5. 启动门槛与一次性证据

只有用户明确确认本次实机步骤后，才生成新的 `approval.json`。批准绑定 plan 摘要、目标及来源、代码、Terminal 入口和解释器摘要，并确认当前地址、同网、供电、屏幕、菜单及 USB 状态。有效期最多 15 分钟；过期须重新核对现状，不能把旧批准当长期授权。

`run-n0.command` 不生成批准、不请求 sudo。缺少批准、未接受模板、状态不全、摘要变化或旧尝试锁都会在网络后端之前拒绝。CLI 还需显式 `--network-io`。

全部门槛通过后，新建 `ATTEMPT_LOCK` 和 `attempt.json`，然后才允许唯一网络尝试。正常结束或捕获异常后保存 `result.json`；原始标识保存为最多 256 字节的十六进制，终端只输出 JSON 转义内容，避免控制字符污染。证据只写本机一次性目录，不写原相机或 SD 卡。

发生本机强制退出而缺少结果时，锁和尝试记录仍保留，标记未完成；不能删除锁重跑。不得自动生成新名字绕过一次性范围。

## 6. 判定与停止条件

| 结果 | 能支持的结论 | 自动行为 |
|---|---|---|
| TCP 接通且收到合规 SSH 标识 | 当次指定地址的 22 接受连接并自报 SSH；不证明相机身份、密钥、认证或登录 | 关闭连接、保存结果，停止 |
| TCP 接通但无完整标识 | 有 TCP 可达证据；SSH 未确认 | 关闭连接、保存结果，停止；不补 ping |
| TCP 拒绝或连接超时 | 仅记录当次结果；不能等同于相机没有联网 | 保存失败结果、停止；本包不补 ping |
| 非预期协议、控制字节、超长标识、读错误、权限/路由错误 | 协议或传输异常，需人工复核 | 立即停止，不改地址、不换端口、不重连 |
| 目标变化、批准失效、已有锁或本机材料变化 | 本包不再满足执行门槛 | 网络前拒绝 |
| 相机屏幕异常、网络丢失、要求格式化/修复 | 当前现场不满足条件 | 不启动或人工中止；不自动恢复、不拔线、不断电 |

CLI：有可达证据且无异常返回 0，诊断未通过返回 3，门槛/未捕获本机错误返回 2。即使返回 0，仍保留 `screen_confirmation_pending=true` 和 `acceptance_complete=false`，后续人工屏幕确认单独记录，不覆写原始收据。

不做 SSH 主机密钥交换，故 `camera_identity_cryptographically_verified=false`、`ssh_login_verified=false` 始终保持。DHCP 地址可能改变或被其他设备占用，所以执行前地址核对不可省略。
