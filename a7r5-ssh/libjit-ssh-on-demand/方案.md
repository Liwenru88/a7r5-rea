# A7R5：libJit 按需启动的原始视图 SSH

本文件描述新工具的实施设计；源码及离线验收已实施，最终结果见`verification/离线验收记录.md`。没有连接相机。旧SSH已按卸载清单删除，不能直接复用旧候选的安装状态、密钥或批准。目标为A7R5 4.00：提前载入材料，每次由Mac经USB主动触发一次，默认不限时提供真实root终端、脚本及SCP，直到明确停止或相机关机、重启。不做开机自启，不修改预加载或原账户。

## 1. 使用方式和生命周期

“单次”指一次服务使用窗口，窗口内可反复登录、执行脚本和传输文件，并非只允许一个 SSH 连接。SCP 会建立独立连接，不能在首个终端退出时无条件关闭所有服务。

按用户要求默认不限时：服务寿命参数 `ttl_seconds=0` 表示不设置到期时间，不能被实现成立即到期。可选正数时限仅由用户显式指定；启动、停止、USB传输和清理等待仍保留各自的超时，不随服务寿命放宽。

Mac 启动命令显示本次会话和不限时状态，不显示倒计时。关闭一个SSH终端、Mac程序退出、Mac休眠或网络断开均不自动结束机内服务；需要显式执行本次停止入口。停止门槛通过后，机内监督器回收本次SSH进程树。相机关机或重启会结束进程，但这不构成清理回执，也不授权工具自动重启相机。

相机在使用期间需有监听进程和监督器。不限时意味着本次手动启动的服务可以持续后台运行，但不安装开机自启、不自动重拉起；停止或重启后，下一次仍须手动触发。

新包提供以下入口；默认只做本机检查，实机阶段必须显式批准：

| 入口 | 行为 |
|---|---|
| `prepare` | 仅本机生成材料、清单和批准摘要 |
| `load-once` | 经一次批准的 USB 会话，仅上传独立目录材料并回读校验，不启动 SSH |
| `start-once` | 一次 libJit 触发；核对 READY 和 USB 恢复后，开放该窗口的连接说明 |
| `stop-once` | 请求结束本窗口，读取清理回执，不重复发送 |
| `collect-once` | 若 SSH 通道已关闭，通过另行批准的只读 USB 会话回收固定 RAM 回执 |
| `status` | 只读本机记录，绝不隐式启动或连接相机 |

每个封包绑定一个新会话号，载入、启动、停止各限一次；再次使用准备新包，旧材料和锁保留。默认记录不限时而非计算到期时间。拒绝重放旧启动票据，不自动重试、不自动覆盖冲突目录。已有活动实例时拒绝重复启动；再次启动前必须解决上次未收口状态。

## 2. 原始视图的实现及语义

推荐复用 `ssh-service/original-view` 的结构：认证阶段位于私有挂载命名空间，只在那里创建 RAM 账户副本、0600 主机密钥、sshd 配置及必要的 devpts；原账户及原厂配置不改。认证后的唯一执行入口切回 libJit 启动监督器持有的原始挂载命名空间与根目录。

新载荷在 libJit 入口捕获原始挂载命名空间、根目录、UID/GID、附加组、能力和 umask，监督器保持对应对象存活。每次 shell、命令和 SFTP 执行前重新核对会话号、监督器 PID/启动时间、命名空间及根目录对象身份，切换并校验；失败以 126 拒绝执行，不退回认证视图。

会话应遵循现有 libJit 任务基础环境：`PATH=/bin:/sbin:/usr/bin:/usr/sbin`、`HOME=/`、`LC_ALL=C`、初始工作目录 `/`。保持 `/bin/sh -c` 的命令语义，stdin 脚本可用 `/bin/sh -s`；交互终端使用普通 `/bin/sh`，不靠 profile 自动执行内容。TERM 等终端必要变量受控保留，PTY 标准文件描述符保持有效。

“同样语义”的验收范围是：原始挂载视图、根目录、root 身份、能力/附加组、umask、基础环境及路径解析一致。SSH 的 PTY、stdin/stdout、会话环境及长期流式输出不同于 libJit 的非交互、15秒/32KiB有界任务，不能声称两者进程上下文逐字节相同。只切换 mount namespace；不宣称其它命名空间也已统一。

不自动 remount、解锁只读分区或改变权限。原始视图中用户命令的真实写入不会自动回滚，不能把 RAM 认证隔离称为用户命令沙箱。

## 3. 提前载入与启动必须分开

固定文件接口不提供mkdir，因此实现改为三个随机前缀平铺路径：`/tmp/jiritsu/a7r5-ljssh-<run-id>.service`、`.session`、`.sftp`。这样载入阶段只传文件，无需先执行机内创建目录代码。路径是否持久必须以实测为准；不承诺重启后材料仍可用。RAM运行目录位于 `/tmp_network/a7r5-libjit-ssh-<run-id>/`，必须核对真实tmpfs和权限。

载入内容预计包括：启动监督程序、统一会话程序、外部 SFTP 程序、仅供重建核验的清单；实际文件数与摘要在封包后冻结。账号密码仅以私有材料中的哈希提供，不写入文档、命令行或日志；是否复用原约定密码在执行包中明确，不默认引入额外认证方案。

卸载已删除旧持久主机私钥，新实现不依赖它。主机密钥由原厂ssh-keygen在本次私有RAM内生成，核验root所有者、0600、单链接普通文件和tmpfs。只通过已认证USB读取公钥，并与READY所记摘要核对；Mac固定该公钥进行SSH服务器身份校验，不无条件接受新密钥。私钥不回传本机，也不写入持久材料路径。

精确 `/tmp/jiritsu/libJit.so` 是执行触发路径，不能在 load 阶段上传。只在 start 阶段完成预检、票据写入后上传一次，加载入口尽快返回原厂调用者；一次性标记及解除触发文件的结果必须记录。预加载要求读回精确512换行并在全程保持不变；未知内容立即停止。

## 4. 专用启动协议，不能直接使用 sshd 后台脚本

现有 `a7r5-exec/payload/libjit.c` 把活动后代视为 FAILED 94，其成功门槛是任务结束且无活动后代。因此不得把 `sshd &` 交给现有 `libjit.sh` 后放宽其检查，也不得通过逃逸进程树绕过监督。

应在新目录实现专用启动载荷与主机操作器，复用已验证的 USB 大文件边界处理、两阶段认证、固定路径和主机恢复观察逻辑。保留通用 libjit.sh 的有界任务契约。

新服务契约：

`LOADED → TRIGGERED → STARTING → READY → USB_RESTORED → ACTIVE → STOPPING → ENDED → COLLECTED`

- `READY` 必须包含监督器/子进程身份、原始视图证明、私有账户及RAM密钥核验、监听和本机标识核验、服务寿命、触发已解除、预加载未变。默认明确记录 `ttl_seconds=0` 且无到期时间；显式限时模式才记录到期时间。READY只证明服务已启动，不等于清理已完成。
- USB STOP 与 SSH 停服是两个不同动作。前者退出 USB 服务模式，后者结束本次监听和进程树。
- 启动期间只在本次 READY、重复状态、预加载和解除触发等专用门槛全部通过后，允许一次 USB STOP；不伪造通用任务 DONE/无后代回执。跨 STOP 存活必须重新实机验证。
- STOP 后只观察主机 USB/驱动/完整媒体恢复，连续匹配后才从 Mac 登录；Pipe error 不触发重发。
- 运行结束时才验收最终进程树回收、监听消失和私有资源释放。无法取到最终回执时标记待回收，不能以端口关闭代替清理完成。

为了避开“从被终止服务自身取最终回执”的已知缺口，最终结果写入共享 RAM；若通道来不及返回，采用另行确认的只读回收会话。服务寿命不依赖 Mac 一直在线。

## 5. 终端、脚本、SCP

新方案只提供一个正式服务端口，建议沿用2222，移除旧方案并行2223的迁移复杂度。启动前检查端口空闲；占用时停止，不杀未知进程、不自动换端口。

普通密码登录可以保留，前提是只修改私有 RAM 账户副本；主机密钥用于服务器身份，与用户使用密码登录并不冲突。禁用端口转发、代理转发及无关子系统。监听地址建议沿用通配 IPv4，但客户端目标地址须在每次执行前核实；历史10.10.10.177不是当前设备事实。

统一入口覆盖：无命令的交互 sh、`ssh ... command`、`ssh ... /bin/sh -s`、外部 SFTP。现代 Mac SCP默认经SFTP，必须切换到原始视图后再启动外部服务端，禁止 internal-sftp 停留在认证视图。旧协议 `scp -O` 需另核对机内 scp 可执行文件及收发行为，未经验证不列为支持。

旧候选使用 OpenSSH 7.4p1 的外部 SFTP，其来源和旧版本限制已有记录。复用前需核对来源摘要、动态依赖和目标ABI，并在隔离QEMU测试；维护版本重建可单列后续工作，不能直接把旧候选称为长期安全方案。

## 7. 离线实现及验收顺序

1. 新建独立源码和封包目录，保留旧工具、旧包、锁及卸载证据。实现独立密钥来源、默认不限时的专用libJit服务监督和主机状态机；所有默认入口只做本机准备，设备执行必须显式选择。服务不限时不放宽各阶段的有界等待。
2. 失败路径验证：材料冲突/摘要错、重复票据/重复启动、未知预加载、旧密钥路径缺失、RAM权限错误、命名空间/根目录/PID复用、setns失败、能力/组不符、端口占用、启动超时、USB异常、STOP Pipe error、网络断开、Mac退出、主动停止时活动PTY/SFTP及回收失败。单列零时限不立即退出，以及显式正数时限的到期路径。
3. 无相机/SD透传的QEMU集成：独立载入后一次启动；密码认证；交互提示、回显、窗口尺寸、Ctrl-C、exit；stdin脚本和退出码；默认SCP双向传输并比对摘要；终端/脚本/SFTP各自核验原始视图；默认不限时跨过旧600秒阈值仍运行，断开客户端后可再次登录，随后主动停止并验收进程树/端口/资源。显式限时模式另测到期回收；有限观察不能证明无限期稳定性。
4. 保留只读原始镜像，只在模拟环境叠加层构造“原始视图与认证视图看到不同文件”的夹具，证明三个入口实际访问正确视图；同时测试PTY在切换后可用，不能只比较/proc命名空间字符串。
5. 封存程序、票据模板、清单、敏感材料权限、构建依赖、测试日志、操作及恢复说明，列出确切写入和删除范围；先交用户审阅，再另行确认实机load与start。未通过时不封为“已可实机使用”。

## 8. 风险和恢复边界

- 用户命令在原始视图以root执行，可真实修改可写系统、持久配置及原始设备；不以“私有账户”弱化该风险。不自动操作任何SD节点。
- 固定libJit路径存在既有文件覆盖和加载器异常风险；协议stat错误6不能证明不存在。写入内容、票据及恢复受限风险需在实机执行前具体确认。
- 默认没有到期兜底：Mac退出、休眠或网络断开后，本次root监听可能持续存在，直到明确停止、服务故障或相机关机/重启。不能把客户端断开写成服务已回收，也不承诺故障后自动恢复。
- 主动停止或显式限时模式到期可中断传输或用户脚本，部分文件及用户写入不会自动回滚。验证中用独立临时文件，不向固件关键路径上传测试数据。
- 停止回收、设备异常或内核阻塞不保证可强制收敛；失败时不宣称成功、不重启、不重发、不自动断电。保存原始响应、已执行动作和最后身份，准备对应受限恢复方案。
- 服务停止与材料删除分开；不自动清除用户文件或研究证据。未来卸载按明确白名单和批准执行。
- 不保留自启钩子，不写profile、开机脚本或ld.so.preload；不承诺重启后自动可用。下一次使用须重新检查材料与预加载基线，并显式触发一次新窗口。

## 当前交付边界

本轮交付源码、离线验证、独立执行包及说明；没有任何新的设备访问、上传、相机SSH连接、预加载写入或DEBUG。实机操作另行确认，不能从QEMU成功推定机身跨STOP、Wi-Fi、拍摄或无限期稳定性。
