# 默认不限时 libJit SSH：待确认实机清单

本文件只用于审阅，不授权或自动触发实机。本轮没有连接相机。唯一实机对象须为用户的A7R5、固件4.00，核对实际USB端口、完整媒体及当前IPv4；历史10.10.10.177不直接作为已确认现状。

## 写入与执行范围

每包固定一个随机会话号。确切路径及摘要见包内`materials/build.json`和`manifest.json`，不允许执行时换路径或材料。

| 阶段 | 固定写入 | 机内执行及结束条件 |
|---|---|---|
| load-once | `/tmp/jiritsu/a7r5-ljssh-<run>.service`、`.session`、`.sftp`，各一次 | 不运行上传代码；逐文件回读，预加载不变后仅一次USB STOP |
| start-once | `/tmp/jiritsu/a7r5-ljssh-<run>.ticket`与`/tmp/jiritsu/libJit.so`，各一次 | 后者触发原厂libJit加载入口；专用监督器生成私有RAM认证、密钥及devpts；本次READY/公钥/心跳/解除触发/基线门槛通过后仅一次USB STOP |
| stop-once | `/tmp_network/a7r5-libjit-ssh-<run>/stop-request`，精确会话号一次 | 监督器回收本次子树，主机读完整父/子终态及重复状态；门槛通过后仅一次USB STOP |
| collect-once | 无 | 只读本次已结束实例的固定RAM回执，所有门槛通过后仅一次USB STOP |

上述USB会话各允许两阶段认证/START。USB STOP退出服务模式，与SSH停服是不同动作。任何阶段都不写`/etc/ld.so.preload`、不DEBUG、不修改原账户、不自启、不格式化或操作SD卡、不自动重启或断电。

监督器使用共享RAM活动锁`/tmp_network/a7r5-libjit-ssh.active`，仅创建本次锁，并在其拥有的子树已回收且端口关闭时移除；未知既有锁不删除。运行证据保留在本次RAM目录，程序材料和票据/claim等可能残留，停止不等于卸载。

## SSH 行为

- 默认`ttl_seconds=0`，不限时；监听`0.0.0.0:2222`，只接受私有RAM账户的密码认证。关掉一个终端、Mac休眠/退出或断网不会自动停服；停止后不自动重启，机身重启也不自启。
- 沿用本机已有口令文件生成哈希，包不含明文口令；账户变更只发生在私有挂载视图。
- 每次启动在私有RAM生成新主机私钥。通过已认证USB读取公钥并固定信任，后续SSH/SCP必须使用本次known_hosts；不接受未知主机密钥、不回传私钥。
- shell、命令、stdin脚本、默认SCP/SFTP均在执行前核验并进入本次libJit监督器的原始挂载视图。切换失败拒绝执行，不退回私有视图。
- 用户root命令可真实读写可写系统及设备，不自动改成只读或拦截任意命令；工具不会替用户回滚已执行命令。

## 分阶段确认和验收

1. 实机前单独确认当前包及load范围；核对本机摘要、稳定独立供电、USB普通身份、端口和完整媒体、机身屏幕。未确认前不得双击设备执行文件。
2. load成功及主机恢复后，人工查看屏幕，再用本机`confirm-screen --phase load-once --screen-normal`收口。失败不允许删锁重试。
3. start须另行确认固定libJit覆盖及不限时监听风险。门槛通过、主机恢复及屏幕确认后，才允许从Mac连接相机当前IPv4验证root终端与SCP；使用本次公钥文件，先运行固定只读命令，再向本次RAM测试目录做双向传输并比对长度及SHA-256。
4. 结束前完成文件传输和退出交互终端，再确认一次stop。停止可终止用户尚未退出的进程；不保证保存用户任务数据。验证父/子清理、端口消失、预加载不变、USB/媒体及屏幕后收口。
5. `collect-once`仅用于已满足同包启动记录的固定RAM回收；仍需单独确认一次只读会话。它不能绕过未知USB状态或失败待恢复标记。

## 异常与恢复边界

- 材料/依赖变化、可读路径冲突、未知预加载、协议/传输错误、视图/密钥/心跳不符、端口占用或清理失败：立即停止，不重试、不换端点、不自动覆盖、不自动断电。
- 固定`libJit.so`写入是触发本身，不能先上传后再决定是否执行。stat结果`0x10000006`不能证明文件不存在；接受当前不可读路径可能被覆盖的风险，不承诺恢复覆盖前内容。
- 未通过完整门槛时禁止USB STOP；此时只保留日志并观察主机元数据。服务身份0336、过渡身份096f或未知身份均不能仅凭名称直接发STOP；需要绑定本次证据的受限恢复方案，另行确认。
- 一次USB STOP返回Pipe error不重发；只用主机元数据有界观察普通USB、驱动和完整媒体连续两次匹配。未匹配就标记未恢复，不自动拔插或重启。
- 默认不限时没有到期兜底。SSH连接不通不能证明服务已退出；端口关闭也不能代替最终子树及RAM资源回收回执。回执缺失时保留待回收状态，不能用屏幕正常把失败改成成功。
- 账户及私有挂载回收不代表用户对真实系统的写入已恢复。工具不提供固件回刷或救砖保证，不以QEMU验证推断实机拍摄、网络、冷启动或无限期稳定性。
- 未来删除持久材料、清理残留或改变预加载需列新白名单并另行确认；保留旧包、永久锁及本机全部证据。
